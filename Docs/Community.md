# Community - Сообщество и поддержка

## RU

### Назначение

Этот документ содержит информацию о том, как получить помощь, задать вопросы и внести вклад в проект Nmsdk.

### Как получить помощь

#### Документация

1. **Начните с документации:**
   - [FAQ.md](FAQ.md) - часто задаваемые вопросы
   - [Getting-Started.md](Getting-Started.md) - начало работы
   - [Troubleshooting Guide](Troubleshooting/Troubleshooting-Guide.md) - устранение неполадок

2. **Изучите примеры:**
   - [Examples/](Examples/) - практические примеры
   - Примеры в сабрепозиториях

3. **Используйте поиск:**
   - Ищите в документации по ключевым словам
   - Используйте [Glossary.md](Glossary.md) для понимания терминов

#### Где задавать вопросы

- **Документация** - сначала проверьте FAQ и Troubleshooting Guide
- **Примеры** - изучите примеры использования
- **Исходный код** - комментарии в коде могут помочь

### Процесс сообщения об ошибках

#### Перед сообщением об ошибке

1. Проверьте [Troubleshooting Guide](Troubleshooting/Troubleshooting-Guide.md)
2. Убедитесь, что проблема воспроизводится
3. Соберите информацию:
   - Версия системы
   - Версия компилятора
   - Логи приложения
   - Минимальный пример для воспроизведения

#### Информация для включения в отчет

- Описание проблемы
- Шаги для воспроизведения
- Ожидаемое поведение
- Фактическое поведение
- Логи и ошибки
- Минимальный пример кода

### Процесс предложения улучшений

#### Перед предложением улучшения

1. Убедитесь, что улучшение не противоречит архитектуре проекта
2. Проверьте, не реализовано ли уже это в проекте
3. Опишите проблему, которую решает улучшение
4. Предложите конкретное решение

#### Формат предложения

- Описание проблемы или недостающей функциональности
- Предлагаемое решение
- Преимущества решения
- Возможные недостатки или ограничения

### Разработка документации

#### Как улучшить документацию

1. Изучите [CONTRIBUTING.md](CONTRIBUTING.md) - правила поддержки документации
2. Следуйте существующему стилю
3. Обеспечьте двуязычность (RU/EN)
4. Добавьте примеры где возможно

#### Структура документации

- Следуйте существующей структуре
- Используйте mermaid диаграммы для визуализации
- Добавляйте ссылки на связанные разделы

### Кодекс поведения

При работе с проектом:
- Будьте уважительны к другим участникам
- Предоставляйте конструктивную обратную связь
- Помогайте другим участникам сообщества

### Дополнительные ресурсы

- [README.md](README.md) - главная страница документации

## EN

### Purpose

This document contains information on how to get help, ask questions, and contribute to the Nmsdk project.

### How to Get Help

#### Documentation

1. **Start with documentation:**
   - [FAQ.md](FAQ.md) - frequently asked questions
   - [Getting-Started.md](Getting-Started.md) - getting started
   - [Troubleshooting Guide](Troubleshooting/Troubleshooting-Guide.md) - troubleshooting

2. **Study examples:**
   - [Examples/](Examples/) - practical examples
   - Examples in subrepositories

3. **Use search:**
   - Search documentation by keywords
   - Use [Glossary.md](Glossary.md) to understand terms

#### Where to Ask Questions

- **Documentation** - first check FAQ and Troubleshooting Guide
- **Examples** - study usage examples
- **Source Code** - code comments may help

### Bug Reporting Process

#### Before Reporting a Bug

1. Check [Troubleshooting Guide](Troubleshooting/Troubleshooting-Guide.md)
2. Ensure the problem is reproducible
3. Gather information:
   - System version
   - Compiler version
   - Application logs
   - Minimal example for reproduction

#### Information to Include in Report

- Problem description
- Steps to reproduce
- Expected behavior
- Actual behavior
- Logs and errors
- Minimal code example

### Improvement Proposal Process

#### Before Proposing an Improvement

1. Ensure improvement doesn't conflict with project architecture
2. Check if this is already implemented in the project
3. Describe the problem the improvement solves
4. Propose a specific solution

#### Proposal Format

- Description of problem or missing functionality
- Proposed solution
- Solution benefits
- Possible drawbacks or limitations

### Documentation Development

#### How to Improve Documentation

1. Study [CONTRIBUTING.md](CONTRIBUTING.md) - documentation maintenance guidelines
2. Follow existing style
3. Ensure bilingual support (RU/EN)
4. Add examples where possible

#### Documentation Structure

- Follow existing structure
- Use mermaid diagrams for visualization
- Add links to related sections

### Code of Conduct

When working with the project:
- Be respectful to other participants
- Provide constructive feedback
- Help other community members
