# Qt GUI UX — аудит выполнения и оставшийся план

**Дата ревизии:** 2026-10-02
**Основа:** [аудит Qt GUI](Qt-GUI-UX-Audit-2026-10-02.ru.md), [baseline](Qt-GUI-UX-Baseline-2026-10.md), [ADR PlotDocument](../../GUI/ADR-PlotDocument.md)
**Назначение:** зафиксировать, что уже реализовано, устранить расхождения с аудитом и оставить только проверяемые незавершённые пункты.

## 1. Вывод повторной сверки

Предыдущая версия плана перечисляла уже закрытые функции как отсутствующие и завышала готовность некоторых пунктов. В обновлённой ветке действительно появились schema v3, плотный Watch, общий toolbar, инспектор, Quick Add, drag-and-drop, шаблоны и Undo. Однако статический повторный разбор обнаружил незакрытые дефекты: `UWatchSerie::toPlotSeries()` каждый раз создавал новый SerieId; Undo удаления панели восстанавливал другой PanelId; «Скрыть» возвращало панель при пересборке сетки; duplicate panel не копировал стиль рядов. Эти дефекты исправлены в текущем проходе.

После исправлений основная реализация Watch соответствует P0/P1 требованиям аудита на уровне исходников. Живое взаимодействие, компоновка при разных DPI и полезная площадь `plotArea` остаются непринятыми: в доступной сессии нет открытого Qt-приложения/рабочего стола для ручного осмотра.

## 2. Реализовано и исправлено

| Область | Результат сверки и исправление |
|---|---|
| Сетка и состав Watch | Изменение `rows × cols` не удаляет панели. Панели вне слотов остаются в документе; явное пользовательское скрытие теперь отделено от временного переполнения сетки. Изменение размера сетки сохраняет порядок и данные. |
| Идентичность | SerieId теперь создаётся один раз на объект, сохраняется при повторном захвате документа, загрузке, Undo удаления серии, Undo удаления панели и переносе между вкладками. Клонирование создаёт новые ID. Добавлены тесты на устойчивость идентификатора и XML round-trip. |
| Browser панелей | В инспекторе есть фильтруемый список с названием, видом, числом рядов, состоянием и путями источников. Доступны выбор, двойной щелчок для разворота, переименование, дублирование, скрытие/показ, удаление, разворот, перенос по порядку и возврат панели в текущую сетку. Порядок панели отменяется через Undo. |
| Перенос между Watch-вкладками | Меню переносит определение панели вместе с настройками и источниками; временные буферы живых отсчётов начинаются заново после переноса. |
| Duplicate panel/series | Дубликат панели копирует стиль, цвет, ширину и тип линии, видимость, настройки XY и оси; получает собственные стабильные ID. Повтор Redo дублирования серии сохраняет ID созданного ряда. |
| Quick Add | Добавлены избранные/недавние сигналы, очередь нескольких рядов, мультивыбор ячеек матрицы и выбор целевой панели. Старый мастер остаётся для сложной конфигурации. |
| Плотная сетка | Общая полоса действий для активного графика, отключение повторных панельных toolbar в плотном режиме и уменьшенные поля Qt Charts уже присутствуют. Фактический выигрыш по пикселям ещё требует замера в GUI. |
| Инспектор | Страницы прокручиваются; сохраняются атомарные диапазоны осей, Fixed X/Y, Sync X, стиль и дробная точность Y shift. |
| Компоненты | Обновление дерева переиспользует элементы и состояние ветвей вместо полной очистки на каждом snapshot; добавлен поиск узла диаграммы с переходом к нему. |
| Каналы и журнал | Панель каналов обновляет элементы на месте, предоставляет частые команды в toolbar и горячие клавиши. Журнал хранит ограниченную историю и повторно применяет фильтры к уже полученным сообщениям, не теряя скрытые фильтром записи. |
| Доступность и shortcuts | Для основных новых browser/picker/search controls заданы accessible names. Добавлены shortcuts Quick Add, поиск панелей, Layout, поиск диаграммы, Start/Pause канала, F2/Delete, Undo/Redo и FitToView. |
| Рабочие области | Именованные Model/Monitoring/Debug и Factory работают через пользовательские QSettings. Конфликт локальной переменной `settings` с членом окна устранён. Первичное заполнение Factory и перенос factory-снимка между машинами не реализованы. |

## 3. Проверка кода и сборки

Выполнено в текущем проходе:

1. `NeuroModeler` успешно собран профилем `win-vs2019-debug-localqt` с Visual Studio 2019 toolchain.
2. Через CTest прошли `Test_WatchTemplateStore`, `Test_PlotDecimation`, `Test_WatchSeriesIdentity` — 3/3.
3. `NeuroModeler.exe` с Qt platform `offscreen` стартовал и оставался активен не менее 10 секунд; процесс остановлен после smoke.
4. `git diff --check` для `Rdk` прошёл без ошибок.

При генерации CMake пропустил ConfigValidation-тесты, потому что в профиле не собран `NeuroModelerConsole`. Интерактивные GUI-тесты отключены (`NMSDK_ENABLE_INTERACTIVE_GUI_TESTS=OFF`). Запуск `offscreen` подтверждает создание процесса и базовую инициализацию приложения, но не заменяет проверку мышью, рендеринга, диалогов и геометрии.

## 4. Обязательная приёмка на рабочем desktop — P0

Выполнить на типичном проекте после появления доступного рабочего стола:

1. Открыть существующий `Interface.xml`; сравнить число панелей, источники, оси и заголовки до/после сохранения.
2. Проверить сетку `2×2 → 1×2 → 2×2`. Убедиться, что PanelId/SerieId, названия, видимость и настройки не меняются. Проверить явное скрытие/показ отдельно от переполнения сетки.
3. В уменьшенной сетке выбрать панель «outside grid» и вернуть её через обозреватель; проверить, что другая панель не удалена.
4. В плотной сетке `2×2` и `4×4` проверить одну общую полосу действий, разворот выбранной панели, отсутствие постоянно повторяемых toolbar и читаемость подписей.
5. Переместить панель между вкладками Watch, сохранить/перезагрузить документ и сравнить определения; подтвердить ожидаемое повторное наполнение живого буфера после переноса.
6. В Quick Add выбрать избранный и недавний сигнал, очередь нескольких свойств, несколько ячеек матрицы и другую целевую панель. Проверить дубли и несовместимую XY-панель.
7. Проверить duplicate panel/series, Hide/Show series, удаление ряда/панели и Ctrl+Z/Ctrl+Y; ID объектов должны быть стабильны после восстановления.
8. Повторить smoke из baseline §2–4 и ADR-PlotDocument Test plan; проверить загрузку `2x1-overview.watch.xml` и сохранение `Interface.xml`.
9. Проверить светлую/тёмную тему, disabled-состояния, tab order и shortcuts на клавиатуре.

Для плотности снять таблицу `plotArea_px / cell_px` для 1×1, 2×2, 4×4 при 100%, 125%, 150% масштабировании. Сравнить с текущим baseline и скорректировать margins/шрифты, если внутренняя область остаётся ниже ориентиров: 1×1 — 80%, 2×2 — 70%, 4×4 — 60% размера ячейки после вычета общей полосы действий. Не скрывать оси или легенды автоматически без отдельной визуальной проверки.

## 5. Остаток работ после текущего прохода

### P1 — завершить после desktop-приёмки

- Проверить управление большим числом панелей и удобство browser на реальных именах/источниках; при необходимости добавить drag reorder и отдельное подтверждение удаления с перечислением источников.
- Проверить сценарий перемещения между вкладками при скрытых и переполненных панелях.
- Зафиксировать детерминированный Factory workspace в проекте либо создать factory snapshot до восстановления пользовательского расположения; проверить Reset на чистой установке.
- Провести замеры `plotArea` и времени ответа при длинных временных рядах. Настраивать интервалы/coalescing только по замерам.

### P2 — отдельные системные улучшения GUI

- Добавить Qt `.ts/.qm` для RU/EN и определить язык приложения. Новые строки уже идут через `tr()`, полноценные каталоги и перевод старых строк отсутствуют.
- Добавить к свойствам единицы измерения и описание, если метаданные компонента их предоставляют; рассмотреть Undo редактирования значений только для редактируемых свойств.
- Добавить состояния каналов (работает/пауза/ошибка) и ошибку рядом с каналом, если engine API предоставляет такой статус.
- Переход из строки журнала к компоненту пока не обеспечен: текущий `UGlogGuiMessage` содержит только severity и текст, без структурированного component/source id. Для этого сначала нужен источник метаданных.
- Добавить фильтры типов/связей диаграммы и видимый масштаб; поиск узла уже есть.
- Замерить latency/FPS для 1×1, 2×2, 4×4 на длинных рядах. Если цели не достигнуты, профилировать сбор/доставку данных и Qt Charts до смены backend.
- Пройти контрастность, масштабирование текста и keyboard traversal; доступные здесь свойства элементов не подтверждают визуальную доступность.

## 6. Критерий завершения

Кодовые пункты из раздела 2 и автоматические проверки выполнены. Полный аудит можно закрыть только после пункта 4 с заполненной DPI/plotArea таблицей в baseline. Открытые P1/P2 задачи остаются отдельным улучшением GUI и не должны описываться как уже принятые.
