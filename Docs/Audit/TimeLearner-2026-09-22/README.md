## 3. Ошибки корректности

Приоритет P1 означает риск неверного исследовательского заключения и необходимость исправления до новых заявлений о качестве; P2 — ограниченный дефект или нарушение документированного контракта. Нумерация используется в плане.

### A01 — P1: ранний ответ принимается за ответ на полный паттерн; N=2/3 не поддерживаются

Источник: [NPatternResponseAnalyzer.cpp](../../../Libraries/Nmsdk-PulseLib/Core/NPatternResponseAnalyzer.cpp), строки 653–680. `pattern_complete` истинно при одном либо >=4 наблюдавшихся стимулах, а after_last_stim сравнивает с последним уже поступившим стимулом.

Контрпример: выход после первого из четырёх стимулов устанавливает neuron_fired, который сохраняется при поступлении остальных трёх. Для N=3 корректный ответ после третьего стимула отвергается. Для N>4 возникает аналогичная возможность преждевременного принятия после четвёртого.

**Исправление:** явные sample id/start/end/expected count из dataset; хранить события до известной границы, затем классифицировать относительно фактического последнего стимула. Нельзя исправить это простым удалением ветки size==1: тогда сломается одиночный паттерн и останется N>4.

### A02 — P1: своевременный ответ обрывает наблюдение late-спайков

Источник: тот же файл, строки 685–720. При установленном neuron_fired CloseTrial вызывается на границе PostPatternWindow. LateResponseWindow продолжается только для trial без своевременного ответа.

Контрпример: target даёт один своевременный и один более поздний спайк внутри заявленного late-окна. CSV сохраняет spike_count=1 вместо 2; проверка single-spike ложно успешна.

**Исправление:** одинаковое полное окно наблюдения для всех trial. Отдельно хранить признак своевременности первого ответа и все события наблюдения. Новый sample не должен молча обрезать предыдущее окно; пересечение окон должно иметь определённую политику.

### A03 — P1: текущий класс может переименовать предыдущий trial

Источник: [NPatternResponseAnalyzer.cpp](../../../Libraries/Nmsdk-PulseLib/Core/NPatternResponseAnalyzer.cpp), строки 445, 467, 653; [NDatasetBase.cpp](../../../Libraries/Nmsdk-PulseLib/Core/NDatasetBase.cpp), BeginSpikeTrainSample, 229+.

Класс читается при открытии, на каждом такте и при закрытии. Dataset переключает CurrentClass при начале нового сэмпла, до его первого импульса. Незакрытый late-trial получает следующий класс. Изолированный контрпример даёт label=0 вместо исходного 1.

На границе нового стимула код также может записывать совпавший выход в закрываемый и открываемый trial; необходима однозначная обработка событий с одинаковым timestamp.

**Исправление:** неизменяемая метка и id при открытии; границы брать из dataset, определить порядок обработки coincident events и запретить двойной учёт.

### A04 — P2: один спайк может считаться ответом на несколько стимулов

Источники: ClassifyResponseMorphology в analyzer и [selectivity_metrics.py](../../../Bin/Configs/SpikeSamples/StructTrain/scripts/selectivity_metrics.py), classify_trial_morphology.

Для стимулов [0, 0.125, 0.25, 0.375] и единственного спайка 0.375 пересекающиеся окна получают один и тот же ответ. C++ возвращает per_stim; Python выставляет per_stim=true. Это ложное отклонение single-ответа.

**Исправление:** взаимно однозначное сопоставление стимулов и ответов с проверкой минимального числа различных спайков. Согласовать C++ и Python на едином наборе эталонных событий, включая пересечения окон.

### A05 — P1: strict-метрика игнорирует часть реальных false positives

Источник: [selectivity_metrics.py](../../../Bin/Configs/SpikeSamples/StructTrain/scripts/selectivity_metrics.py), classify. Effective fire строится из neuron_fired и late_fired, а не из полного списка спайков.

Контрпример: target с одним корректным ответом, семь foils с одним mid-pattern spike каждый; у foils fire=late=0. Результат: `ok_audit=1, acc_strict=8, fa_strict=0, response_quality=ok_single`. Правильное число FP — семь.

Независимо от этого дефекта сам порог ok_strict/ok_audit исторически допускает 4/8. Это слабый явно заданный gate, а не реализация идеальной избирательности. Его нельзя представлять как 8/8.

**Исправление:** любой foil-спайк в полном окне — FP; для target отдельно проверить количество и время. Проверять согласованность count/times/flags и reject неизвестную/неполную схему. Версионировать новые метрики, не переписывая исторические CSV.

### A06 — P2: last_pulse_ok использует max(ISI) вместо суммы

Источник: [audit_structtrain.py](../../../Bin/Configs/SpikeSamples/StructTrain/scripts/audit_structtrain.py), строки 108–135.

Для ISI [0.01, 0.02, 0.03] конец паттерна 0.06; spike=0.025 принимается через 0.8*max(ISI)=0.024. Документированное старое ручное правило 0.8*sum(ISI) тоже не строго «после последнего», хотя существенно сильнее кода.

**Исправление:** использовать timestamp последнего стимула либо sum реально измеренных ISI и явно заданный допуск дискретизации. Сохранить старое правило как legacy-метрику, если нужна историческая сопоставимость.

**Ограничение вывода:** среди 175 просмотренных CSV не найдено результата, принятого одновременно ok_audit и старым last_pulse_ok, где target_t_rel раньше sum(ISI). Контрпример доказывает ошибку критерия, но не фальсифицирует эти исторические численные результаты.

### A07 — принятая особенность: калибровка на текущей Test Matrix

Статус пересмотрен по указанию владельца 2026-09-23: **не ошибка и не P1**, обязательного исправления нет.

Источники: [TimeLearner](../../../Libraries/Nmsdk-PulseLib/Core/NNeuronTimeLearner.cpp), MaybeStartInferenceMidProbes (4132+); [Branch](../../../Libraries/Nmsdk-PulseLib/Core/NNeuronTimeLearnerBranch.cpp), тот же метод (4687+).

Алгоритм при silent FixedLTZ>=0.9 проигрывает текущую Matrix, подбирает порог, сбрасывает dataset/analyzer и оценивает ту же Matrix. Первые N строк (sample 0) задают target; MatrixClasses не выбирает его. Это текущий контракт: смена порядка/первого сэмпла меняет калибруемую цель.

Документация должна называть результат качеством на калибровочном наборе. Независимая оценка обобщения возможна как отдельное исследование, если потребуется; она не является условием приёмки исправлений этого аудита и не требует сейчас менять алгоритм.

### A08 — P1, частично исправлено в Branch: finite guard есть, validity метрик нет

Источник: [NNeuronPostTrainTune.cpp](../../../Libraries/Nmsdk-PulseLib/Core/NNeuronPostTrainTune.cpp), LandscapeOk / ComputeMidThreshold; FinalizePostTuneMid в [TL](../../../Libraries/Nmsdk-PulseLib/Core/NNeuronTimeLearner.cpp), 3948+, и [Branch](../../../Libraries/Nmsdk-PulseLib/Core/NNeuronTimeLearnerBranch.cpp), 4487+.

Helper по-прежнему для target=0.5, foils={0.2,0.6} возвращает mid=0.35 и gap=+0.3, исключая foil выше target; глобальный gap −0.1. В обычном TimeLearner inference такой threshold может сохраниться. Branch 9a6cee0b теперь оставляет silent-порог при неразделимом finite landscape, а Search Train с включённым mid оставляет silent и при хорошем landscape.

Однако LandscapeOk(0.5,{NaN}) всё ещё true. В реальном теле Branch Finalize контрпример с foil=NaN даёт recognition-mid=0.495, Complete=true. Setup failure и timeout не имеют обязательного invalid-статуса; метрики инициализированы нулями. При плохом finite inference-landscape Branch завершает процедуру с silent-порогом и InferenceMidDone=true: автоматического повторного замера в том же процессе нет.

**Оставшееся исправление:** конечные полные метрики и явные результаты success/nonseparable/setup_failure/timeout; глобальный max foil для оценки разделимости; guard обычного TL. Complete означает окончание процедуры, а не quality PASS; verifier должен проверять результат. Принятая same-Matrix калибровка A07 сохраняется.

### A09 — P1, частично исправлено в Branch: повторный замер best добавлен

Источники: HandlePostTuneFinishIteration — [TL](../../../Libraries/Nmsdk-PulseLib/Core/NNeuronTimeLearner.cpp), 4316–4417; [Branch](../../../Libraries/Nmsdk-PulseLib/Core/NNeuronTimeLearnerBranch.cpp), 4819–4934.

Обычный TimeLearner по-прежнему применяет BestTips/snapshot и считает mid по последним другим метрикам. В Branch после выбора Tips метрики очищаются, запускается новый free-run; это исправляет основной путь прежнего замечания. Тест SelectedBestStartsFreshProbe подтверждает передачу выбранного best и отсутствие преждевременного завершения.

Остаются две ветки: при setup failure выполняется Finalize на нулевых метриках; при free-run reject Finalize восстанавливает snapshot, но публикует рядом с ним метрики отклонённого best. Silent threshold защищает от немедленного использования такого Train mid, но flag не является измерением сохранённых весов.

**Оставшееся исправление:** перенести повторный замер в TL; на ошибке setup выдавать отдельный failure; после fallback измерять snapshot либо явно инвалидировать/помечать метрики candidate id и weights hash. Проверки: best первый/средний, все плохие, setup failure и fallback.

### A10 — P2: PostTrainMidMetric не имеет единого смысла

Источники: [Branch](../../../Libraries/Nmsdk-PulseLib/Core/NNeuronTimeLearnerBranch.cpp), ReadPostTuneProbeMetric (4038+) и UpdatePostTuneFreeRunPeak (4183+); [TL](../../../Libraries/Nmsdk-PulseLib/Core/NNeuronTimeLearner.cpp), соответствующие методы.

Branch free-run всегда измеряет soma даже при явном mode=1 (LTZ). В другом пути mode LTZ расширяется max(LTZ,soma). TL для soma в одном пути суммирует индивидуальные максимумы, а в free-run берёт максимум одновременной суммы: `sum(max(x_i))` и `max(sum(x_i))` в общем случае различны.

**Исправление:** единый сборщик метрик с задокументированным физическим сигналом и окном. Тестировать несовпадающие пики каналов и разные soma/LTZ, а не только Auto/default.

### A11 — P2: NAxoneDelay добавляет лишний такт

Источник: [NAxoneDelay.cpp](../../../Libraries/Nmsdk-PulseLib/Core/NAxoneDelay.cpp), ACalculate, около строки 82. Цикл `(s-1)<desired_buffer_length` формирует N+1 элементов при N=int(DelayTime*TimeStep).

При DelayTime=0.001 с и TimeStep=2000 шагов/с импульс появляется через три такта (1.5 мс), а не через два (1 мс). Квантизация задержки при нецелом произведении также должна иметь явный контракт.

**Исправление:** определить порядок write/read и хранить ровно необходимую историю; тесты N=0,1,2, дробная задержка, Reset и изменение частоты. Для цепочки проверять сумму задержек, чтобы ошибка не накапливалась по сегментам.

### A12 — отложенное ограничение численной схемы; исправление сейчас не требуется

По указанию владельца 2026-09-23 это общая особенность дискретных численных реализаций; предполагается достаточно малый шаг. Пункт исключён из активных дефектов P2 и обязательного плана.

Источник: [NAperiodicLink.cpp](../../../Libraries/Nmsdk-PulseLib/Core/NAperiodicLink.cpp), ACalculate. Явный Euler: y+=(x−y)/(Tau*TimeStep), где TimeStep — частота. Условие устойчивости этой линейной схемы: 0<alpha=1/(Tau*TimeStep)<2; монотонность alpha<=1. При Tau=0.001 и 250 шагах/с alpha=4, то есть предположение о малом шаге нарушено.

Ранее выполненный тест с результатом y=244 после пяти шагов сохранён как диагностический контрпример вне допустимого режима, не как блокирующий regression test. Замена интегратора, substeps или новый guard сейчас не предлагаются. В опытах фиксировать используемый шаг; Tau=0 остаётся pass-through.

### A13 — P2: один регистрационный вариант не применяет новые defaults к построенным детям

Источники: [NPulseLibrary.cpp](../../../Libraries/Nmsdk-PulseLib/Core/NPulseLibrary.cpp), 1190+; [NPulseNeuron.cpp](../../../Libraries/Nmsdk-PulseLib/Core/NPulseNeuron.cpp), setters 175+, ApplyElementDefaults; [UContainer.cpp](../../../Rdk/Core/Engine/UContainer.cpp), Build 2202+.

NSPNeuronGenPreinh2_5D002C25e11 сначала Build, затем задаёт UseElementDefaults/Capacity/TC и вызывает Build повторно. Setters Ready не сбрасывают, а Build при Ready сразу возвращается. В отличие от соседних AsymRm регистраций, явного ApplyElementDefaults нет. Поэтому свойства оболочки не гарантируют немедленное соответствие параметров каналов и синапсов.

**Доказательство:** статическая цепочка вызовов; runtime-регистрация полного Rdk не запускалась. Последующая полная пересборка объекта может скрыть дефект, поэтому нельзя по одному названию класса объявлять все исторические конфиги неверными.

**Исправление:** согласовать инициализацию до первого Build либо явно применить defaults после него; интеграционно проверить prototype и экземпляр из Storage, также после добавления сегментов и XML reload.

### A14 — P2: GUI пропускает узкие препятствия

Источник: [UModernDiagramLinkRouter.cpp](../../../Rdk/GUI/Qt/UModernDiagramLinkRouter.cpp), segmentHits и obstacleHitsOnPolyline.

Функция проверяет несколько точек сегмента (обычно восемь), не геометрическое пересечение. Линия (0,0)→(1000,0) пересекает rect(55,−10,10,20), но hit count=0. Маршрут может пройти через узел, хотя оценщик считает его свободным.

**Исправление:** точное пересечение отрезок–прямоугольник с padding и явной политикой касания. Для кривых — соответствующая геометрия/адаптивное разбиение с гарантированной точностью. Существующие 13 тестов сохранить; добавить adversarial узкие и длинные случаи.

### A15 — P2: Console повторяет сохранение и непоследовательно обрабатывает exit flag

Источник: [main.cpp](../../../App/NeuroModelerConsole/main.cpp), configureAutomation, строки 290–329.

После IsCalcFinished всех каналов таймер каждые 500 мс вызывает SaveProject при -S, если -x не завершил процесс. Нет latch/stop после успешного сохранения. Создание монитора учитывает AppCore.exitAfterCalcFlag, а quit — только cliExitAfterCalc, поэтому настройка, пришедшая не из CLI, может не завершить процесс.

**Исправление:** единый effective exit flag и обработчик завершения once-per-run, сбрасываемый при новом запуске; остановка таймера или latch, код ошибки сохранения. Проверить несколько каналов, отсутствие проекта/окружения, -S без -x и выход из настроек. Вывод получен по коду, runtime CLI не запускался.

### A16 — P1: verifier не обеспечивает заявленную приёмку и допускает старые артефакты

Источник: [posttune_verify.py](../../../Bin/Configs/SpikeSamples/StructTrain/scripts/posttune_verify.py), run_gate (352+), run_case / append_result (509–562+) и main.

Ненулевой return code дочернего gate не исключает последующее чтение CSV. expect_fires/expect_tipr попадают в результат, но не все ожидания проверяются как обязательные условия failure/ненулевого exit. mid_source_of считает threshold<0.9 с inference-флагом признаком cpp, не требуя пригодного landscape.

Harness может восстанавливать XML из flag/trace и завершать процесс извне. Это допустимая отдельная процедура, но не эквивалент штатному сохранению Console. Старые логи/CSV/flag должны быть исключены до запуска. В wait_need0 ветка более 12 GiB расположена после безусловного continue для более 2 GiB и недостижима.

Дополнение 2026-09-23: tipr_vs_keep сравнивает строки первых четырёх чисел, поэтому эквивалентные 2e7/20000000 получают diff. Сравнивается также чужой keep-клон, не собственный snapshot Search; diff не доказывает ни изменение физических весов, ни отсутствие отката. Test flag может перезаписать Train search_reverted при объединении метаданных — provenance фаз нужно хранить раздельно.

**Исправление:** уникальный run-id и каталог; строгие return codes; валидировать свежесть/полноту, соответствие hash конфигурации и бинарника; все ожидания превращать в assert с машинным verdict; сравнивать численные векторы с допусками, длиной и собственным snapshot, раздельно хранить Train/Test metadata. Разделить graceful-save и восстановление из trace. Тестировать намеренный child failure при наличии старого PASS CSV.

## 4. Оценка алгоритмов и исследовательских выводов

### Обучение длинам и амплитудам

Фактическая схема — joint train в фазе 0, не Sync→Normalize. TL использует fan-out и отдельные дендриты с последним как опорой; Branch обучает точки одного дендрита в обратном порядке. Это согласованные эвристические процедуры настройки по измеренным пикам, но доказательства сходимости для произвольного паттерна/параметров в коде и отчётах нет.

AllDendritesSynced / AllSynapsesNormalized содержат best-effort исключения: слабые/неизмеримые пики, пределы сопротивления и числа синапсов, отсутствие улучшения. Поэтому Done/Need=0 следует интерпретировать как остановку процедуры, а не доказательство выполнения всех исходных допусков. Нужны отдельные termination_reason, измеренные остатки времени/амплитуды и validity. Текущая документация теперь это отражает.

Изменение тайминга AutoScaleIterationGap=true сокращает интервалы относительно старых XML. Переход на текущий HEAD способен менять остаточную активность и калибровку даже при EnablePostTrainTuning=0. Для регрессии недостаточно одного переключателя.

### Статусы и независимость опытов

Каталог PHASE12 содержит **12 VALIDATED и 20 VALIDATED_CLONE**. Две VALIDATED — синхронизированные LtzCal-копии родителя. VALIDATED_CLONE проверяет перенос матрицы/рецепта с родительскими весами; это полезная проверка переноса, но не независимый cold-run каждого клона.

Срез PHASE12 закреплён на 780ffc7; RELIABILITY_MAP содержит более поздний pin d6baf6e; текущий PulseLib — fd79b0fb. Эти уровни нельзя объединять в заявление «32 cold-эксперимента подтверждают нынешний PostTune».

Первый сохранённый срез POSTTUNE_VERIFY_RESULT имел br25_on/asym25 skip_train и br100_search done_search_diff. Новый upstream-срез 16:47:46Z содержит только br100_search; оба теперь показаны с отдельной датой. Полный V1–V6 этим не подтверждается. Заявление search_reverted=1 не противоречит diff, но требует flag/trace текущего Train; прежний вывод о противоречии снят.

### Численные результаты

Пересчёт 175 канонических CSV текущим скриптом воспроизводит 106 ok_audit и 60 полных strict 8/8. Это воспроизводимость **расчёта метрик над сохранёнными данными**, не повторение самого моделирования.

Ранний last-pulse контрпример не найден среди принятых сохранённых строк, но потерянные после CloseTrial спайки нельзя восстановить из CSV. Исправление Python без повторного моделирования не устранит A01–A03. Same-Matrix калибровка принята как особенность A07. Её результаты сами по себе не показывают устойчивость на новых ISI, jitter, амплитудах или порядке сэмплов.

Результаты узкого threshold gap требуют анализа чувствительности к дискретизации и численным погрешностям. Одиночный удачный threshold не доказывает широкий рабочий диапазон. При отдельном исследовании обобщения программа может включать sweep вокруг порога и временного шага, несколько независимых cold-инициализаций и заранее отделённый test pack.

### Научная терминология

LTZone означает low-threshold zone, а не long-term plasticity. Приписывание ей LTP/LTD в Scientific-Background, API и нескольких component docs не соответствует реализации генерации выхода. Эти описания исправлены. Биологическая мотивация, совпадение формы сигналов и доказанная физиологическая точность — разные уровни подтверждения; ссылки на общую нейрофизиологию не заменяют проверки уравнений и размерностей конкретного класса.
