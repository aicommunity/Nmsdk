Need=1, отсутствующий Train flag, NaN/Inf, неизвестный snapshot и diff_after_revert имеют ненулевой verdict и понятный reason. ## P1. Единая физическая метрика и повтор минимального опыта

### 4. Устранить R05

Один collector задаёт выбранный физический сигнал и одинаковое накопление для iteration/search/free-run. Branch mode=LTZ исключает soma side channel. TL Soma использует максимум суммы во времени, если именно этот objective принят; мгновенное значение в конце окна не подменяет пик.

**Приёмка:** сигналы с soma peak=.8/LTZ peak=.2 различают режимы; несовпадающие по времени soma-пики различают sum(max), max(sum) и terminal sample. Один и тот же trace даёт одинаковую метрику во всех фазах каждого learner. Defaults Auto у TL/Branch сохраняются.

## P2. Исследование морфогенеза, если после исправленного измерения FAIL сохраняется

Начать с br25_on. До каждого опыта фиксировать гипотезу и менять один фактор:

| Проверяемая гипотеза | Контроль | Что различает причины |
|---|---|---|
| Неполный soft_cold reset | soft_cold и полная новая инициализация при одинаковых параметрах | Начальные L/R, anchors/snapshots, потенциалы, FixedLTZ |
| Изменение интервала влияет на остаточную активность | AutoScale 0/1 с записанными фактическими gap/delay | Одинаковые weights и разные timing, измеренные остатки |
| Канон ухудшает landscape новых длин | Одни свежие L, отдельно Canon/Keep, без других преобразований | target/max(all foils), global gap, полные traces |
| Ошибка переноса Train→Test | Прямая загрузка конечного Train и текущий overlay | Содержимое XML/weights до и после каждого преобразования |
| Best-effort завершение рано останавливает обучение | Лог termination reason и residuals каждого этапа | Фактические sync/amp отклонения, не только Need=0 |

Отрицательный gap по правильной метрике — отсутствие разделимости в данной параметризации; это может быть результатом эвристики, а не программной ошибкой. Обосновывать изменение алгоритма следует после локализации причины, с контрольной регрессией gold и исходного случая.

Далее повторить br25_off, br100_keep, asym25/asym50, br100_search и phase6_480 тем же протоколом. Для Search сравнить с **собственным** snapshot; отдельные поля applied_best/reverted и изменение gap. Успешный fallback не называть улучшением поиска. У phase6 отдельно задать regression expectation 10000010 и строгую цель 10000000: это разные вердикты.
