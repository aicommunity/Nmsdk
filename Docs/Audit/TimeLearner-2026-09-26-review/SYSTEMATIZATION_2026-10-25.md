## 1. Краткое резюме

### 1.1. Что установлено надёжно
1. **Console считает с dt = 0.5 мс** (DefaultTimeStep 2000). Пик одиночного звена 0.0157814 совпадает с `InitialSomaPotential` W04 (TH §1, FM §2). Модель `library.py` заложена на dt = 0.05 мс, то есть не та, что у Console (TH §0, стр. 9 и 31).
2. **Главный параметр — c = τ/S, а не длина L.** Дисперсионная граница: σ/S ≥ √(dt/S). Критерий S/4 требует τ ≲ 0.0075·S (TH §3, стр. 41–53).
   * При dt = 0.5 мс случай S25 недостижим (σ/S ≥ 0.14).
   * Для S100 граница 0.071 лежит на самом пределе.
   * S50 пассивно недостижим с запасом (TH стр. 53; FM §0 п.3).
3. **Линейный потолок набора из 8 ложных паттернов.** Ложные s1, s2, s4–s6 совпадают с целью по 3 спайкам из 4, поэтому m8 ≲ 0.25 при любых неотрицательных ядрах (TH §2, стр. 37). Ложный №6 при S100 совпадает по трём спайкам, а №4 отличается всего на S/8 (FM §2, стр. 62). Значит, m8 ≈ 0 ожидаем и регрессией не является.
4. **Тестовый протокол даёт артефакты порядка и ITI.** Когда цель идёт первой, выигрыш создаёт перенос состояния с предыдущего предъявления (CS: C1 nextseg 0.154 против tpos4 −0.198; simk2 +0.2389 / −1.2725; combo psi2.5+nextseg 0.2293 / −0.2192; W04_BR480 1.0 / −inf; W01_CL50 +0.0142 / −0.0188).
   * Хвост nextseg: −0.039 через 0.5 с и −0.003 через 1.5 с; при ITI 1.5 с он ещё переносится (CS; TH стр. 32).
   * Гипотеза lazy-wiring опровергнута (CS).
5. **Единственный положительный результат, не зависящий от порядка и ITI**, — `W08_BR480_N0_PSIoff_NEXT`: tgt 0.0365 / foil 0.0358, m ≈ +0.0196; у `br480_tiprmin` m ≈ +0.0177 (CS).
   * Запас всего около 2%.
   * W08, br480_nextseg и h0_b480_nextseg_n0_pton — одна детерминированная структура, а не 3 реплики.
   * Результат стабилен при ITI 1.5–12 с. С выключенным nextseg получается −0.034, срабатывают все паттерны.
   * Порог sep_margin ≥ 0.10 (PL Q1) не достигнут.
6. **Console детерминирован.** Сид через TipR-джиттер последнего отвода стирается SoftCold, поэтому пары s0/s1/s2 побитно совпадают (CS, аудит E05 A; DL11/DL17 `AGENT_KILL … provable duplicate`, 03:16–03:18 МСК).

### 1.2. Что опровергнуто
* Гипотеза «быстрые классы TauH0 / Sim как есть проходят критерий». FM §0 (segsim, dt 0.5): TauH0_S50 0.038, TauH0_S100 0.016, Sim2/Sim4/legacy < 0. H0b: 0 PASS (FM §1, `H0B_COLD_LAUNCH_2026-10-23.tsv`).

* «W0 — положительный контроль». Детекция PASS, но sep_margin ≈ 0.011 при пороге 0.10, то есть FAIL (CS).
* «Нормализация с ресинхронизацией (stage1) или подрезкой ёмкости (stage2) снимает отказ Classic E1». На smoke 7.5 исход не изменился (NS; SNAP: NSR_E1_c f0/f1/r2 и NSC_E1_c_t1 остаются `cpp_training_refusal`).

### 1.3. Что не проверено из-за ошибок
* **Торможение (PSI, NextSeg, SegEI) в Classic и Branch.** Ни одного валидного on/off-сравнения нет. Причины: ERR-10, ERR-11, ERR-12, ERR-14, ERR-15, ERR-27.

* **Реплики и разброс.** Независимых сидов нет (ERR-05).
* **Серия D** (сетка торможения S50/S100) невалидна как отрицательный результат: 4 красных флага (CS, 11:05). Остановлена решением Тима 25.10 в 11:22 МСК (файлы `STOPPED_BY_DECISION_2026-10-25` в job-каталогах .11/.17).

## 5. Рекомендации к рефакторингу

1. **Единый источник шага.** Сейчас dt задаётся в `library.py`, шаблонах Train/Test, `phase8_tiprmin_gate.py` и Project.ini разных линий (ERR-09, ERR-20). Нужен один параметр конфигурации, который читают Train, Test, PostTune и все гейты, и который попадает в result.json как readback. Если в Train и Test шаг разный, запуск должен отклоняться.
2. **Параметры, переживающие пересборку нейрона.** BuildStructure пересоздаёт нейрон из `NeuronClassName` (FM §1: Classic ≈3151–3161, Branch ≈3899–3908), XML-флаги теряются (ERR-10). Все физические параметры должны быть свойствами Learner/класса: Capacity, Rm/Rs exc/inh, Enable* торможения, NextSegInhResistance, NormalizationMode, InitEstDelayPerSeg, NumSynapse. Branch PostTune Rebuild не должен молча откатываться на 1e-9 (ERR-21).
3. **Обязательные readback-гейты.** После Train, после PostTune и перед Test читать из живой модели: класс, L, Capacity, Rm/Rs, Enable*, UsePresyn/NumSynapse, NormalizationMode, шаг, sha Console. Если не совпадает со spec — задача invalid, метрики null (ERR-01, 04, 14, 15). Отдельный флаг: «Test = обученная структура» (sha структуры Train == Test).
4. **Независимые seed.** Явный параметр Seed, который SoftCold не канонизирует (ERR-05). Приёмка: у реплик различаются траектории обучения.
5. **Порядок и пауза в тестовом протоколе.** Цель не первая; минимум 2 позиции цели; ITI ≥ 300 мс для S100 и ≥ 200 мс для S50 (FM §6), а для nextseg ≥ 6 с (CS). Перед стимулом проверять, что остаточный потенциал < 1% пика. Отчёт инвариантности: перестановки и ITI.
6. **Метрики.** Раздельно m(S/4), m(S/8), m8 (FM §6 п.5). Критерий — m(S/4) ≥ 0.10. Статусы обучения: Done_exact, Done_BE, refused, Ns == kMax, not_converged. Один gate вместо gate05 и phase8 (ERR-09). Метрики на шаблоне запрещены (ERR-04).
7. **Стоп-критерий Branch.** Явно связать с L_expect или целевой задержкой (ERR-06, ERR-07); NoImprove не должен срабатывать, пока растёт |dt| на Rmin.
8. **Classic на отказе (ERR-24).** Решение Тима (CS «Open for Tim»): поднять Rmax / принять отказную структуру как BE / сделать правильный перенос. После этого — штатный экспорт BE-структуры в Test с readback (ERR-03).
9. **Валидация параметров.** τ ≥ 2·dt для каждой мембраны, включая тормозную (ERR-22); MaxDendriteLength ≥ S/(τ − dt) (TH стр. 47).
10. **Запускалка и очередь.** Одна очередь на хост с поштучным запуском: не пакетами (ERR-26), резерв только по живым процессам (ERR-28), проверка окружения при старте (ERR-27), неизменяемая копия бинарника с sha на задачу (ERR-01, ERR-32). Дубликаты отсекать по fingerprint до запуска, а не через AGENT_KILL.
