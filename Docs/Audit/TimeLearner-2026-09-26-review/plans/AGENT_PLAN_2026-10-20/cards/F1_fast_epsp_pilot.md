# F1. Пилот «быстрый EPSP + точная задержка»

**Цель:** проверить главный вывод раздела «Модель нейрона и длина паттерна». Пассивный кабель не даёт положительного запаса разделимости ни при какой длине, потому что ширина EPSP растёт как 2.35·τ·√L. Положительный запас 11–25% даёт только сочетание узкого EPSP (τ = 0.25 мс) и задержки без дисперсии.
**Части:** F1a — офлайн, слабый агент, 30 мин. F1b — Console, **senior**: нужен новый тип конфигурации.
**Зависит от:** A0, C2. F1b — ещё и от C1 (модель кабеля валидна).

## F1a. Офлайн (слабый агент)

```bash
source "$HOME/tl-agent/env.sh"; OUT="$REPORTS/F1a_$(date -u +%Y%m%d)_$HOSTTAG"; mkdir -p "$OUT"; cd "$CABLE"
test -x ./cable || gcc -O2 -o cable cable.c -lm
python3 ideal_delay.py | tee "$OUT/ideal_delay.jsonl"
python3 sweep.py 0.00025 0.001 25,50,100 | grep '^{' | tee "$OUT/sweep_tau025.jsonl"
python3 classic_full.py 0.01 0.001 25 15,12,8,1 | tail -3 | tee "$OUT/classic_full_w10.txt"
```

**Ожидаемо:**

- `ideal_delay`: margin = 0.1158 / 0.2044 / 0.2446 / 0.2499 / 0.25 для 25 / 50 / 100 / 200 / 480 мс;
- `sweep 0.00025`: `feasible=false` (нужно L > 100). Тот же быстрый нейрон на пассивном кабеле не синхронизируется;
- `classic_full`: запас для обученного состояния W10/packA (L = 15,12,8,1) — записать как есть.

Вывод для отчёта: какие из текущих конфигураций матрицы используют τ = 0.25 мс на пассивном кабеле. Это `NSPNeuronGenAsymRmD001C25e12*`: W13 ltz*_preinh, W37 PACKC. По модели они **не могут** синхронизироваться длиной ≤ 100. Сверить с их результатами в `TimeLearnerMatrix/W13/results.json` и `W37/results.json`; записать `training_convergence` каждого случая.

## F1b. Console (senior; карточка — спецификация, а не команды)

**Конфигурация:** Classic Test без обучения, 4 входа. Каждый вход — дендрит L = 1 с моделью `NSPNeuronGenAsymRmD001C25e12` (τ = 0.25 мс). Между генератором и синапсом стоит `NAxoneDelay` (PulseLib `Core/NAxoneDelay.h`) с задержкой `d_k = S − t_k` (t_k — время k-го импульса цели), так что все 4 EPSP целевого паттерна приходят одновременно. Тестовый набор — тот же, 8 паттернов, масштаб S = 25 и 50 мс.

**Порог:** mid между `max(foil)` и `target` по пикам `ltz_potential` из trace. Порог считается на одном прогоне и проверяется на втором, с другим порядком паттернов.

**Критерии успеха:** запас (target − max foil)/target ≥ 0.08 при S = 25 мс и ≥ 0.15 при S = 50 мс (модель: 0.116 и 0.204), fires = `10000000`, 3 повтора.

**Что сделать до запуска:**

1. Проверить по исходникам, как `NAxoneDelay` берёт задержку: свойство, единицы, дискретизация шагом модели. Задержка должна быть кратна шагу; при 2000 Гц шаг 0.5 мс, а это сравнимо с FWHM 1.5 мс. Поэтому DefaultTimeStep ≥ 20000 Гц обязателен.
2. Собрать XML вручную из Test-шаблона W01 (20000 Гц). Проверить проводку `check_model_wiring.py` (правила Classic с L = 1) и отдельно — что каждый `NAxoneDelay` стоит ровно на одном пути.
3. Если подтвердится: следующий шаг — тренер подбирает `d_k` (длину задержки), а не длину кабеля. Это отдельная задача проектирования (этап 4 плана, ControllerVersion = 2).
