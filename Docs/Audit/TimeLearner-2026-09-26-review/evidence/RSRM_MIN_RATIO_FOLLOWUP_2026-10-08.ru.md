# Нижняя граница Rs/Rm: обоснование и реализация

Дата: 2026-10-08. Продолжение проверки сопротивлений из [`RSRM_D_RETEST_2026-10-08.ru.md`](RSRM_D_RETEST_2026-10-08.ru.md).

## Вывод по физическому обоснованию

В статье А. В. Бахшиева и С. П. Романова «Воспроизведение реакций естественных нейронов как результат моделирования структурно-функциональных свойств мембраны и организации синаптического аппарата» на рисунке 2 (печатная стр. 5) показан вклад синапса в мембранный потенциал при разных `Rs/Rm`. Текст статьи называет эффективным диапазоном управления `Rs/Rm ∈ [0.1; 10]`. На графике влияние быстро падает ниже `0.1`; выше `10` кривая приближается к плато.

Поэтому абсолютный `ResistanceMin` не должен быть параметром в омах. Его следует получать из мембранного сопротивления и dimensionless-границы `Rs/Rm`. В статье эффективный диапазон ограничен `[0.1;10]`, но верхний предел `1000` уже был намеренно расширен по указанию пользователя для проверки дополнительного затухания. Пользователь подтвердил использовать один параметр и его обратную величину для обоих пределов. Поэтому при `MaxSynapseToMembraneResistanceRatio=1000` нижнее отношение равно `0.001`.

Это **не** утверждение, что `0.001` входит в эффективную область статьи: там влияние ниже `0.1` уже мало. Симметричный интервал `0.001…1000` сохраняет широкую область для экспериментального поиска, заданную верхним параметром, и разрешает модели проверять нижнюю сторону такого же логарифмического диапазона. Прогоны должны отдельно показать, не приводит ли нижняя область к практически нулевому вкладу и затруднению обучения.

## Глобальные границы для набора дендритов

Тренер пока использует одну скалярную пару `ResistanceMin` / `ResistanceMax` для всех tip-синапсов. Для неодинаковых `Rm` нижняя граница вычисляется от наибольшего целевого `Rm`, а верхняя — от наименьшего:

```text
ResistanceMin = max(target Rm) / MaxSynapseToMembraneResistanceRatio
ResistanceMax = min(target Rm) × MaxSynapseToMembraneResistanceRatio
```

Здесь `min_ratio = 1 / MaxSynapseToMembraneResistanceRatio`, то есть у диапазона один параметр и обратные друг другу отношения. Общий интервал гарантирует для каждого целевого дендрита `1/ratio <= Rs/Rm_i <= ratio`. Для существования общей скалярной границы разброс целевых сопротивлений должен удовлетворять `max(Rm)/min(Rm) <= ratio²`; иначе допустимые интервалы разных дендритов не пересекаются. В этом случае построение/обновление отклоняется. Коэффициент должен быть конечным и не меньше 1.

При одинаковом `Rm=10 МОм` и верхнем коэффициенте `1000` получается `ResistanceMin=10 кОм` (`0.001 Rm`) и `ResistanceMax=10 ГОм` (`1000 Rm`). Нижний предел теперь масштабируется вместе с мембранным сопротивлением и на два порядка ниже прежнего default `1 МОм`. В D-конфигах абсолютный `ResistanceMin=20 МОм` ранее совпадал с `TipResistanceCanonFloor`; эти две роли были смешаны.

## Изменения в C++

- В `NNeuronTimeLearner` и `NNeuronTimeLearnerBranch` свойство `ResistanceMin` стало наблюдаемым `ptPubState`, симметрично `ResistanceMax`.
- Оба тренера теперь рассчитывают и валидируют границы из текущей топологии мембран. Нижнее отношение выводится как обратное к `MaxSynapseToMembraneResistanceRatio`; при значении `1000` оно равно `0.001`.
- `ResistanceMin` и `ResistanceMax` очищаются в структурном режиме; расчёт применяется только в параметрическом режиме.
- `TipResistanceCanonFloor` остаётся самостоятельной настройкой посттренировочного канонического вектора. `ApplyPostTrainTipMode` больше не подменяет им состояние тренировочной нижней границы.
- В read-only iteration audit добавлены `rmin` и `rs_rm_min`, чтобы в логах были видны эффективная нижняя граница и использованный коэффициент.
- Интеграционные проверки покрывают вычисление reciprocal-границ в Classic/Branch и сброс обеих границ в структурном режиме.
- Из `posttune_verify.py` удалён устаревший `--resistance-min`, который записывал нижнюю границу в XML как независимый `ptPubParameter`; исследовательские override теперь могут менять общий коэффициент и начальную Rs/Rm, а нижняя граница всегда выводится из коэффициента. SoftCold reset и salvage также больше не записывают исторические `20 МОм` в вычисляемое состояние.

Старые XML, содержащие абсолютный `<ResistanceMin>` (включая `20 МОм`), теперь несут устаревшее состояние: после построения параметрического тренера оно заменяется вычисленным значением. Настройку результата CanonRmin по-прежнему задаёт `TipResistanceCanonFloor`. Поэтому параметры обучения в старых XML после обновления C++ не воспроизводят прежнюю нижнюю границу 20 МОм; это ожидаемое изменение новой политики.

## Удалённая сборка и C++-проверки

Сборка и эксперименты выполняются только на сервере, в отдельных временных checkout и run workdir. Рабочая станция не использовалась.

- Linux Console собран из root `cea2ae90`, PulseLib `b5229e4`, Bin `5685edb`; SHA256 бинарного файла `NeuroModelerConsole`: `4f336d3c26fdee73e012047b21e9f916097601ee2c047c633a6facbc073f1214`.
- `TimeLearnerResistanceTest.*`: 6/6 проверок прошли, включая Classic/Branch, параметрический cold start, структурный режим и проверку `ratio >= 1`.
- Для текущих выбранных запусков прочитанное из C++ состояние подтверждает `rmin=10000`, `rmax=10000000000`, `rs_rm_min=0.001`, `rs_rm_limit=1000` и `rs_rm_initial=1` в параметрическом режиме. Значит, старый XML `ResistanceMin=20 МОм` не блокирует новый диапазон после cold reset.

## Монитор завершения и дальнейшая проверка

Старый экспериментальный монитор мог ждать окончания Console до `-t` даже после того, как C++ записал отказ в `TimeLearnerTrainingAudit.log`. В Bin добавлена проверка append-only аудита на `failure_reason>0` с завершением Console и отдельным статусом запуска; обычное завершение по `Need=0`/post-train flag также обрабатывается монитором с коротким grace-периодом для сохранения `-S`. Это только orchestration эксперимента; алгоритм и состояние тренера не меняются.

Старые активные процессы ещё не имеют терминального `failure_reason`: их последний аудит был `phase=0`, `Need=1`. Их не следует перезапускать с нуля только ради нового монитора; серверный watcher проверяет пять старых аудитов раз в 10 секунд и посылает `SIGTERM` только соответствующему Console при `failure_reason>0`. При появлении терминального состояния процесс останавливается без ожидания исчерпания `-t`. Новые запуски следует сразу делать с failure-aware монитором; снимать `-t` для этого не требуется. На последней проверке пять старых процессов шли около часа wall-clock, новый `br25_on` — около 25 минут. `-t=320/640` задаёт модельное время, поэтому wall-clock ETA зависит от тяжести конкретной модели и параллельной нагрузки; для обоих `-t=640` запусков оно существенно дольше. У `asym50_preinh` пока нет ни одного валидного пика.

Работа с нижней границей существенно меняет пространство параметров: при `Rm=10 МОм` разрешённый минимум теперь `10 кОм`, а холодный старт `Rs/Rm=1` не ограничивается прежним абсолютным `ResistanceMin=20 МОм`. Поэтому прежние результаты нельзя переносить на этот код.
