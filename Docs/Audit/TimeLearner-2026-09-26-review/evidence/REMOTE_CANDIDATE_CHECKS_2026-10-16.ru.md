## Уточнение Branch invalid-peak проверки

Первое сообщение о провале `BranchInvalidPeakNoRecoveryTest.RefusesAfterRepeatedNoActionAboveRmin` было получено при сборке, которая не перекомпилировала `NNeuronTimeLearnerBranch.cpp`: timestamp объектного файла был новее исходника. Этот результат был ложным для текущего исходного candidate diff. После принудительной пересборки изменённый файл вошёл в библиотеку; временная инструментальная печать подтвердила срабатывание `no_legal_recovery`, затем была удалена. В тесте оставлены полезные assertions: после третьего no-action вызова timing error остаётся выше `0.02`, счётчик достигает `3`, и проверяются `FailureReason=3` и `Phase=5`. В итоговом forced run все 34 assertions прошли.

В `.11` forced build также действительно перекомпилировал `NDatasetBase.cpp`, `NNeuronTimeLearner.cpp`, `NNeuronTimeLearnerBranch.cpp`, `NPulseSynapseCommon.cpp` и тестовые translation units. Следовательно, результат 49/49 относится к обновлённым исходникам, а не к старым объектам.

- `.11` и `.17` root checkout сильно отстают от origin и содержат незатреканные исторические данные. Не обновлять их поверх существующих деревьев и не чистить их. Перед новыми опытами нужно создать чистые изолированные checkout на актуальном `codex/historical_view`, перенеся в них только кандидатные изменения после отдельного review/rebase.
- Отдельно проверить общий teardown SIGSEGV в тестовом harness. Он возникает после успешных assertions и сам по себе не свидетельствует о дефекте проверяемой логики тренера.

## Предварительный review логики кандидатов

Проверка исходников после тестов выявила ограничения, которые не видны по успешным assertions:

- В `.11` `UpdateResistanceBoundsFromMembranes()` задаёт `effective_synapses = 1` для любого параметрического режима. При этом физическая модель учитывает режим `UseAverageSynapsis`, а `GetNumSynapses()` может вернуть больше одного подключённого входа. В канале без усреднения суммарная проводимость растёт с числом входов; нижняя граница, рассчитанная как для одного входа, тогда не гарантирует заявленное ограничение. Перед применением нужно вычислять эффективное число по фактическому `UseAverageSynapsis`/числу соединений и сверить с кодом `NPulseChannel::ACalculate2()`.
- Этот же кандидат сохраняет назначение `SynapseResistanceStep` новым синапсам в структурном режиме. Следовательно, он не устраняет ранее отмеченное отличие N0 от исторического правила «новый синапс получает параметры существующего»; это отдельная ветка исследования.
- Кандидат `.17` с `no_legal_recovery` — ранний отказ после повторных итераций без разрешённого шага; он не добавляет шаг восстановления и действует только при `IsParametricNormalization()`. Поэтому он не объясняет и не исправляет W03 с чисто структурным N0. Его Branch-тест проверяет только контракт явного отказа для заданной N1-фикстуры.
- Оба набора тестов подтверждают локальные assertions, но не проверяют динамику канала на нескольких входах, реальное ограничение Rs, естественную сходимость или качество классификации. Серверные diff пока остаются исследовательскими кандидатами; переносить или коммитить их без адаптации к базе `c8a0a891` и целевых интеграционных проверок рано.
