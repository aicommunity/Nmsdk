# Диагностика восстановления порядка Branch после коллапса амплитуды — 2026-10-13

## Краткий вывод

Трасса BR100 выявила узкое противоречие в ветке Branch. При невалидном пике код может признать вход «best effort synced» после подтверждённого коллапса амплитуды и исчерпания лимита синапсов, но затем не восстанавливает нарушенный порядок длин сегментов. Финальная проверка порядка блокирует `PulseSynced`, а селектор оставляет этот вход активным. В результате состояние может повторяться без изменения длин и с `Need=1`.

Это подтверждённый дефект перехода состояния в проверенном случае, а не доказательство, что все Branch-отказы вызваны им. Исправление не меняет нормальную настройку по валидному пику и не разрешает рост длины при произвольном отсутствии пика.

## Причина в коде

В `NNeuronTimeLearnerBranch::ChangeDendriteStatus` ветка невалидного пика выходит раньше проверки структурного порядка. В ней предусмотрен best-effort переход при амплитуде ниже порога и исчерпанном лимите синапсов, но он только ставит `DendBestEffortSynced`. На завершении итерации `FinishTrainingIteration` всё ещё требует строгого порядка длин, чтобы установить `PulseSynced`. Поскольку `SelectActiveDendrite` выбирает первый несинхронизированный импульс, этот вход остаётся активным.

Проверка порядка, добавленная в коммите `10a9549 Fix Branch segment-order liveness`, находилась после раннего выхода и применялась только при валидных пиках. Поэтому заявленное восстановление порядка не охватывало best-effort путь, который сам должен позволять пройти дальше после подтверждённого амплитудного коллапса.

## Исправление и C++ проверки

В PulseLib-коммите `e4e0274 fix(Branch): repair order after exhausted amp collapse` общий переход проверки порядка вызывается и для валидного измерения, и для best-effort случая с одновременно подтверждённым падением амплитуды и исчерпанием синапсов. Если длину можно увеличить, выставляется `DendStatus=1`; при невозможности восстановить порядок на `MaxDendriteLength` сохраняется отказ с `TrainingFailureReason=2`. Одного лишь отсутствия пика или model-derived оценки недостаточно для роста.

В корне коммит `c8d05b5 test(TimeLearnerBranch): cover collapse order recovery` добавил проверки:

- рост при валидном пике и нарушенном порядке;
- отсутствие роста при невалидном пике без подтверждённого коллапса;
- восстановление порядка при подтверждённом коллапсе и исчерпании синапсов;
- отказ по `MaxDendriteLength` в том же best-effort сценарии.

Release-сборка `NeuroModelerConsole` и `Test_PulseLib_StorageComponents` прошла на `.17`. Все пять тестов `BranchSegmentOrderTransitionTest` завершились PASS. Полный integration executable сообщил PASS всех 29 тестов, затем упал в общем `UAppCore` teardown (`UGenericMutexSharedLocker` / `URdkCoreManager::GetNumChannels`) после финального отчёта тестов; это завершение тестового процесса отдельно от результата новых Branch assertions.

Повторный запуск тестов сохранил stdout в `/media/user/Data/NmsdkStructTrainArchive/TimeLearnerAudit-20261013-historical_view/release-tests/`: выборочная проверка завершилась с process exit 0 (SHA-256 `7296dad6e03015f659bb9ca53a1f9552bfa1094d2b7f429b28060c1b39d78ec7`), полный integration executable — process exit 139 после 29 PASS (лог SHA-256 `2fdf64987fd66d2223077b5cc145ad7f6b126a6c929f38a735bb7686c58f47eb`).
