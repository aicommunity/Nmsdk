## Цель и границы

Сравнить влияние начального отношения `Rs/Rm` на структурно-параметрическую нормализацию (`NormalizationMode=1`) отдельно для Classic и Branch, PSI on/off. Проверяются сходимость C++-обучения и качество Test независимо. Это не полный перебор матрицы и не попытка оптимизировать классификатор.

Поэтому выявленная отдельно ошибка сериализованного `ResistanceMin` не подменила стартовое отношение в этих запусках.

## Исправление подтверждённой ошибки холодного старта

До вычисления per-input bounds индексный `ClampResistance()` в Classic и Branch переходил к legacy scalar `ResistanceMin`. При старом сериализованном `ResistanceMin=20 МОм` это могло заменить явно заданное значение из XML ещё до построения топологии. Исправление сохраняет конечное положительное входное `Rs` до появления per-input bounds, а после их построения оставляет обычное ограничение по derived диапазону. Структурный режим `NormalizationMode=0` не менялся.

Исправление отправлено в `origin/codex/historical_view`:

- PulseLib `97dd521` — обе независимые реализации Classic и Branch;
- root `d1d5ebc` — gitlink и regression-тесты для обоих тренеров.

`.17`, Linux Release (GCC 13.3), собрал `NeuroModelerConsole` и `Test_PulseLib_StorageComponents`. CTest `PulseLib_StorageComponents` прошёл `1/1`; отдельный фильтр запустил два новых regression-теста, оба прошли. Release Console SHA-256: `f76f90565eee8eefc241e7bf03b31e6504f2b998c6592a2cdf1c249a31f01d9e`. Сборка с `RDK_USE_LLM=OFF`; обучение на Windows не проводилось.

Следовательно, обратный порядок выбора активного импульса сам по себе не объясняет, почему первый элемент остаётся коротким.

## История `SynapseResistanceStep`

В доступной истории Git значение `1e9` не появилось в октябрьских правках. Старый `NNeuronTrainer` уже по умолчанию назначал добавляемым синапсам `SynapseResistanceStep=1e9`; это видно в исходном снимке `0b03edb` (2023-10-10). Temporal Classic был добавлен коммитом `ad50903` (2026-08-10) как адаптация/копия `NNeuronLearner` и сохранил этот default; Branch добавлен `279116d` (2026-08-18) с тем же default. Коммиты описывают добавление структурных синапсов и применение свойства, но численного обоснования выбора 1 ГОм не содержат. Документация определяет свойство только как сопротивление новых синапсов.

Это уточняет историческое предположение: в базовой реализации новые контакты по умолчанию не наследовали сопротивление исходного синапса. В отдельных экспериментах конфиги могли переопределять это свойство, поэтому историю нужно сверять по фактическому Train-файлу и runtime provenance каждого результата. Текущие парные повторы показывают, что 1 ГОм существенно повышает число контактов на коротком Branch25 относительно 86 МОм, но пока не устраняет невалидный пик или `Need=1`. Поэтому legacy-default объясняет происхождение поведения, но не доказывает его пригодность для каждого диапазона Rm и длительности паттерна.

Сравнение условий указывает на конкретный эффект автооценки: после одинакового первого роста `1→9` она выводит gamma из fallback `0.05` на основании `amp/initial` и затем при росте `9→17` снижает Rs примерно в 5.5–7.3 раза сильнее, чем фиксированная gamma. На измерении длины 17 это совпало с большим превышением целевой амплитуды; с fixed `0.05` пик оставался немного ниже исходного эталона. Значит, в этой траектории auto-gamma не просто ускоряет достижение Rs floor, а даёт крупную нелинейную коррекцию амплитуды. Однако оба варианта позже достигли `Rmin`, не восстановили все пики и завершились одинаковым типом C++-отказа при `L3=89<MaxLen=100`. Это ухудшающий фактор траектории, но не единственная причина несходимости.

Код оценивает `gamma_obs = -log(MaxIterSomaAmp/InitialSomaPotential)/(DendriteLength-1)` внутри `ChangeSynapseResistanceStatus()`, а отдельная функция `FeedforwardResistanceOnLengthGrow()` затем применяет `Rs *= exp(-gamma*ΔL)`. В момент оценки Rs уже менялся feed-forward на предыдущем росте; поэтому наблюдаемое отношение амплитуд включает реакцию всей модели, а не изолированное пассивное затухание кабеля. Кроме того, `ResetToUntrained()` явно заменяет загруженное из XML значение gamma на sentinel `-1`, если включена автооценка; поэтому начальный `AttenuationGamma=0.11149` из W04-конфига не используется как стартовое значение — первый рост идёт по fallback `0.05`. Это текущий контракт reset, подтверждённый runtime audit. Возможное влияние такого оценщика на величину коррекции требует контроля: сами прогоны показывают согласованную последовательность, а не математическое доказательство ошибки.

Из старых опытов известно, что при отключённом feed-forward AmpNorm тоже способен довести Rs до Rmin, а Branch480 всё равно отказывает по другому входу до оценки качества ([абляция 14 октября](../RS_DROP_AND_MIN_RATIO_INVESTIGATION_2026-10-13.ru.md)). Поэтому ни фиксированная gamma, ни исправление одной автооценки не являются достаточным решением сходимости. Следующий экспериментальный шаг уже запущен на `.17`: `W04_BR480_N1` PSI off/on в режиме `per-input-auto` (`tl-b10-w04-br480-n1-perinputauto-20261017`). Он сравнит общую gamma, которая меняется при последовательной обработке разных входов, с независимым коэффициентом для каждого входа. Одновременно на `.11` идёт текущий Classic480 N1 fixed-gamma контроль; общий активный лимит остаётся не выше 20 Console.

Перед запуском сверю фактическую свободную ёмкость диска и число уже работающих Console.
