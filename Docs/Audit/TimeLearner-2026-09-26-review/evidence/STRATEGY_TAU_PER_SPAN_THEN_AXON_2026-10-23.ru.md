# Стратегия 2026-10-23: τ по классу паттерна (дендрит) → затем аксонный тренер (F1b)

**Статус:** нормативное дополнение к плану аудита и AGENT_PLAN. **Не** отменяет выполненные evidence (E1.*, F1a, F3–F5, CL-N1 H1, SPEC DRAFT и пр.).  
**Источник решения:** senior 2026-10-23 (уточнение после F1b-разъяснения).  
**Канон плана:** [`../TIMELEARNER_AUDIT_AND_PLAN_2026-10-20.ru.md`](../TIMELEARNER_AUDIT_AND_PLAN_2026-10-20.ru.md) §«Дополнение 23.10»; исполняемый пакет [`../plans/AGENT_PLAN_2026-10-20/`](../plans/AGENT_PLAN_2026-10-20/).

## 1. Диагноз смешения задач

В кампании и в формулировках «единая модель нейрона» фактически смешали **две разные задачи**:

1. **Чисто дендритное обучение** — задержка и амплитуда на пассивном / модифицированном дендрите (длины сегментов, TipR, mods: gen / preinh / nextseg / AsymRm / FastSpan / LTZ / PSI и т.д.). Тренеры: Classic и Branch; режимы: чисто структурный (N0) и структурно-параметрический (N1).
2. **Обучение на аксонах** — носитель задержки вне дендрита-приёмника: рост / подбор сегментов аксонов **нейронов-источников** сигнала (элемент точной задержки / регенеративный аксон). Это **отдельный тренер** (план F1b / этап «аксоны»), а не патч к текущему дендритному контроллеру.

Попытка решить **все** длины паттерна (25…480 мс) **одной** постоянной времени мембраны сегмента τ — ошибочная постановка. Безразмерный критерий FWHM/span связывает τ и span; при фиксированном MaxDendriteLength одна τ не обслуживает все классы одинаково хорошо. Вывод F1a/C2 («при L≤100 запас неположителен ни при каком τ») относится к **единой** τ на всём наборе спанов, а не запрещает подбор **своей** рабочей τ под каждый класс паттерна.

**F1b не отбрасываем.** Пилот «быстрый EPSP + `NAxoneDelay`» и дальнейшая линия — **план реализации обучения на аксонах**. Особенность: обучение идёт за счёт роста сегментов аксонов источников. Это **основное направление после** того, как будут исчерпаны возможности и ограничения **чисто дендритного** обучения.

## 2. Ближайший фокус: дендрит, τ по классу паттерна (через Cm)

### 2.1 Принцип

- Для **каждого класса паттерна** (ось Span: 25 / 50 / 100 / 200 / 480 мс, при необходимости укрупнённые корзины) подобрать **рабочую постоянную времени** τ сегмента так, чтобы задача была **максимально хорошо разделима** (FWHM/span в благоприятной зоне; запас по предсказателю E1.4 / офлайн C2; достижимые L при текущем MaxL).
- Реализация предпочтительно через корректировку **ёмкости мембраны Cm** (при фиксированных Rm и логике сопротивлений): так меняется \(\tau = R_m C_m\), **не** ломая отношение сопротивлений синапса и мембраны (TipR / Rs / Rm), от которого зависят амплитудные рычаги N1 и калибровки.
- Для каждого найденного решения зафиксировать **свой тип нейрона** (NeuronModel / XML-профиль с данной Cm и родственными параметрами) и **не** требовать, чтобы тот же тип обслуживал чужой класс спана.

### 2.2 Обязательное изучение на каждом найденном τ-решении

Иерархия группировки результатов — канон [`RESULT_GROUPING_HIERARCHY.ru.md`](RESULT_GROUPING_HIERARCHY.ru.md):

1. **Trainer × Mode:** Classic×N0, Classic×N1, Branch×N0, Branch×N1.  
2. **Span** (класс паттерна, для которого выбрана τ).  
3. **NeuronModel** — выбранный профиль с данной τ(Cm) (+ AsymRm / FastSpan / LTZ как отдельные модели, если входят в сетку).  
4. **Mod:** gen / preinh / nextseg / PSI / …  
5. Колонки PostTune ON/OFF; ссылки на **Train** и **Test** в каждой строке.

Цель фазы: карта «какие (Span, τ(Cm), NeuronModel, Mod) дают устойчивую разделимость и сходимость» для **обоих** тренеров и **обоих** режимов — до любых выводов о «потолке дендрита».

### 2.3 Что сохраняется из уже сделанного

Не выбрасывать и не переписывать как «ошибку»:

- F1a / C2 (идеальная задержка vs пассив; feasible при L≤100 для **несогласованной** τ);
- E1.0–E1.5 (ядра, repeatability, relaxation, predictor, fragility);
- фиксы F2–F8 / F3-R8 / mid H3 / silent-Test partial / CL-N1 H1 (480-specific) / SPEC DRAFT;
- tl-baseline, E0 `--train-param`, A15 hygiene.

Их роль в новой стратегии: **измерительная база и ограничения**, внутри которых ищется τ(Cm) per Span; плюс регрессионный якорь R8 при смене NeuronModel.

### 2.4 Связь с контроллером v2 (дендритная часть)

Пока идёт дендритная фаза:

- `LEN_SEARCH` / `AMP_ALIGN` / mid / VERIFY / exit-классы H2 — остаются в силе для **дендритного** контроллера.
- Шаг `FINE_DELAY` через аксонную задержку **не** блокирует дендритные эксперименты и **не** требует немедленного Console-пилота F1b: он относится к **следующей** фазе (аксонный тренер). В SPEC DRAFT F1b переводится из «блокер FINAL дендритного v2» в «отдельный продукт / фаза 2»; числовые tol и mid для дендритного v2 закрываются без обязательного axon PASS.

## 3. Поздняя фаза: аксонный тренер (F1b → отдельный тренер)

| Тема | Норматив |
|------|----------|
| Статус F1b | **Не отменён**; docs-ready checklist сохраняется |
| Суть | Обучение за счёт роста сегментов аксонов нейронов-**источников**; точная задержка без дисперсии кабеля приёмника |
| Когда | После завершения исследования возможностей и ограничений **чисто дендритного** обучения (τ per Span + Trainer×Mode×Mod карта) |
| Артефакты | Отдельный тренер (не смешивать с Classic/Branch дендритным кодом без явного fork); пилот Console из карточки F1b — вход в эту фазу |
| Связь с планом 20.10 | Этап 6 «регенеративные аксоны» / E1.6 — уточняются как **фаза аксонов**, не как замена дендритного τ-подбора |

До go-ahead senior на аксонный cold: не стартовать F1b Console из тиков монитора; не подменять дендритные cold аксонным пилотом.

## 4. Очерёдность работ (без потери старых этапов)

```
[уже сделано / в полёте]  измерительная база, фиксы, SPEC DRAFT, долги D2/CL-N1/F5…
        │
        ▼
Фаза D — Дендрит: подбор τ(Cm) × класс Span
        → карта NeuronModel per Span
        → сетка Trainer×Mode × Mod (preinh, nextseg, asym, …) на каждом решении
        → при необходимости доработка дендритного Controller v2 FINAL (mid/tol/CL-N1 policy)
        │
        ▼
Ворота D: «потолок / карта дендрита» задокументированы; R8 и ключевые острова не потеряны
        │
        ▼
Фаза A — Аксоны (F1b): отдельный тренер, рост аксонов источников
        → Console-пилот → train-loop → сравнение с дендритной картой
```

Старые этапы 0–5 AGENT_PLAN / аудита **остаются** в силе как backlog и evidence; новые работы фазы D **добавляются** сверху, не удаляя карточки A–G1.
