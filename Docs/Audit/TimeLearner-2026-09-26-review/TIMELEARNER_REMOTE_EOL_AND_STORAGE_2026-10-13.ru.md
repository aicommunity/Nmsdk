# Переносимость снимков входов и размещение логов TimeLearner — 2026-10-13

## Выявленная причина отказа подготовки W04

Первый запуск на `.17` не дошёл до обучения: подготовка волны остановилась на сообщении, что определение матрицы отличается от сохранённого снимка. Это было ложное несовпадение из-за переводов строк при переносе между Windows и Linux:

- одна и та же `matrix.json` в Windows checkout с CRLF имела SHA-256 `6a2fcf4799e09393d277f98cb2209c71a9fe62a61b7298972fe5cafe0783a7d6`, совпадающий со значением в W04-манифестах;
- Git blob и Linux checkout с LF имели SHA-256 `d00f8aaf166d336afcf3415802c4d35170236df1c9b1ee462570d2747ca5269b`;
- у `Train/Model_00.xml` BR480-манифест сохранял хеш CRLF `520d199b…`, тогда как SHA-256 Linux/Git blob был `777646b0…`; после сведения переводов строк к LF файл побайтно совпадает с Git blob.

Таким образом, матрица и конфиги не были изменены по смыслу. Runner ошибочно сравнивал сырые хеши файлов. Исправление в Bin `180c600` принимает только LF/CRLF-варианты одинакового UTF-8 текста. Хеши бинарных и не-UTF-8 файлов остаются точными; любые отличия содержимого, факторов матрицы или файлов входа по-прежнему отклоняются. Новые манифесты дополнительно сохраняют нормализованный LF-хеш матрицы.
