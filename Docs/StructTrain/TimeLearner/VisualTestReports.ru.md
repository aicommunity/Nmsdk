# Обязательные графические отчёты испытаний

Требование пользователя от 29.10.2026, дополнение к этапам 3, 9, 10, 11 и 12.
Статус: включено в план; первая часть production renderer реализована в отдельной
ветке, полная матрица и визуальная приёмка ещё не выполнены.
Текущая реализация и открытые требования: [VisualReportRenderer.ru.md](VisualReportRenderer.ru.md).

## Обязательное содержание

Для всех предъявленных target и foil паттернов, всех их повторов и всех soma
сохранять временные графики мембранного потенциала на выходе сомы с наложенными
фактическими входными импульсами. Не ограничиваться успешными cases, средними
кривыми или одним выбранным паттерном. Failed, unresolved, silent и censored
cases также присутствуют с явным статусом и границами доступных данных.

Каждая пара trial/soma имеет индивидуальный график, а не только миниатюру в сетке.
Индекс отчёта связывает run/trial/sample ID, label, фактическую позицию предъявления,
reset policy, ITI, model hash, конфигурацию и исходные данные с соответствующими
рисунками. Для одного входного потока, подаваемого на несколько кончиков,
показывается реальный общий поток и routing; независимые источники не выдумываются.
При нескольких источниках отображаются все фактически поданные потоки с легендой.

Использовать именно записанный soma membrane potential; в descriptor указать
полный путь компонента/свойства, роль канала и единицы. Не подменять его LTZone
pulse output, максимумом, нормализованной огибающей или предсказанным сигналом.
Существующий recorder записывает Soma*.SumPotential: связь этого свойства с
выходным потенциалом проверяется для каждого поддерживаемого физического класса.
Нужны descriptors всех каналов, без прежнего ограничения четырьмя значениями.

## Масштаб, пригодный для визуального анализа

1. Для каждого паттерна нужен крупный overview полного observation window,
   включая baseline до стимула, весь burst, хвост ответа и область учёта late FP.
   Для continuous серии дополнительно нужна временная панорама фактического
   порядка, ITI и границ/reset событий; промежутки времени не сжимаются молча.
2. Нужны отдельные zoom-панели burst/ответа и при необходимости хвоста. Окна
   масштабируются так, чтобы узкие входные импульсы, детали фронтов и временные
   расхождения различались глазами. Если весь burst не помещается в таком
   масштабе, строится несколько увеличенных фрагментов с видимыми границами
   на overview. Один высокий DPI при слишком широком X-range этого не заменяет.
3. Экспортировать vector SVG/PDF и читаемый PNG preview. Практический минимум
   одного индивидуального raster panel — 1600×800 px; PDF/SVG ориентировать
   на ширину не менее 10 дюймов, шрифты при целевом отображении не мельче 12 pt.
   Это нижняя граница, а не гарантия: при большом N или длинном ITI добавлять
   страницы/панели, не уменьшать всё до неразборчивых миниатюр.
4. На zoom самый короткий значимый импульс/временная деталь должен занимать
   несколько различимых пикселей (ориентир не менее 6–8 по X). При достаточной
   дискретизации сохраняется различимость отдельных отсчётов; недостаточная
   исходная частота явно указывается и не исправляется интерполяцией.
5. Для сравнения паттернов одного model/condition использовать общие пределы
   и деления осей, одинаковые единицы и согласованный временной anchor. Если
   общий Y-range скрывает слабый ответ, добавлять явно помеченный detail view
   с собственным Y-scale. Исходные амплитуды сохраняются; независимая нормировка
   каждой кривой и скрытое изменение масштаба запрещены.
6. Входные импульсы накладываются на ту же временную ось ступенчатой кривой
   по фактическим stimulus samples; их отдельная Y-шкала/полоса и легенда не
   должны перекрывать soma trace. Показывать реальные onset и ширину. Если
   доступны лишь timestamps, использовать явно подписанные event markers,
   не выдавать восстановленную по предположению форму за измеренную.
7. Указывать абсолютное время и/или однозначное соответствие relative time
   фактическому onset, единицы X/Y, модель/паттерн/сому и reset policy. Физические
   V/mV применять только при установленном соответствии единицам модели;
   неизвестные единицы не переименовывать в mV. Threshold рисовать на soma axis
   только если он относится к этому же сигналу; иначе отражать отдельно.

NaN, missing ticks и censored хвост видны как разрывы/отсутствующая область,
а не заполненные нули или соединённая линия. Не обрезать отрицательные значения
и экстремумы. Если для больших traces нужен display downsampling, он должен
сохранять min/max, одиночные пики и входные фронты; исходные samples сохраняются
целиком. Метрики считаются по primary data, не по прореженному рисунку.

## Компоненты реализации

- Этап 3: расширить/проверить observation descriptors и экспорт raw traces:
  actual timestamps, все soma, все используемые stimulus channels, units,
  completeness, routing/model revision и границы событий. Источник текущего
  native контура — Core/TimeLearner/NativeRecognitionTrial.* в PulseLib;
  legacy analyzer/CSV адаптеры имеют явные версии и доступность данных.
- Этап 9: создать plotting.py и reports.py в корневом
  Scripts/StructTrain/TimeLearner; добавить настоящий report CLI с библиотечным
  API без import-time execution. Рендерить стандартным plotting backend на
  workers, сохранять версии инструментов и параметры масштаба. Исторические
  scripts не возвращать в Bin, PulseLib или Docs.
- Этап 11: report generator принимает ожидаемое множество испытаний из job spec
  и versioned analysis. Создаёт переносимый HTML/Markdown index, крупные overview,
  zoom views, vector exports, previews и manifest рисунков. Ссылки относительные;
  отчёт открывается из чистого checkout без CDN, сервера или внешних файлов.
- Этап 10: публиковать изображения, индексы, plot manifest и необходимые primary
  data через Git в Reports/StructTrain/TimeLearner. Для больших traces допустимо
  сжатие с checksum. Отсутствие графика любой ожидаемой trial/soma пары делает
  новый итоговый отчёт неполным. Diagnostic/partial отчёт публикуется с этим
  статусом; пустой placeholder не подтверждает полноту измерения.
- Этап 12: описать CLI, каналы/единицы, правила X/Y scaling, zoom и чтение отчёта;
  связать рисунки с критериями оценки, не подменяя визуализацией numeric validation.

## Проверки и приёмка

Использовать production renderer и реальные native observations на обоих workers.
Проверить Classic/Branch, N0/N1, все используемые soma, N>4, порядок/ITI,
reset/continuous, молчание, ранний ответ, late FP, отрицательный baseline,
широкий диапазон амплитуд, длинный хвост, missing/NaN и censored окно.
Небольшие явно synthetic traces служат отдельными controls сохранения одиночного
пика, узкого импульса и extrema при display downsampling; они не scientific runs.

Приёмка включает сверку ожидаемой coverage trial×soma/source с plot manifest,
соответствия plotted данных primary trace/model hash, правильности временного
совмещения и отсутствия скрытого clipping/normalization. Обязательно открыть
отрендеренные previews и vector/PDF при целевом масштабе: подписи и легенды
не перекрываются, кривые и входные импульсы различимы, zoom действительно
позволяет сравнивать форму, амплитуду и задержку. Один тест существования PNG
или зелёный numerical gate этой приёмки не заменяет.

Для исторических опытов строить графики там, где сохранились реальные traces.
Если их нет, отмечать это явно. Replay для восстановления визуализации является
отдельным прогоном с provenance; он не становится исходным августовским trace
и не отменяет визуально подтверждённые тогда 4/8–6/8.
