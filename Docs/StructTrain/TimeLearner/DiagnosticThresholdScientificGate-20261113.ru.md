# Проверка диагностического порога на фактическом LTZone сигнале

Цель — проверить настоящим spiking прогоном, может ли сохранённая остановленная stock Classic N4 модель обнаружить target без большинства ложных срабатываний. Незавершённый Train и certificate=null сохраняются; это явно same-matrix diagnostic, не независимый Test и не доказательство сходимости.

Предварительный просмотр восьми ранее принятых nonspiking проб дал target LTZone.Potential максимум0.013063091157563489; foils4/5 выше него (0.017207756229445453/0.01814808570096277), остальные пять ниже, ближайший0.013034654842755095. Эти значения ещё должны быть повторно связаны полным production audit с исходным manifest и файлами. Одного максимума Soma1 для этого вывода недостаточно.

Правило выбора до настоящего spiking прогона: по полным actual LTZone frames выбрать midpoint между минимальным target maximum и самым высоким foil maximum ниже него. Результат — только post-hoc nonspiking peak proxy. Все foils выше target сохраняются как прогнозируемые FP; NonSeparable не превращается в8/8. Затем сначала выполнить baseline100 на новом SDK, сравнить исходные native time/input/LT waveforms, и отдельно все8 паттернов при фиксированном предложенном пороге. Ничего не подбирать по исходу этих8 spiking trials. Фактические TP/FP/FN/TN получить общим строгим scorer, не требовать6/8 как условия прохождения инженерного теста.

Для этого вводится диагностический threshold candidate отдельного kind/state_kind. Обычные пути завершённого обучения/калибровки остаются строгими. В job diagnostic-evaluate schema2 появляется единственный обязательный фактор diagnostic_threshold; schema1 не меняется. Полный source_stopped и source_recognition, record единственной правки, реальные graph/storage/native XML и frozen before/after должны быть проверены. Любая другая правка физики, подмена source, неполные данные или неизвестная схема запрещают положительный итог.

Проверки: два native Classic/Branch N1 fixtures с Build/Init/Reset и реальными target/foil/partial trials; запрет ordinary import и цепочек кандидатов; Python sole-edit audit и rehashed corruption controls; совместимость старой diagnostic матрицы и обычных threshold candidates. Сборка и численные проверки только на серверах, в новом source/build/runtime. Полный научный отчёт должен включать все8 soma responses с actual inputs и читаемыми масштабами; primary сжатые, выбранные PNG в Git, полная gallery в M40 cache. Приёмка пока pending.
