# Потоковое хэширование крупного первичного файла

Первая попытка physical DATA replay fr1122 остановилась до запуска
Console. Journal пользовательской systemd-unit фиксирует OOM-kill
28.11.2026 в15:19:07UTC. Оставлены исходные owner, source-before,
управляющий Git и журнал; новой серии наблюдений эта попытка не дала.
После `--collect` unit отсутствует: значения Result=success и
ExecMainStatus=0 при LoadState=not-found не доказывают успех прежней unit.

Обнаружен конкретный путь чрезмерного расхода памяти:
`native_pipeline_worker._artifact_records` для execution schema1
вызывает `native_calibration_worker._record`, который считывал весь
файл через `read_bytes`. В данном источнике `model.json` занимает
1214410468 байт, больше лимита1ГиБ Python-контроллера. Для получения
размера и SHA256 разбор JSON или его одновременное хранение не нужен.

В `_record` заменено полное чтение последовательным чтением блоками
1МиБ. Формат path/bytes/sha256, проверка обычного файла и запрет symlink
сохранены. Физика, модель, критерий и наблюдения не изменяются.
Другие функции, действительно разбирающие полный JSON, этим изменением
не объявляются потоковыми; composite resolver требует отдельной проверки.

Приёмка предусматривает вычисление записи настоящего model.json
в ограниченном процессе, сравнение с исходным подписанным inventory,
существующие проверки calibration/pipeline и реальный physical DATA
replay восьми реакций. На момент фиксации исходника эта приёмка
ещё не выполнена. Повторный Train не требуется.

## Реальная проверка и исправление оценки тестового запуска

fr1135 подтвердил запись настоящего1214410468-байтового model.json
в отдельном процессе с kernel MemoryMax512МиБ. Path, размер и SHA256
совпали с исходным подписанным inventory. Это адресная положительная
проверка устранения чрезмерного расхода памяти при хэшировании.

Дополнительный вызов двух прежних unittest-модулей дал returncode0,
но stderr содержит `Ran 0 tests` и `skipped=3`: необходимые корпуса
Console не были заданы. Поле `existing_calibration_and_pipeline_regressions_passed`
в terminal fr1135 ошибочно; его положительный смысл отозван этим уточнением.
Исходный terminal сохраняется. Эти модули не считаются пройденными.
Для адресной проверки wire-контракта и отрицательных случаев добавлен
отдельный набор PrimaryArtifactRecordsTest без обязательного внешнего
корпуса. Его серверный запуск должен явно проверить testsRun=8,
skipped=0, errors=0, failures=0. Корпусные проверки остаются отдельным
требованием; новый набор их не подменяет.

fr1137 выполняет настоящий DATA replay в новом каталоге с теми же
восемью паттернами и порогом. До окончания полного сравнения реакций
его результат и перенос модели не объявляются принятыми. Физика
и исходные наблюдения fr1003 не меняются.
