# Явные DATA inputs для finalization-тестов

Проблема подтверждена [отклонённым SDK102 M40](ValidationPlans/M40SharedExportBoundarySdkA1-20261112/RESULT.ru.md):50 actual PASS, затем GTEST_SKIP из-за недоступного legacy env. Это ошибка test setup, не дефект обучения. Меняется только способ получения fixtures в Test_PulseLib_FinalizationBoundary.cpp: native_gate schema5 уже умеет захватывать/hash/stage8 DATA files, но C++ cases читали только внешние env roots, которые contained_runner намеренно не передаёт. Runner, scheduler, learner/PulseLib и математические условия не меняются.

Новый loader читает ../native-inputs относительно owned TIMELEARNER_EXECUTION_OUTPUT. При descriptor.json отсутствующая роль даёт явную ошибку; скрытый env fallback запрещён. Без staged descriptor прежний внешний test-fixture путь остаётся совместимым. Ничего не выполняется при import и не используется текущий рабочий каталог.

В [manifest](../../../Tests/Integration/Data/TimeLearnerFinalization/manifest.json) перечислены8 файлов: Classic/Branch × fixed source, cold configuration, evaluation design, calibration grid. Два fixed jobs — исходные bytes реального baseline-source; остальные6 — свежие декларации, не выдуманные исторические runs: cold jobs созданы существующим production make_job(legacy=True) из исходной configuration/profile, design/grid сохраняют original trials/thresholds и явно подписаны. Saved learned graph не устанавливается в cold learner; C++ case строит его штатно из cold configuration. Это N2 same-matrix lifecycle fixture, не научный N4/independent Test.

В Git хранится fixtures.tar.xz:34008bytes вместо12820879bytes raw. Перед native запуском требуются bounded restore ровно8 regular members, проверка всех bytes/SHA из manifest, затем неизменяемые data_inputs существующего native_data_checks schema1. Путь raw cache не является самостоятельным доказательством доступности: все8 inputs фиксируются перед/после каждого gate.

[Source review](FinalizationStagedDataAssertionReview-20261112.json) подтверждает сохранение всех202 GTest assertions в прежнем порядке и с прежними аргументами; все52 исходные IDs сохранены. Это source-проверка, не runtime PASS. Нужны свежая серверная сборка test loader и actual52 без skips с проверкой source/runtime/inputs и closure. Не требуется повторять50 незатронутых production cases только из-за изменения test-only чтения данных; при композиции результатов обязательно фиксировать оба SourceRoot и byte-identical production core/Console. Старый failed102 сохраняется failed.
