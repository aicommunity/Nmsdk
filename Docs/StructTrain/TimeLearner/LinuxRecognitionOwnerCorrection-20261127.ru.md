# Выбор владельца физической модели в Linux-распознавании

## Дефект и граница влияния

`linux_physical_recognition_sequence.job_for` всегда записывал
`owner_class=NNeuronTimeLearner`. Для исходной DATA Branch это не
соответствует её ModelSpec. Штатный `validate_job` обнаруживает такое
несоответствие и отклоняет новое задание до native-расчёта. Дефект
блокирует использование этого общего координатора для Branch;
он не доказывает причину FP в уже выполненных Branch-опытах, где
класс был явно задан правильно.

## Исправление

Перед формированием задания проверяется полный physical DATA-документ:
схема, digest, ModelSpec, фактический граф и связанные состояния.
Владелец выбирается по проверенному `configuration.model.branch`:
`NNeuronTimeLearner` либо `NNeuronTimeLearnerBranch`. Физический
документ, времена импульсов, окно, критерий оценки и бюджеты задания
не изменяются. Подмена топологии только в конфигурации с пересчитанным
digest не должна проходить эту проверку.

Повторная проверка DATA непосредственно перед вызовом `job_for` убрана:
проверка теперь выполняется самим генератором и не зависит от вызывающего
кода. Штатный production-validator перед расчётом сохраняется.

## Приёмка

Набор `test_actual_linux_DATA_owner` должен читать сохранённые настоящие
DATA обеих топологий с проверкой их `file_record`. Проверяются обе фазы
baseline/confirmation, неизменность графа, отказ исходного неверного
Branch payload, обратное несоответствие Classic/Branch и изменение
топологии без соответствующего изменения всего графа.

Отдельный native replay обеих моделей проверяет исполнение задания,
полные окна и сравнение с сохранёнными реакциями. Генерация и успешный
validator сами по себе не считаются новым научным результатом или
доказательством сходимости обучения.

На Elder завершены все четыре адресных проверки без отказов и пропусков.
Затем выполнены настоящие восемь предъявлений Classic и восемь Branch
при прежнем высоком пороге. Все 16 полных реакций, включая 4001 отсчёт
каждого окна, входные и выходные события, совпали с сохранёнными реакциями
при допуске сравнения 10⁻¹². Обе группы процессов закрыты, исходники
Python и SDK совпали до и после; сохранены реальные байты 28 загруженных
файлов каждого основного процесса. Нового Train и подбора порога не было.
