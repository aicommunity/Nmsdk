# Зафиксированные проверки остановленной Classic-модели с лимитом8 кандидатов

Постановка фиксируется до первого нативного импорта и получения счётчиков
распознавания этой модели. Обучение остановилось по бюджету; фактические
длины241;201;121;1 и числа синапсов13;11;9;1 подтверждены полным аудитом.
Отдельного итогового сертификата всех входов нет. [Исходная подготовка](ClassicCandidateCap8PhysicalPreparation-20261125.ru.md)
и [протокол единственной калибровки](ClassicCandidateCapRecognitionDesign-20261125.ru.md)
сохраняют это происхождение.

## Допуск

Дождаться преобразования DATA1 → DATA2, полной исходной восьмёрки,
предложения единственного порога и его реальной проверки, затем полного
повтора восьми реакций через новый импорт. Допуск требует закрытия точных
процессов, полного аудита наблюдений и совпадения всех сигналов и событий
при неизменных параметрах модели и пороге. Ошибка останавливает очередь;
автоматического повторного расчёта нет. Если допустимого кандидата порога
не оказалось, сохранить отрицательный результат и последующие проверки
распознавания не запускать. Работавший Train24 не прерывать.

Оба последующих исследования используют тот же Windows SDK
`891a75b39b2b020025aedc7e6158f89fd2f25ed2`, Python actor
`75110fa16336416f15adf7f2ea2cd8b17051b521` и полный граф из подтверждённого
повтора. Нового обучения, замены порога, изменения ёмкости, сопротивлений
или морфологии нет. Частота2000Гц, сброс перед каждой пробой, полное окно2с,
фактические входы и выходные события, все четыре сомы и решающий LT-сигнал.

## Сдвиг третьего импульса

Повторить направленный протокол прежних Classic и Branch:

```math
P_\delta=\{0;\ 0{,}08;\ \delta;\ 0{,}48\}\ \mathrm{с},\qquad
\delta\in\{0{,}12;0{,}16;0{,}20;0{,}24;0{,}28;0{,}32;0{,}36;0{,}40\}.
```

Времена отсчитываются от первого входа; его задержка от начала пробы10мс.
Только δ=0,24с является целью. Порядок возрастающий, цель на четвёртой
позиции. Все восемь проб оцениваются по прежнему критерию фактических
событий. Контрольную цель сравнить с полной исходной реакцией по4001
отсчёту, временной сетке и событиям; допуск сравнения10⁻¹².

Проверяется, различает ли новая модель изменения третьего момента после
поиска, затронувшего третий обучаемый путь. Предполагаемый результат не
задаётся. Это направленная диагностика, выбранная с учётом прежних ошибок,
а не независимая случайная выборка. Между моделями менялись несколько
параметров, поэтому причинного эффекта только длины третьего пути не выводить.
Нативный предел8ГиБ/3600с; полный производственный аудит обязателен.

## Новые отрицательные паттерны

Затем выполнить существующий протокол `frozen_new_foil_isi_grid_half_steps_v1`
через `prepared_physical_study`: каждый из трёх межимпульсных интервалов
80;160;240мс умножить независимо на1/2,1,3/2. Новые паттерны с hashes,
встречавшимися в исходной калибровочной восьмёрке, исключаются; точный
повтор цели сохраняется один раз. Число проб определяется декларацией,
а не подгоняется по ответам. Проверяются все новые отрицательные примеры
и совпадение контрольной цели. Порог по этим данным не подбирается.
Штатные пределы этого пути4ГиБ/7200с; общий Windows lock тот же.

Для каждого исследования отдельно сохранить TP/FP/FN/TN, времена выходов
относительно входов, полный граф, фактические первичные данные и крупные
временные рисунки всех паттернов с наложенными входными импульсами.
Внешние архивы хранить на M40, в Git — условия, численные итоги и проверенные
ссылки. Неполный набор либо повреждённый контроль не допускают положительного
вывода. Эти проверки не превращают исходный `budget_exhausted` в Exact.
