# Выполнение общей матрицы TimeLearner

## 1 Предмет проверки

Общая матрица включает обучение обычного нейрона и нейрона с общей
ветвью, нормализацию числом синапсов и сопротивлением, поддерживаемые
профили компонентов, торможение, частоту, число импульсов M, способы
управления, PostTune и оценку распознавания. Полное выполнение этой
матрицы остаётся требованием этапов4–8 и11 исходного плана.

Начинать готовые блоки можно до завершения всех исправлений. Неизвестный
эффект, ошибка постановки и ограничение поиска получают отдельные исходы.
Для принятия численного опыта не требуется заранее получить8/8 или
подтвердить совместное выполнение всех допусков обучения. Требуются
корректная постановка, полные измерения, неизменность объявленных условий
и проверяемое происхождение данных.

## 2 Начатый блок порядка, периода и сброса

В качестве двух самостоятельных исходных состояний взяты уже проверенные
Classic и Branch при M=4 и частоте2000Гц. У каждой модели фиксированы
структура, параметры и порог, подобранный на прежней восьмёрке. Исходные
результаты каждой модели —1TP/7TN/0FP. Исходное обучение остановлено по
ограничению времени вычисления; выполнение всех допусков не установлено.

Для каждой модели объявлены32 условия: восемь циклических перестановок
исходных паттернов, два периода предъявления и два способа сброса.
Цель занимает каждую из восьми позиций. Между перестановками выполняется
сброс. Внутри отдельного условия первая проба всегда начинается со сброса;
остальные семь либо тоже сбрасываются, либо сохраняют динамику нейрона.

При длинном периоде начало очередной пробы следует через2с. Короткий
период рассчитывается по действительным интервалам исходных паттернов:
максимальное время последнего импульса плюс0,2с, на сетке вычисления.
Все интервалы наблюдаются без разрывов. Последняя проба дополнительно
включает не менее2с после последнего фактического импульса. Поэтому
поздние события не теряются за границей последнего паттерна. Точные
длительности и моменты входов сохраняются для каждого условия.

## 3 Выполнение и критерии приёмки

Постановка каждого случая и fingerprint фиксируются до первого расчёта.
Используются существующие производственные функции объявления периодов,
сериализации условий, расчёта модели и аудита. Отдельный координатор
не интегрирует модель и не меняет порядок Rdk Calculate/Reset/Build.

Проверяются полный набор ID, восемь окон, все входные моменты и выходные
события, неизменность структуры/параметров/порога, отсутствие разрывов
наблюдения и завершающее тихое окно. Первые реакции в паре «со сбросом /
с сохранением динамики» должны совпадать при одинаковом начальном сбросе.
Остальные различия являются предметом опыта. При непрерывном потоке
событие не приписывается причинно одному паттерну только по номеру окна.

Ошибка случая сохраняется отдельно. Другие условия продолжаются после
подтверждения закрытия принадлежащих ему процессов. При неизвестном
состоянии процесса останавливается соответствующий исполнитель; другие
работники и готовые блоки не ждут этой диагностики. Не менять runtime
действующего задания и не повторять живые либо неизвестные процессы.

На.12 предусмотрены36ГиБ свободного места и не более12ГиБ новых выходов;
периодический контроль прекращает только своё задание перед нарушением
предела. Это сохраняет пользовательский минимум32ГиБ. Первичные данные
после завершения публикуются во внешний архив M40. В Git остаются
координаторы, постановки, документы и компактные проверенные ссылки.
Обязательны временные графики потенциалов всех участков сомы с реальными
входами, читаемые увеличения и последующее независимое чтение данных.

Windows fr1225: основной CLI-процесс PID24104 вернул0, список оставшихся
содержал другой PID22744; после очистки вся группа закрыта. Установлен
отказ вспомогательного запуска, но природа этого другого процесса пока
не определена. Гипотеза о повторном учёте самого основного PID отвергнута.
Не переименовывать старый отказ в успех и не ослаблять требования к
научному процессу. Linux Classic-блок уже отправлен отдельно; успешные
предыдущие переносы Windows и работающий Branch не изменялись.

## 4 Оставшиеся оси и ближайшие решения

|Историческое сравнение|Согласованные saved-state replay, повторное обучение и legacy/v2 A/B; исходные августовские4/8–6/8 сохраняются как результаты своего протокола|

Эти оси не заменять ещё одним набором перестановок. Существующие адресные
проверки надо связать с конкретными ячейками и условиями; старые333 cases
не являются автоматически текущей принятой матрицей. Отсутствующий или
недействующий параметр — ошибка постановки, а не научный отрицательный
результат. Общий этап принимается после проверки требуемого покрытия,
доступности первичных данных и соответствующей документации.
