# Объявленные DATA-входы native-проверок Windows

## Контракт и область изменения

Gate schema8 добавляет к Windows schema7 обязательные `data_inputs`.
Сохраняются полные имена GoogleTest, именованные каталоги результатов,
ограничения Job Object, worker lock, cooperative capture, проверка
загруженных библиотек и закрытие всех дочерних процессов. Схемы1–7
сохраняют прежнюю схему полей; в старую Windows-схему нельзя добавить
DATA как молча игнорируемое свойство.

Вход описан именем назначения, абсолютным путём, числом байтов и SHA256.
Число файлов1–8, один файл не более64МиБ, суммарно не более128МиБ.
Windows-имена устройств, конечные точки и пробелы в имени запрещены.
До запуска захватываются точные байты; внутри нового owned output
создаётся `native-inputs` с файлами и descriptor. Windows-путь размещения
проверяет каноничность и идентичность каталогов, создаёт файлы с `xb`,
проверяет записанные байты. POSIX размещение сохраняет `dir_fd`.
После native-процесса снова проверяются исходники, namespace, descriptor
и staged bytes; алиас или hardlink к исходнику не является собственной
копией. Эти проверки целостности отдельно от результата C++ и научного
verdict.

Windows validation profile version3 явно указывает Python gate source
и его полный commit. Код gate может быть новым при неизменном compiled
SDK/runtime: обе версии сохраняются отдельно, source gate проверяется
до и после. Сам worker должен принадлежать объявленному gate source.
Полные имена тестов version3 передаются в schema8 без подмены слешей.
Версии validation1/2 сохраняют прежние одиночные/partitioned пути и
отклоняют новые неиспользуемые DATA-поля.

## Три проверки реального сохранённого состояния

Нужен один исторический файл `classic-package6.qz`:323020 байт, SHA256
`d58ce13f3759a9e7c38f65c2cdb3059bb7ddccbd152d7e4144564c1efa36b234`.
Он уже хранится в общем внешнем object store M40. qCompress объявляет
4812359 несжатых байт с SHA256
`1c8d50628e7eea87c2bad230428526000802ec73e9627bd5d7d7f414bb69e05c`.
C++ читает его относительно `TIMELEARNER_EXECUTION_OUTPUT` из
`../native-inputs/classic-package6.qz`; SDK не получает незакоммиченный DATA.

Проверки: `NativeArchiveOwnership.MoveRetainsDecodedPrimaryStorageAndCopyIsIndependent`,
`NativeClassImageReplay.ActualMembraneCopyAndLoadStages`,
`NativeClassImageReplay.ClassicActualSavedModelAcrossNativeGraphRelease`.
Они исполняют скомпилированные Decode/Move/Copy/Load/Init/Reset и
сравнение фактической модели. Транспортные Python-проверки используют
те же архивные байты и отрицательные контроли повреждения и алиасов;
результат модели ими не заменяется.

## Приёмка

На28.11,13:23UTC новые Python-проверки прошли26/26 на Elder и
по26/26 на каждой Windows, без пропусков. В Windows проверены реальные
архивные байты, descriptor, повреждения, hardlink и junction. Native gate
на каждой машине выполнил все три объявленных случая: два прошли,
`ClassicActualSavedModelAcrossNativeGraphRelease` завершился отказом
проверки `transportEqual` во всех трёх циклах. При этом фактическая
physical identity совпала; source/staged bytes остались неизменными.
Отказы fr1040 (.14) и fr1041 (.8) сохраняются, приёмка3/3 не объявляется.

Причина несовпадения представления — исторический XML GCC и новый XML
MSVC записывают разные имена C++ типов, например `i`/`int`, `b`/`bool`.
Тест исправлен на существующий production `SamePortableModelArchive`,
который проверяет исходные digests, полный XML, типы/значения и граф,
сохраняя точное сравнение представлений как отдельную диагностику.
Это изменение теста переноса, а не физики либо правил обучения.
Новая диагностика schema3 содержит `archive_portable_equal`; старые
отрицательные результаты schema2 не переоцениваются. Изменение C++
ещё требует новой серверной сборки и реальных проверок, включая
существующие отрицательные контроли типов, значений и digests.

Runtime-проверка ещё не завершена. До
положительных исходов на реальных Windows не объявлять поддержку
принятой,3/3 завершёнными или научный worker допущенным. Старые18/18
и их независимые архивы сохраняют собственный проверенный охват.
