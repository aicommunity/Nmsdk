# Продолжение опыта Classic с лимитом24 кандидата

Этот документ уточняет выполнение уже объявленного общего
[протокола распознавания случаев8 и24](ClassicCandidateCapRecognitionDesign-20261125.ru.md)
до получения результата текущего Train24. Исходные условия, научные
бюджеты и работающий вычислитель не изменяются.

## Допуск и фактическое состояние

Использовать только исходный случай `classic-n0-length4-cap24-dp17`,
job SHA `632aa8a3f1823351e94dab93a3b6c1dbd4042079c4d5ba2a3601b87fde5b3713`,
отпечаток условий
`2792ed60890930bb0e46ca418cd62beeb81e442381b97c8c93a2bcc73960c01d`.
Ждать точного владельца `Classic-cap24-after-cap8-audit-dx29` и завершения
полного первичного аудита. Проверить закрытие всех дочерних процессов,
исходные job/conditions, execution и фактический пакет модели. Исход,
признак завершённой границы и revision считываются из проверенного
результата, а не задаются ожидаемыми значениями.

Остановленное обучение разрешает только явно диагностическую оценку
с сохранением причины остановки. Если получена завершённая модель,
исходный сертификат хранится в первичном пакете; DATA-проекция сама
по себе его не передаёт и нового сертификата не создаёт.

## Сохранение и выделение модели

Сохранить полные первичные файлы Train, подготовленные условия и квитанции
контроллера в новом архиве с перечнем всех членов и hashes. Исходные файлы
не удалять. Пакет перенести во внешнее хранилище M40 и независимо
восстановить до объявления результата опубликованным. В Git двоичные
данные не добавлять.

Полную физическую DATA1 получить существующим `physical_data_projection`
из фактически указанного execution-пакета с проверкой его исходных байтов.
Не извлекать неполный набор L/Ns/Rs из истории и не подставлять модель8.
Вспомогательный разбор выполняется отдельным ограниченным процессом:
16ГиБ,3600с, источник не более4ГиБ, DATA не более128МиБ. Это
операционные пределы подготовки, не дополнительные бюджеты обучения.

Чтобы не конкурировать за память с продолжающейся оценкой случая8,
ожидать закрытия его очереди научного продолжения
`Classic-cap8-frozen-third-and-grid-after-repeat-ea19` и всех её дочерних
расчётов. Корректный отрицательный научный результат случая8 не запрещает
исследовать случай24. Техническая ошибка сохраняется отдельно;
автоматического повтора Native Train нет.

## Распознавание

Применить тот же нативный импорт DATA1 → DATA2 с преобразованием identity,
без изменения сопротивлений и ёмкостей. Затем исходная восьмёрка при
пороге100, одно предложение порога правилом midpoint между максимумом
цели и наибольшим строго меньшим максимумом отвлекающего паттерна,
явный нативный кандидат DATA3 и реальная подтверждающая восьмёрка.
Более высокие отвлекающие максимумы не исключать из оценки.
Отсутствие кандидата является самостоятельным отрицательным исходом.

Сохраняются2000Гц, сброс перед каждой пробой, полное окно2с/4001 отсчёт,
все четыре сомы, решающий LT-потенциал, фактические входы и выходные
события. Порог выбирается по той же матрице; независимым Test этот опыт
не объявляется. Числа TP/FP/FN/TN и остатки обучения не задаются заранее.
Полный граф и исходная причина остановки сохраняются при оценке.

SDK Windows остаётся
`891a75b39b2b020025aedc7e6158f89fd2f25ed2`, actor Python
`75110fa16336416f15adf7f2ea2cd8b17051b521`; текущие источники и runtime
работающего опыта не обновляются. Реальные нативные операции используют
штатный общий Windows lock и предел8ГиБ/3600с. После оценки требуются
полные первичные данные и читаемые временные графики каждого паттерна
с наложенными фактическими входами, затем отдельный повтор переноса
и объявленные проверки устойчивости. Эта подготовка не завершает этап11.

## Зарегистрированные последовательности

После публикации постановки в коммите
`10a803116a307aef5316dbc4cbb80f8b73051362` зарегистрированы:

- `Classic-cap24-primary-DATA-and-conversion-after-cap8-ec3` — точное
  ожидание владельцев Train24/full audit и научного продолжения8, затем
  архивирование, DATA-проекция и явное нативное преобразование;
- `Classic-cap24-baseline-midgap-confirmation-ec5` — ожидание успешного
  преобразования и закрытия его владельца, проверка связи с собственным

  одно предложение порога и реальная подтверждающая восьмёрка.

проверок. Метки, hashes и полные условия восьми паттернов сохранены;
никакие значения ожидаемых счётчиков не добавлены. Самодостаточные
