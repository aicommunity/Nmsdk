# Разбор вмешательства в четвёртый импульс

Серия проверяет сохранённую Branch-модель с фиксированным порогом. Это
направленный контроль ранее обнаруженного раннего выхода, без нового
обучения и без подбора порога. Первые три импульса сохраняются; изменяется
только время четвёртого. Число импульсов M=4, частота 2000 Гц.

Для каждого режима сброса исходный случай T=960 тактов сравнивается с
T∈{560,640,720,800,880,1040,1120}. Перед исследуемым паттерном предъявляются
те же пять паттернов. Изменённый паттерн имеет метку foil, а исходная цель
предъявляется последней как положительный контроль. Нельзя сравнивать
только изолированные шестые пробы при разной предшествующей истории.

## Сравнение записанной реакции

Модуль `Scripts/StructTrain/TimeLearner/frozen_fourth_pulse_analysis.py`
сначала повторяет production-аудит обоих полных нативных запусков: модель,
объявленные задания, все восемь наблюдений и итоговые метрики. Проверяются
физические параметры, конфигурация, порог, управляющие настройки, dataset,
типизированный граф и определения всех storage-образов. Различие написания
платформенных типов в исходном XML не даёт права считать разные физические
модели одинаковыми. Эта аналитическая сверка не заменяет проверку импорта.

Пять предшествующих полных реакций сравниваются штатным компаратором.
Для исследуемой шестой пробы используется фактическое время начала входа,
а не предполагаемое расписание. Обозначим относительное время четвёртого
входного события в двух запусках через t₄ и t′₄. Сравниваемый интервал
заканчивается перед min(t₄,t′₄); отсчёт на самой границе исключён. Все
записанные отсчёты до этой границы, включая участок перед первым импульсом,
сравниваются по времени, потенциалу сомы, входу, выходу LT и решающему
потенциалу LT. Также сравниваются выходные события и записанная история
детекторов, включая доступную историю до начала окна. Абсолютный допуск
сравнения равен 10⁻¹². Это допуск равенства записей, а не допуск обучения.

Исходные наблюдения остаются полными. Подсчёт TP/FP/FN/TN выполняется
только по полным нативным окнам. Производный префикс не подменяет окно
классификатора. Результат сравнения не доказывает равенства незаписанной
внутренней динамики и не создаёт сертификат сходимости обучения.

## Проверка реализации

`tests/test_fourth_probe_prefix.py` использует реальные полные наблюдения
прежней матрицы r3, включая ранний выход при сохранении динамики. Шесть
проверок охватывают исходные реакции, перенос абсолютного времени,
незавершённое наблюдение, изменение сигнала до границы, изменение после
границы и несовпадающую политику сброса. Отдельно требуется прогнать полный
анализ фактических изменённых условий и сохранить его первичные привязки.
Все шесть проверок прошли на M40 без пропусков; независимо восстановлены
32 файла проверки. Исправлена именно тестовая трансляция часов: производные
относительные времена пересчитываются по новым абсолютным значениям
binary64. Строгость production-аудита не менялась.
[Проверенная запись](../../../Reports/StructTrain/TimeLearner/Progress-20261126/Branch-fourth-prefix-analysis6-accepted-fq18.json).
Полный анализ фактической пары T=560 также завершён для обоих режимов
сброса: пять предшествующих полных реакций и участок шестой до280 мс
совпали. [Результаты и ограничения](BranchFourthPulseResults-20261126.ru.md).
