# Общий ограниченный поиск: реализация и границы приёмки

Ветка `stage07/bounded-controller` реализует `BoundedTrainingSession` в PulseLib.
Контроллер возвращает Edit или Probe. Адаптер применяет разрешённое изменение
между пробами, читает эффективные параметры и fingerprint, затем подтверждает
действие. Контроллер не вызывает Build, Reset или Calculate и не обращается к Rdk.
Существующие конфигурации продолжают использовать legacy-контроллер. Подключение
через ControllerVersion=2, полные структурные адаптеры и научная матрица ещё нужны.

Порядок входов — Classic round robin и Branch reverse. Последний вход фиксирован;
его Ns, Rs и позиция не являются переменными поиска. Для Branch допустимы только
невозрастающие позиции, включая совпадения. В существующем native Branch
совпадающие позиции имеют один физический банк: эффективные Ns/Rs этих входов
должны совпадать. Независимая поправка, скрыто меняющая соседний вход или
фиксированный anchor, не предлагается. Поиск может сначала исследовать
разделение позиций; при фиксированных связанных позициях ограничение остаётся
явным unresolved. Legacy requested Ns (max по общему банку) нельзя подставлять
в readback как индивидуально реализованный Ns. Границы Rs индивидуальны; общего
пересечения не требуется. N0 перебирает целые Ns до 128 и длины, N1 — длины и
объявленную конечную сетку положительных Rs. Первые точки Rs: текущее значение,
границы, затем двоичное уточнение в логарифмической координате. Никакой глобальной
монотонности, физической недостижимости или полноты непрерывного поиска эта сетка
не доказывает. Прогноз задержки и адаптивное предложение кандидатов остаются
следующими улучшениями порядка исследования, а не заменой измерений.

Каждый кандидат получает свежую опорную пробу и пробу активного входа в одной
ревизии модели. Обе проходят тот же ValidateProbeMeasurement, что используется
при захвате references и в финальной проверке. Изменение модели инвалидирует
текущие измерения всех входов. История кандидатов содержит собственные epoch,
fingerprint, trial активного и опорного входов; история не становится свежим
доказательством после последующих изменений. Цель амплитуды — собственный raw
CapturedPerInput, допуски не заменяются шагом времени или процентом.

Ранжирование учитывает нарушение временного допуска, нарушение амплитудного,
суммарный нормированный остаток и стоимость изменения. При исчерпании локального
бюджета лучшая реально измеренная точка восстанавливается и измеряется заново.
После прохода всех входов FinalVerificationSession независимо проверяет всю
конечную модель. Только его Exact даёт Exact обучения. Остаток вне допуска после
объявленного числа проходов даёт SearchUnresolved; исчерпание общего бюджета —
BudgetExhausted; внешняя остановка не создаёт сертификат.

Адресные проверки включают немонотонные длины, Ns=128, quantization, несовместимые
между входами интервалы Rs, повреждение ранее настроенного входа, missing/ambiguous/
incomplete/nonfinite observation, mismatch эффективных параметров и внешнее
изменение fingerprint. Native integration проверяет реальную коррекцию одного Rs
с возвратом к исходному fingerprint на Classic/Branch при 2000/20000 Гц через
штатные scheduler/Reset/routing. В этом fixture длины фиксированы и sync tolerance
явно равен 0.2 с: он изолирует нормализацию Rs и не доказывает синхронизацию при
production default 0.02 с.
