приёмка полного плана. Оба процесса завершились с валидными экспортами и

## Classic: временной поиск сработал, совместная цель не достигнута

Все64 завершённых кандидата относятся к входу0. Исходная опорная амплитуда
этого входа0.026776213813404892. При L1 временной остаток около−0.480с.
После L2 и L3 измеренный прогноз предложил L241. Поэтому утверждение,
что алгоритм всё время последовательно перебирал только малые длины,
не соответствует полной траектории.

При L241/Rs86МОм временной остаток+0.0085с уже внутри допуска, амплитудный
−0.0242704983. При L241/Rs8.090169943749473МОм он равен+0.0080с и
−0.0032922324301704053 соответственно. По текущему лексикографическому Rank
эта измеренная точка лучше последующих несинхронных малых длин, но амплитуда
всё ещё вне допуска примерно в329 раз. Всего13 кандидатов удовлетворяют
времени, ни один — обеим целям одновременно.

После конечного локального Rs-turn алгоритм вернулся к общему перечислению
длин4…50. Наличие временно подходящей точки прекращает дальнейшее предложение
`ProposeMeasuredLength`; исследование соседней совместно допустимой геометрии
не имеет отдельного приоритета. Это вопрос стратегии совместного поиска,
а не основание считать отсутствующую амплитуду измеренной или ослаблять допуск.

Последний завершённый кандидат L50 имеет временной остаток−0.382с.
Экспортирован фактический граф L=[51,1,1,1]: прежний NextAction успел выдать
следующее изменение до проверки исчерпанного probe budget. Исправление
PulseLib `5dabcb1b0c627d1de52bf2dccec35f33cb755e92` запрещает это дополнительное
изменение. Само по себе оно оставит последнюю измеренную точку, **не** лучшую
историческую L241. Автоматический перенос сертификата на восстановленный
граф недопустим.

## Следующее сравнение и оставшиеся исправления

На том же неизменном native runtime объявлен новый matched cold job
`s10-finite-fair-input-cold-m40-a4`, controls
`8832b21f76a66c3e870feddce4255456653679af`. Меняется локальный cap128→16;
общий probe budget128, физика, начальная модель и допуски сохранены.
В идеальном пути48 локальных кандидатов расходуют96 anchor/input probes,
три свежих восстановления best —6, финальная проверка —4:106 search probes.
Ещё4 references имеют отдельный capture budget; суммарно110 логических групп.
Повторные sweeps и invalid recovery могут исчерпать остаток; это расчёт
объявленного бюджета, не гарантия завершения. Cap16 также может не позволить
повторить найденную на24-м кандидате точность входа2 Branch.

Дальнейшие обязательные изменения этапа7:

1. Явно определить terminal selection при глобальном исчерпании бюджета.
   Восстановление лучшего **полного** состояния активного поиска должно быть
   отдельным native edit на законной границе с readback Rs/Ns/L/C и учётом
   edit budget. При невозможности восстановления сохранить честную причину.
   Внешний stop не должен незаметно запускать новый поиск или модификацию.
2. Разделить восстановление измеренной точки и подтверждение её качества:
   история задаёт выбор, Exact требует свежей all-input проверки конкретной
   revision. Для общего кабеля Branch прежние локальные успехи инвалидируются.
3. Проверить ограниченное исследование соседних геометрий около временно
   подходящей точки после амплитудного miss. Прогноз определяет порядок,
   не заменяет измерение; физический Rs domain оценивается заново. Сравнить
   с прежним перечислением при одинаковом бюджете и исходной цели.
4. Оценить реальные terminal-модели на всех8 паттернах с полными окнами,
   отдельным объявленным подбором порога и неизменным learned-state hash.
   В отчёте сохранить soma/input временные графики читаемого масштаба.

Ни минимум Rs в одной геометрии, ни отсутствие локального bracket не
доказывают физическую недостижимость задачи. Общая амплитудная цель, изменение
C по умолчанию и уменьшение защитного Rs вне численной допустимости сюда
не включаются. Августовские4/8–6/8 этим разбором не пересматриваются.
