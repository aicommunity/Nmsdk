# Проверка распознавания состояний Classic после ограничения числа кандидатов

## Цель и независимые результаты

Для заранее объявленных случаев8 и24 кандидата отдельно исследуется
фактически сохранённая модель после остановки. Исходный результат Train
сохраняется. Случай8 уже завершён по бюджету и прошёл полный первичный
аудит; случай24 ещё работает. Возможное полезное распознавание не превращает
остановку поиска в сходимость. Параметры модели ради оценки не дообучаются.

## Перенос полной модели

1. Дождаться полного закрытия подготовки DATA и проверить её исходный
   пакет, revision, полный аудит и контрольные суммы.
2. Дождаться освобождения штатного общего вычислительного lock Windows.
   Для нынешнего случая8 дополнительно подтвердить закрытие точного
   нативного процесса случая24 и его дочерних групп. Текущий Train24
   не прерывать. Его последующий аудит может продолжаться при достаточной
   памяти: он не использует вычислительный lock модели.
3. Существующим `prepared_physical_export.prepare_conversion/run` выполнить
   нативный импорт и явное преобразование DATA1 → DATA2. Спецификация:
   `schema_version=1`, `mode=identity`, `resistance_bounds=[]`,
   `reference_amplitudes=[]`. Для identity не подставлять неиспользуемые
   амплитуды. PostTune, изменение ёмкостей и масштабирование Rs не вводить.
4. Проверить фактический граф, индивидуальные параметры, storage-образы,
   revision, неизменность исходного файла, завершение процесса и захват
   загруженных файлов. Сохранить исходный diagnostic boundary и отсутствие
   сертификата. Полная история остаётся в отдельном проверенном архиве.

Использовать прежний неизменный Windows SDK
`891a75b39b2b020025aedc7e6158f89fd2f25ed2`, PulseLib
`f2ea795b5a9c4166b1c6b5329bf61b0fff298b3f`; Python actor
`177cc36df02caf33af859852bc7ef4e14fb7ddea`. Нативному преобразованию
разрешены8ГиБ и3600с. Новые входы и выходы создаются в отдельных каталогах.
Повторный запуск при ошибке автоматически не выполнять.

## Последующая оценка

После успешного переноса применять один и тот же объявленный протокол
для обеих моделей. Он состоит из полной исходной восьмёрки при пороге100,
предложения одного порога существующим `physical_threshold_proposal`,
создания явного кандидата и реального повторного предъявления восьмёрки
с выбранным порогом. Перед каждой пробой сбрасывать физическую динамику;
записывать2с целиком, фактические входы, LT-потенциал, все сомные потенциалы
и выходные события. Частота2000Гц; при корректном контуре4001 отсчёт.

Порог предлагается между максимумом LT-отклика цели и наибольшим строго
меньшим максимумом отвлекающего паттерна. Более высокие отвлекающие пики
сохраняются как возможные FP. Отсутствие промежутка или непредставимый
порог — отдельный отрицательный исход. Числа из неспайкового предложения
не заменяют фактических TP/FP/FN/TN. Подбор относится к Historical
Same-Matrix, независимой калибровкой не объявляется.

После фиксации модели и порога отдельно проверять новые отрицательные
паттерны и направленный сдвиг третьего импульса. Их исходы не подменяют
исходную восьмёрку и не создают свежего сертификата обучения. Для всех
предъявлений сохранять читаемые временные графики с фактическими входами;
рисунки и полные первичные данные публиковать во внешнем архиве M40.
В Git сохранять постановку, численные результаты и проверенные ссылки.

Этот документ фиксирует протокол до нативного переноса случая8 и до
получения результата24. Он не является утверждением о выполненном Test.
