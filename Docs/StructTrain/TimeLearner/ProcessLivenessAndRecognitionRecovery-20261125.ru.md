# Восстановление очередей и проверка завершения процессов, 25.11.2026

## Linux: завершённый дочерний процесс

В сопоставимой паре M40 первый Native Train завершился в16:41 UTC.
Все четыре вычислительные группы закрылись. Родительский координатор
605404 продолжал ожидать supervisor677378 с тем же start_ticks466693117,
поскольку тот сохранялся в /proc как zombie (Z). Совпадение PID, времени
запуска, boot ID и UID подтверждало принадлежность, но не жизнеспособность.

В production owned_native_job разделены идентичность и состояние. Оба
поля считываются из одной записи stat. Состояния Z/X/x не считаются живым
исполнением. Проверка не вызывает waitpid за чужого родителя, не считает
ненулевой выход успехом и не заменяет проверку закрытия всей группы.

Root исправления:3e5cb887913959e4a1484452126f4e86ce0133f1. На M40 выполнены
две адресные проверки, без пропусков. Одна создаёт настоящий дочерний процесс,
сохраняет его непрочитанным после выхода23, проверяет неизменную идентичность,
отсутствие liveness и сохранность кода выхода. Вторая сохраняет прежнее
отклонение ошибочной либо неполной идентичности. Полный код974 Scripts-файлов
проверен по Git-проекции. Каталог внешнего доказательства:
experiments/2026-11-25/M40-actual-process-liveness-ej24.json,
SHA256 b078c3de646e30c24102966026d6b19257cc069946685950cf062ef673002c40.

Перед остановкой только старого метадатного координатора повторно проверены
все вычислительные группы и отсутствие запуска второго случая. Исходный
Train не повторялся. Новый координатор
classic-traversal-same-runtime-pair-recovered-m40-ej25 продолжает с полного
первичного аудита. Существующие объявления обоих случаев, исходное состояние,
SDK и runtime сохраняются. Наблюдение использует исправленный production
контракт; последующий Native запускается прежним строго закреплённым
инструментом из его отдельного дерева. Запуск и завершение аудита не
переименовываются в завершённое обучение или классификацию.

## Windows: передача фактически подписанного задания

Базовая восьмёрка cap8 завершилась:8×4001 отсчётов, Native wall2574,56с.
Последующий вызов предложения порога получил собранный вызывающим скриптом
job без sha256, хотя production prepared_evaluation уже сохранил полное
подписанное задание. Аудитор правильно отклонил такой payload до подбора.

Восстановление читает сохранённый envelope, проверяет его связь с фактической
DATA-моделью, полный digest задания, закрытие процесса и все наблюдения.
Базовая восьмёрка не повторяется. Первое восстановление ej13 прошло этот
аудит, но остановилось до Native на проверке расположения windows_process.py:
новое дерево инструментов использовало то же содержимое backend по другому
абсолютному пути. Проверка целостности не отключалась.

Для ej22 создан отдельный runtime manifest с новым путём того же backend.
Размер и SHA256 файла полностью совпадают; production runtime_content_identity
и fingerprint остались прежними. Исходный manifest и работающие ранее
задания не менялись. Fingerprint:
77fa25c0e052822dea3e3093d304bcd7cf19343308248441af3029ba86da0791.
Порог0,026339412714535534 применён нативно; идёт подтверждающая восьмёрка.
Прогноз TP1/FP1/TN6 пока не является фактическим результатом.

Старые зависимые очереди закрылись с ошибками предшественника; их терминалы
не подменялись успешными. Требуется новое объявленное продолжение повторов,
сдвигов и сетки, а затем cap24. При подготовке учесть найденный в старом
worker ea19 неверный аргумент summarize_trial_timing: необходим evaluation.json,
а не execution job. До этого участка ea19 не дошёл, новых проб не выполнял.

## Визуальный анализ из архива

physical_data_visual_report поддерживает явный archived-source: полный
production-аудит всех байтов и записей процесса остаётся обязательным,
повторное наблюдение ядра исходного сервера не утверждается. Этот режим
предназначен для построения кэша рисунков, не разрешает Native-выполнение
и не выдаёт сертификата обучения.

compact-views сохраняет все исходные отсчёты полного окна и отдельные
увеличения измеренных максимумов, исключая только сплошную плиточную
раскладку каждого100-тактового интервала. Обычный режим прежний. Временное
увеличение вершины теперь сохраняется и тогда, когда более узкий Y-диапазон
не нужен. Это особенно существенно возле спайка с отрицательной перезарядкой.
Подсчёт ответов выполняется по первичным событиям, независимо от рисунков.

Проверка на реальном восстановленном q3-комплекте охватывает8 полных проб,
32 соматических канала и8 записей решающего потенциала. Изображения хранятся
во внешнем кэше; готовые DOCX ради этих изменений не регенерировались.
