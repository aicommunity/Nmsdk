# Composite core: исправление полноты типа при компиляции

08.11.2026. Исходная попытка `s07-composite-core-m40-a1` на M40 использовала
Root `27ba5aa2906d5e5a1ecc081044fffb8dc82e6c38` и PulseLib
`269164d2a2339908a8667e859a04a8e81da50c3c`. Она остановилась при сборке;
ни один из ожидаемых 143 тестов не запускался.

В `NativeCompositeTrainingAttempt.cpp` использован `UEPtr<NPulseNeuron>`
в вызовах, принимающих `UEPtr<UContainer>`. Заголовки learner содержат лишь
forward declaration нейрона. Без полного определения компилятор не может
проверить наследование и выполнить преобразование; последующие ошибки
`QJsonObject` и callback expressions требуют повторной проверки после
исправления первичной ошибки.

PulseLib `dafbb2133f989963cf8e536b91d73d61a03e4ec3` добавляет явный include
`NPulseNeuron.h` в этот translation unit. Состояния, порядок вычислений,
измерения, критерии и допуски не меняются. Локальных C++ сборок и численных
проверок не выполнялось. Исправление ещё не принято runtime-проверкой.

Для следующей серверной попытки обязательны: корневая CMake-сборка, сверка
реального `--gtest_list_tests`, 74 прежних bounded-теста, 23 Final/Clock и
46 новых native composite случаев. Старый ошибочный перечень «71+23»
считал тело макроса тестом и пропускал четыре его развёртки; его отрицательная
попытка сохраняется отдельно и не считается успешной регрессией.

Отдельное исправление отмены `NativeProbe` из prepared callback и дальнейшая
интеграция service/codecs/CLI не входят в эту правку. Успешная компиляция
не заменяет проверку 143 тестов и не доказывает научную разделимость.
