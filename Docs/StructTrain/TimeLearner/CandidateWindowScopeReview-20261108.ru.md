# Область действия объявленного окна при поиске структуры

Статус 08.11.2026: подтверждённое ограничение API; влияние на реальное обучение
ещё требует адресного runtime-контроля. Это не переоценка ранее сохранённых
valid/ambiguous наблюдений и не доказательство физической недостижимости.

В PulseLib `e183bee14be285862663c094b0b36b3f0dc15747`,
`NativeCompositeTrainingAttempt::StartMeasurement` берёт окно из неизменяемого
`protocol.compositeMeasurement.inputWindows[inputIndex]`. В service
`661c3d932b7084348e071154e2c1541007fcf17e` валидация требует равенства окон
плана и этого контракта; `QueueComposite` не передаёт отдельное предложение
окна кандидата. Следовательно, текущий путь использует фиксированное окно
каждого входа на протяжении всей попытки.

Это допустимый явно объявленный протокол, но его fixtures с фиксированными L
не доказывают поддержку поиска, где максимум закреплённого импульса смещается
за начальное узкое окно. Расширение окна на всю пачку тоже не является общим
решением: более высокий максимум другого импульса не заменяет закреплённый.
Необходимо проверить это поведение до полной приёмки этапа 7.

Цель остаётся прежней: CapturedPerInput для максимума закреплённого импульса.
Планировщик может предлагать окно по задержке/истории измерений, но прогноз
не подтверждает наличие или принадлежность пика. Окно объявляется до пробы
и остаётся неизменным для всех full/omit/repeat контролей конкретной группы.
После получения данных перенос окна или замена ими reference запрещены.

Следующая проверка должна включать:

1. Реальную модель с изменением L, у которой измеренный закреплённый максимум
   выходит за начальное окно; полный waveform и реальные входные события.
2. Отдельную свежую группу с заранее объявленным окном кандидата; те же
   immutable reference targets и проверка необходимости закреплённого импульса.
3. Отказ при изменении окна внутри группы или задним числом; сохранение
   ambiguous для настоящего слияния пиков и запрет максимума чужого импульса.
4. Fresh all-input final verification с фактическими окнами, revision и
   model epoch каждого измерения, без вывода Exact по предсказанию.

Решение требует явно отделить исходные reference windows/target family от
объявления конкретного измерения. Если нужен новый policy/schema, он должен
быть версионирован, включён в condition identity и одинаково проверяться
native codec и независимым reader. Уже сохранённые schemas 4/6 сохраняют
свой смысл; их нельзя молча переинтерпретировать как адаптивное окно.
Fixed-window compatibility остаётся воспроизводимой; её границы должны быть
видны в конфигурации, отчёте и сертификате.

Реализация и адресные проверки переданы в текущую работу по общему контроллеру.
Этот документ фиксирует открытый пункт, а не объявляет его исправленным.

## Проверенный следующий подэтап

Отдельный pure module подготовлен на Root
`df06a7014f7b62a09b394d4aea31ea96c831feeb` / Pulse
`e7a38933051706f8f2fa76fe322c3fe7401ee52a`.
На M40 обычная и ASan-сборки прошли по 40/40 случаев. Проверяется один
детерминированный frame interval по immutable arithmetic seed и actual-parameter
facts: границы, переполнения, размеры, declared grid/source/reset policy,
учёт изменений L/Ns/Rs/C. Прогноз не возвращает измеренную амплитуду/время.

Evidence `72da089b46d64aaa9bd8a4abdc6acfddf0c8bebb` опубликован;
[независимая проверка](CandidateWindowPure40M40A1Verification.json)
сверила 139 членов архива, source Git blobs, compiled inventory/JUnit,
загруженные библиотеки и закрытие трёх групп. Это standalone target projection,
а не полный root CMake/SDK gate; проверка утечек не заявляется.

Arithmetic result является только данными. Модуль не предоставляет способа
создать trusted reference seed из raw facts и ещё не подключён к native Train.
Следующий bridge должен связать окно с полным reference capture, реальным
owner/input map, source/model epoch и заранее объявленной группой проб.
Фиксированное окно текущего service пока остаётся открытым ограничением.

## Подготовленный native bridge: ещё без runtime-приёмки

Source-кандидат Root `c1b3ad79afd8559eac01561412928be714367085` / Pulse
`60fd65e4ccf956175d7c2ae661faba9547364a36` добавляет отдельный protocol5
cold constructor, staged actual references всех входов и закрытый complete-set
factory. P0/C0 берутся из исходного эффективного графа. Перед выдачей complete
set повторно проверяются реальные live tokens, owner lifecycle и принадлежность
узлов; физический Reset отдельной пробы разрешён, подмена графа — нет.

Окно кандидата вычисляется из исходного reference set и actual readback,
проходит strict encode/decode и independent proposal replay, затем фиксируется
перед первой пробой. После закрытия используется реальная геометрия full/omit/
repeat данных. Прогноз не выдаёт амплитуду или сертификат. Невидимый direct-value
ABA вне поддерживаемого пути edits не объявляется обнаруживаемым.

В исходниках подготовлены16 новых native controls:2000/20000Гц, growth,
C0Off/bound, partial, остановка, Reset/Default и восстановление того же model
hash после перестройки графа. Они ещё не выполнялись на сервере. Root source
review этого подэтапа не заменяет их исполнения.

Остаются обязательными archive2/portable reference replay, привязка нового
primary-byte budget к proof2 и соответствие duplicated policy fields,
интеграция typed bounded/final consumers, service/CLI и реальное обучение.
Старые protocol4 consumers сохраняются; admission нового пути поиска и
сертификатов пока явно запрещён. Новые source-only schemas не переоценивают
исторические данные и не меняют принятый SDK автоматически.
