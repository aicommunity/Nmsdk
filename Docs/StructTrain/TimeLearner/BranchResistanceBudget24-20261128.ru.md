## Следующая научная проверка

После положительного полного аудита проверить сохранённую модель на
исходных восьми паттернах: полные двухсекундные окна, reset-per-trial,
baseline с исходным порогом100, затем один объявленный Same-Matrix
кандидат порога и настоящий подтверждающий Test. Если нет разрешимого
промежутка для целевого ответа, сохранить отрицательный результат.
Не подбирать модель по отвлекающим, не менять обученные параметры,
не выдавать baseline или калибровку за завершившийся Train.

Построить временные графики сомы и LT с реальными входными импульсами
для всех паттернов обеих фаз, включая увеличения без прореживания.
Полные модели, пробы и история должны попасть во внешний архив M40
с независимым чтением; этот документ не заменяет первичный комплект.

Подготовленный диагностический worker теперь также разрешает существующий
корень .4 `/home/user/Nmsdk-experiments`, его собственный
`resource-reservations.sqlite3` и только `readbacks` для новых входов и
выходов. Прежние два корня и остальные проверки сохранены. Второй
независимый ledger для обхода действующих reservations не создаётся.
Приёмка этой возможности — настоящий диагностический запуск на .4;
изменение строки допуска само по себе не считается runtime-проверкой.

## Разбор завершённой истории

Production CLI `analyze --format native-search-history` fr1086 выполнил
полный повторный аудит исходного комплекта. Зарегистрированы46 измерений
кандидатов,93 логические пробы и45 правок. Эти счётчики имеют разные
определения; число файлов отдельных волн не заменяет ни один из них.
Совместного выполнения временного и амплитудного допусков в записанных
кандидатах нет.

Число25 включает всю записанную последовательность измерений пути2,
в том числе повторное измерение выбранного состояния; оно не является
новым значением лимита exploration-кандидатов24. Последняя такая запись
имеет L121, Rs8,090169943749473МОм, временную ошибку−0,5мс и амплитудную
ошибку+0,004187080333055593 условной единицы модели. Это измеренный
остаток выбранной точки, а не свежая проверка конечного графа после
последующих правок.

Уменьшенное Rs действительно измерялось на длинной геометрии:
для пути2 —при L118–121, для пути1 —при L199–202. Таким образом,
ограничение8 не следует считать проверкой того же поиска, что24.
При этом соответствие двум допускам не появилось; простое наличие
подстройки Rs не доказывает её завершение.

Для пути2 первый временно допустимый кандидат оказался16-м в его
записанной последовательности: L121, Rs86МОм. Следующее измерение
сохранило эти параметры активного пути, но сдвинуло две более дальние
точки с121 на122, отделив общую точку подключения. Затем измерялось
Rs8,09МОм. Для пути1 первая временно допустимая точка была8-й:
общие L202/202; далее первая точка сдвинута на203, после чего измерены
Rs8,09;26,38;14,61МОм при L202. Различие полного вектора структуры
сохраняется в истории: одинаковые L/Rs активного пути не означают
одинаковое состояние всего нейрона.

Причина остановки — `native_training_time_budget_exhausted`.
Задано10000с модельного времени и32400с вычисления. Получено
1038,8055с модельного времени; проверка `NativeTrainingService::CheckBudget`
останавливает по достижении одного из этих двух пределов. Следовательно,
в данном запуске ограничило время вычисления, а не160 логических проб
или10000 модельных секунд. Время завершения записи входит в сообщённые
32922,60с процесса. До самостоятельного измерения пути0 поиск не дошёл;
его длина201 возникла при допустимом росте общей структуры и не считается
результатом отдельной настройки этого пути.

Проверен также исходник фактического SDK .4: PulseLib
`5f36aebb9bfdef747c04319f3ab065be199de67c`, blob
`Core/TimeLearner/NativeTrainingService.cpp` —
`d5d915884db520e6419ce59a50431510179e7d92`.
Он совпадает с проверенным файлом текущего дерева; вывод о двух
ограничениях времени не перенесён с другой реализации по одному имени метода.

Измерения указывают на две задачи следующего сравнения алгоритмов:
распределение вычислительного времени между путями и выделение локальной
квоты Rs после отделения общей точки подключения. Нельзя переносить
остатки между различными полными геометриями либо подтверждать
недостающий пик прогнозом. Изменение правил поиска требует отдельного
A/B контроля с теми же CapturedPerInput и допусками; увеличение лимита24
само по себе не является исправлением алгоритма.
