# Ожидание подтверждения состава runtime после расчёта

Подтверждающий Test Elder `s11-classic-count-recognition-elder-a1-threshold`
сохранил все8 наблюдений, но завершился кодом2 с
`native_runtime_capture_not_acknowledged`. Исходный отрицательный статус,
входные данные, модель и файлы захвата сохранены. Новый Train не запускался.

В фактических файлах ready и ack одинаковые PID627030 и start_ticks489986731.
Разность времён изменения файлов —11,522150431с. Сам нативный код ожидал
только10с. Поэтому правильное, но позднее подтверждение не могло быть принято.
Захват loaded-files и его надёжная запись требуют дискового ввода-вывода;
точная доля времени каждой операции здесь не измерена. Различий идентичности
процесса или повреждения JSON эти файлы не показывают.

В `App/NeuroModelerConsole/RuntimeCapture.h` операционный период ожидания
увеличен до120с. Расчёт модели к этому моменту уже закончен; scheduler,
амплитудные и временные допуски обучения не меняются. Внешний runner
по-прежнему ограничивает полное время попытки. Отсутствующее или относящееся
к другому процессу подтверждение не становится успешным.

Отдельный target `Test_TimeLearner_RuntimeCapture` включает настоящий
производственный header и проверяет задержку11с, чужую идентичность и
ограниченное отсутствие ack. Параметр меньшего ожидания нужен для адресной
проверки отрицательного исхода; CLI и поля компонентов не менялись.
Серверная сборка и результаты этих проверок пока ожидаются. Уже работающие
runtime Windows и M40 не изменяются. Исходный ошибочный Test не переименован
в успешный после исправления кода.
