# Внешний архив экспериментов TimeLearner

Актуальная политика по указанию пользователя от 14.11.2026 заменяет правило
30.10 о хранении compressed primary в Git. Архивирование и очистка истории —
техническое условие продолжения исходного плана; они не завершают рефакторинг
и не изменяют научную интерпретацию уже полученных результатов.

## Авторитетное хранилище

На M40 используется отдельный каталог
`/media/user/Data/Nmsdk-StructTrainExpArchive`. Его нельзя смешивать с
`NmsdkStructTrainArchive`, `TLAgent-*` и `TimeLearnerRefactor`: последние могут
содержать исторические оригиналы и рабочие кэши, но не являются новым архивом.
Идентичность нового хранилища задаёт `archive.root.json`.

По дополнительному указанию пользователя настроен общий доступ Samba:
`//10.245.1.17/Nmsdk-StructTrainExpArchive` (Windows UNC:
`\\10.245.1.17\Nmsdk-StructTrainExpArchive`). На Elder тот же каталог смонтирован
как `/mnt/nmsdk-structtrain-archive`; настроено автоматическое подключение.
Сервер принимает авторизованные соединения с указанных машин, требует SMB3,
подпись и шифрование. Учётные данные не входят в Git, manifests или отчёты.
Windows-сеанс перед обращением к архиву устанавливает соединение с учётной
записью M40; на `.8` используется полное имя `M40\user`. Доступ из одного сеанса
не считается доказательством доступности из другого: preflight каждого worker
проверяет marker и возможность чтения/записи. На Elder используется
`cache=none,actimeo=0,closetimeo=0,noserverino`: при прежнем кэшировании
зафиксирована ошибка немедленного чтения после hard-link publication; с новыми
параметрами четыре последовательных production store/dedup/resolve/materialize
прошли без ошибки. Те же операции проверены на обеих Windows-машинах и локально. Пароли передаются защищённым
каналом отдельно от job spec.

Эксперимент пишет рабочие данные в локальный runtime/cache. После закрытия
наблюдения пакет сохраняется в общем архиве и проверяется. Архивирование и
сетевая передача не включаются в model time и не подменяют лимит самого Train.
Временные кэши удаляются только после проверки соответствующих архивных данных.

В архиве сохраняются точные байты первичных данных, моделей, журналов и полных
визуальных отчётов. Сжатые primary bundles не заменяются повторно рассчитанными
данными. Их `bundle.json`, logical member hashes, исходные commits, runtime
identity и критерии сохраняются. Архивирование не придаёт результату новый
уровень доказательности. Архив на одном диске не является независимой резервной
копией; наличие дополнительной копии указывается отдельно и не предполагается.

`objects/sha256/AA/SHA256` содержит неизменяемые объекты. Одинаковые байты
хранятся один раз. `history-maintenance/20261114/` — закрытый служебный раздел
для инвентаризаций, резервных копий и таблиц замены истории. Старые Git bundles
там предназначены только для восстановления, а не для push/fetch в origin.

В Git остаются код, исходные настройки, небольшие описания моделей и метрики,
читаемые отчёты, inventories и ссылки `*.archive.json`. Сжатые архивы, бинарные
модели, Git packs/bundles и крупные результаты (больше 1 MiB на файл) хранятся
внешне. Это предел публикации отдельного файла, а не обещание размера всего
репозитория. Отдельные небольшие выбранные рисунки допустимы; полные галереи
хранятся в архиве, а рабочие развёрнутые галереи являются кэшем.

## Запись и восстановление

На M40 перед публикацией ссылок:

```text
python3 -m Scripts.StructTrain.TimeLearner.external_archive store PRIMARY_FILE
```

Команда выводит JSON с kind/schema, размером, SHA256, авторитетным root и
относительным object path. Сохранить этот JSON рядом с описанием результата,
например `primary.tar.xz.archive.json`. Она копирует источник, сверяет источник
и конечный объект, не удаляет оригинал и не заменяет существующий объект.
Коллизия с повреждённым содержимым завершается ошибкой.

Для нового завершённого пакета предусмотрена подготовка публикации:

```text
python3 -m Scripts.StructTrain.TimeLearner.external_archive prepare-publication CLOSED_PACKAGE NEW_REPORT_DIRECTORY
```

Каждый исходный файл сохраняется и проверяется в архиве. В `NEW_REPORT_DIRECTORY`
создаётся небольшой `package/` с исходными metadata/checksums и ссылками вместо
тяжёлых данных; отдельный наружный `SHA256SUMS.json` описывает физические файлы,
которые разрешено передать publisher. Исходный checksum manifest пакета не
пересчитывается под ссылки. Исторический reader восстанавливает логическое
пространство имён и проверяет оригинальные bytes/hash. Команда не меняет индекс
Git и не выполняет push. Для native tools, которым нужен настоящий filename:

```text
python3 -m Scripts.StructTrain.TimeLearner.external_archive materialize REFERENCE_JSON LOCAL_CACHE_FILE
```

Существующий иной файл не перезаписывается. Развёрнутые данные остаются кэшем;
их повторное добавление в историю блокируется проверкой всей предлагаемой
истории, включая payload, добавленный и удалённый до её конечного HEAD.

```text
python3 -m Scripts.StructTrain.TimeLearner.external_archive verify REFERENCE_JSON
python3 -m Scripts.StructTrain.TimeLearner.portable_primary BUNDLE_JSON OUTPUT_DIRECTORY
```

Native bundle reader использует локальный оригинал либо проверенную ссылку
`primary.tar.xz.archive.json`. При доступе к другой смонтированной копии архива
задаётся `NMSDK_STRUCTTRAIN_ARCHIVE_ROOT`; marker остаётся обязательным. Размер и
SHA256 проверяются до распаковки. Отсутствующий архив — явная ошибка, а не
основание для неполного анализа или восстановления из шаблонной модели.

На машинах без смонтированного архива получать нужные объекты отдельно по
защищённому соединению и проверять их SHA256. Большие файлы не коммитить для
пересылки между workers. Код и настройки по-прежнему синхронизируются через Git.
Выбор и подключение такого транспорта не выполняются скрыто при import.

Для `closed_python_validation stage` задаётся отдельный новый каталог публикации:

```text
python3 -m Scripts.StructTrain.TimeLearner.closed_python_validation stage CLOSED_CACHE --repository REPOSITORY --publication-output REPOSITORY/Reports/StructTrain/TimeLearner/RUN
```

Исходный закрытый пакет может находиться вне Git. Перед staging сохраняются
только четыре объявленных артефакта и их исходный inventory; промежуточные
файлы коллектора не публикуются. Исходные receipt/hash не меняются. В Git
передаются внешний inventory и metadata/ссылки подготовленного каталога.
Publisher проверяет доступность и SHA256 объектов до любых дочерних push.

## Регрессионные fixtures

Python fixtures читают исходные проверенные байты через `locate`; исходные
source/member hashes сохраняются. Для native LoadHistory-тестов, которым нужен
файл в source tree, перед запуском явно восстановить два кэша:

```text
python3 -m Scripts.StructTrain.TimeLearner.external_archive materialize Tests/Integration/Data/NativeWindowPackage6Classic/learned-state.json.qz.archive.json Tests/Integration/Data/NativeWindowPackage6Classic/learned-state.json.qz
python3 -m Scripts.StructTrain.TimeLearner.external_archive materialize Tests/Integration/Data/NativeWindowPackage6BranchC0/learned-state.json.qz.archive.json Tests/Integration/Data/NativeWindowPackage6BranchC0/learned-state.json.qz
```

Команды выполняются после замены истории, когда sidecars уже существуют.
Оригинальные файлы входят в ignore как кэши. Отсутствие архива означает отказ
подготовки теста; пропуск теста или подстановка другого learned state запрещены.
Приватные aliases веток/stash хранятся в common Git metadata, в
`info/structtrain-root-revision-aliases.json`; linked worktrees используют
одну таблицу. Они не публикуются вместе с публичной картой commits.

## Обязательная последовательность замены истории

1. Инвентаризировать origin, локальную машину, Elder `.11`, M40 `.17`, Windows
   `.8` и ранее использованную Windows `.14`. Проверить все common Git stores,
   private branches, remote refs, detached worktree HEADs, stash и reflogs;
   исправить пробелы сканирования неинициализированных submodule stores.
2. Сохранить проверенные резервные копии всех уникальных историй и рабочих
   состояний. На Elder мало свободного места: крупные backups хранить на Data M40.
3. Подготовить новую историю отдельно. Для каждого исключаемого blob сохранить
   точные байты в новом архиве и таблицу repository/old commit/path/blob/size/hash.
   Проверить destination, доступность и полноту до изменения origin.
4. Сравнить деревья и topology: все не исключённые исходники, настройки, modes,
   авторы, messages и порядок merge parents сохраняются. При изменении истории
   дочернего repo сначала заменить её и проверить соответствующие root gitlinks.
   Private commits не публиковать в публичных ветках.
5. Перед переключением остановить автоматические Git fetch/write и проверить
   отсутствие использующих дерево экспериментов. Origin заменить атомарно с
   проверкой ожидаемых старых refs. Изменения веток за время подготовки требуют
   пересчёта, а не безусловного force push поверх чужой работы.
6. Перевести все рабочие копии, индексы, detached HEADs, stash и reflogs на новую
   историю, сохраняя staged/unstaged files. Не применять reset --hard. Удалить
   активные ссылки на прежнюю историю; офлайн backups оставить в архиве.
7. Проверить fresh recursive checkout, работу readers/publication guards,
   целостность refs и отсутствие исключённых blobs во всех live histories.
   Только затем удалить ненужные объекты Git и объявить миграцию завершённой.

Не подменять исторические научные SHA новыми в первичных данных. Отдельная
таблица aliases связывает исходные SHA с новой историей и учитывает обе очистки.
Старые отчёты остаются историческими; новые ссылки ведут к архивным references.

## Текущий статус

14.11.2026: сохранены и проверены 68 532 выбранных уникальных объекта полного
объединения публичных и локальных историй (5 230 064 519 исходных bytes,
104 705 исторических путей). Архивный manifest SHA256:
`a0ecdad93655a51071b07fe0c46c6c9f37328a892521800d12f3e428e5c2e867`.
Исходный публичный снимок и полное объединение имеют проверенные offline
bundles; metadata/index/stash/reflogs и уникальные физические объекты сохранены
со всех пяти машин. В read-only проверке jump host найдены 90 Git markers,
копий корневого Nmsdk среди них не обнаружено.

Первый публичный черновик отдельно прошёл проекцию всех 8 295 commits /
1 250 refs. Полный черновик построен; проверка всех 14 102 commits продолжается.
Проверки source revision `be3d07f3d` (полный SHA в архивном worker receipt):
160/160 на M40. Это инструменты архива/публикации и регрессионные readers,
без нового исполнения нейронных моделей. Поправка closed-job staging проверяется
отдельным последующим контролем и не входит в указанные 160.

Отдельная репетиция подготовки индексов проверила staged/unstaged bytes,
split index, sparse checkout, linked worktree и unmerged stages. Исходные
индексы и рабочие файлы не изменились. Selected intent-to-add явно отклоняется
до изменения источника и не считается поддержанным случаем.

Замена origin и исходных рабочих репозиториев ещё не выполнена.
Окончательная приёмка требует отдельного receipt с полными SHA, проверками
архива, списком обработанных stores/worktrees и оставшимися ограничениями.
