# Внешний архив экспериментов TimeLearner

Актуальная политика по указанию пользователя от 14.11.2026 заменяет правило
30.10 о хранении compressed primary в Git. Архивирование и очистка истории —
техническое условие продолжения исходного плана; они не завершают рефакторинг
и не изменяют научную интерпретацию уже полученных результатов.

## Авторитетное хранилище

На M40 используется отдельный каталог
`/media/user/Data/Nmsdk-StructTrainExpArchive`. Его нельзя смешивать с
`NmsdkStructTrainArchive`, `TLAgent-*` и `TimeLearnerRefactor`: последние могут
содержать исторические оригиналы и рабочие кэши, но не являются новым архивом.
Идентичность нового хранилища задаёт `archive.root.json`.

В архиве сохраняются точные байты первичных данных, моделей, журналов и полных
визуальных отчётов. Сжатые primary bundles не заменяются повторно рассчитанными
данными. Их `bundle.json`, logical member hashes, исходные commits, runtime
identity и критерии сохраняются. Архивирование не придаёт результату новый
уровень доказательности. Архив на одном диске не является независимой резервной
копией; наличие дополнительной копии указывается отдельно и не предполагается.

`objects/sha256/AA/SHA256` содержит неизменяемые объекты. Одинаковые байты
хранятся один раз. `history-maintenance/20261114/` — закрытый служебный раздел
для инвентаризаций, резервных копий и таблиц замены истории. Старые Git bundles
там предназначены только для восстановления, а не для push/fetch в origin.

В Git остаются код, исходные настройки, небольшие описания моделей и метрики,
читаемые отчёты, inventories и ссылки `*.archive.json`. Сжатые архивы, бинарные
модели, Git packs/bundles и крупные результаты (больше 1 MiB на файл) хранятся
внешне. Это предел публикации отдельного файла, а не обещание размера всего
репозитория. Отдельные небольшие выбранные рисунки допустимы; полные галереи
хранятся в архиве, а рабочие развёрнутые галереи являются кэшем.

## Запись и восстановление

На M40 перед публикацией ссылок:

```text
python3 -m Scripts.StructTrain.TimeLearner.external_archive store PRIMARY_FILE
```

Команда выводит JSON с kind/schema, размером, SHA256, авторитетным root и
относительным object path. Сохранить этот JSON рядом с описанием результата,
например `primary.tar.xz.archive.json`. Она копирует источник, сверяет источник
и конечный объект, не удаляет оригинал и не заменяет существующий объект.
Коллизия с повреждённым содержимым завершается ошибкой.

```text
python3 -m Scripts.StructTrain.TimeLearner.external_archive verify REFERENCE_JSON
python3 -m Scripts.StructTrain.TimeLearner.portable_primary BUNDLE_JSON OUTPUT_DIRECTORY
```

Native bundle reader использует локальный оригинал либо проверенную ссылку
`primary.tar.xz.archive.json`. При доступе к другой смонтированной копии архива
задаётся `NMSDK_STRUCTTRAIN_ARCHIVE_ROOT`; marker остаётся обязательным. Размер и
SHA256 проверяются до распаковки. Отсутствующий архив — явная ошибка, а не
основание для неполного анализа или восстановления из шаблонной модели.

На машинах без смонтированного архива получать нужные объекты отдельно по
защищённому соединению и проверять их SHA256. Большие файлы не коммитить для
пересылки между workers. Код и настройки по-прежнему синхронизируются через Git.
Выбор и подключение такого транспорта не выполняются скрыто при import.

## Обязательная последовательность замены истории

1. Инвентаризировать origin, локальную машину, Elder `.11`, M40 `.17`, Windows
   `.8` и ранее использованную Windows `.14`. Проверить все common Git stores,
   private branches, remote refs, detached worktree HEADs, stash и reflogs;
   исправить пробелы сканирования неинициализированных submodule stores.
2. Сохранить проверенные резервные копии всех уникальных историй и рабочих
   состояний. На Elder мало свободного места: крупные backups хранить на Data M40.
3. Подготовить новую историю отдельно. Для каждого исключаемого blob сохранить
   точные байты в новом архиве и таблицу repository/old commit/path/blob/size/hash.
   Проверить destination, доступность и полноту до изменения origin.
4. Сравнить деревья и topology: все не исключённые исходники, настройки, modes,
   авторы, messages и порядок merge parents сохраняются. При изменении истории
   дочернего repo сначала заменить её и проверить соответствующие root gitlinks.
   Private commits не публиковать в публичных ветках.
5. Перед переключением остановить автоматические Git fetch/write и проверить
   отсутствие использующих дерево экспериментов. Origin заменить атомарно с
   проверкой ожидаемых старых refs. Изменения веток за время подготовки требуют
   пересчёта, а не безусловного force push поверх чужой работы.
6. Перевести все рабочие копии, индексы, detached HEADs, stash и reflogs на новую
   историю, сохраняя staged/unstaged files. Не применять reset --hard. Удалить
   активные ссылки на прежнюю историю; офлайн backups оставить в архиве.
7. Проверить fresh recursive checkout, работу readers/publication guards,
   целостность refs и отсутствие исключённых blobs во всех live histories.
   Только затем удалить ненужные объекты Git и объявить миграцию завершённой.

Не подменять исторические научные SHA новыми в первичных данных. Отдельная
таблица aliases связывает исходные SHA с новой историей и учитывает обе очистки.
Старые отчёты остаются историческими; новые ссылки ведут к архивным references.

## Текущий статус

14.11.2026: начаты инвентаризация, подготовка резервной копии origin и изменение
архивных readers/publication policy. Замена origin и всех копий ещё не выполнена.
Окончательная приёмка требует отдельного receipt с полными SHA, проверками
архива, списком обработанных stores/worktrees и оставшимися ограничениями.
