В relevant Pulse/Core и Root/App/Tests выполнен текстовый поиск одинакового receiver `object[key] = object[otherKey]`. Три найденных producer site с вставкой нового ключа закрыты отдельными cold6, cold7 и execution3 commits. Recovery5 уже использовал owning `const auto baseSchema=result.value(...)`. Оставшиеся совпадения — числовые/строковые массивы, test arrays, изменение scalar через `.toDouble()`/`.toInt()` до mutation либо test assignment двух существующих keys. В частности, post-tune `internal[key]=internal[key].toInt()+1` материализует integer до изменения объекта, поэтому не требует blanket правки. Этот grep не объявляется доказательством отсутствия произвольных alias между различно названными объектами.

Причина подтверждается реализацией Qt5.15: mutable `QJsonObject::operator[]` возвращает positional `QJsonValueRef`, `atImpl` вставляет отсутствующий ключ, а ref assignment читает значение через сохранённый индекс. Источники: [официальный Qt qjsonobject.cpp](https://raw.githubusercontent.com/qt/qtbase/5.15/src/corelib/serialization/qjsonobject.cpp), [официальный Qt qjsonvalue.cpp](https://raw.githubusercontent.com/qt/qtbase/5.15/src/corelib/serialization/qjsonvalue.cpp). Owning value устраняет зависимость RHS от индекса изменяемого объекта.
