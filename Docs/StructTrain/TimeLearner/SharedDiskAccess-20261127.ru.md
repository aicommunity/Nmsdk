# Общий диск M40 и доступ к архиву экспериментов

Пользователь подтвердил подключение4ТБ диска M40 ко всем рабочим машинам.
Авторитетным каталогом результатов остаётся
`/media/user/Data/Nmsdk-StructTrainExpArchive` на M40. Общий ресурс всего
диска имеет имя`//10.245.1.17/disk4tb`; внутри него используется именно
подкаталог`Nmsdk-StructTrainExpArchive`, проверяемый по`archive.root.json`.
Прежние архивные каталоги с другими именами не являются этим хранилищем.

Буква сетевого диска и доступ из SSH или задания Task Scheduler относятся
к разным сеансам Windows. Перед использованием общего пути в фоновом
задании проверять доступ именно из его учётного контекста. Существующие
пользовательские подключения не отключались и не заменялись. Расчёты
Windows продолжают писать в изолированные локальные каталоги; недоказанный
сетевой доступ не выдаётся за завершённую публикацию.

Новая проверка `TimeLearner-SharedDiskProbe-fr502` выполнялась скрытым
`pythonw.exe` через Task Scheduler с `TASK_LOGON_INTERACTIVE_TOKEN`,
без повышения прав и смены существующих подключений. Управляющие Git
commits: .8 — `a96595fd5c73d26eea42e50d5d090b3579d9d55a`, .14 —
`927940ca81b6085169f10639aea50cf4b30b5658`. На M40 подтверждены все
четыре файла: размеры 199/205 байт и полные SHA256 совпали с результатами
Windows. Это доказательство доступа из проверенного интерактивного
контекста; права обычного SSH/S4U-сеанса этим не изменились. Для нового
задания такой контекст должен оставаться доступным.
[Серверное подтверждение](../../../Reports/StructTrain/TimeLearner/Progress-20261127/Windows-interactive-shared-archive-fr505.json).

В точном `C:/Python313/python.exe` .8 также проверены Matplotlib 3.10.3
и Agg. Python .14, используемый для Train, Matplotlib не содержит;
отрисовку ему без отдельной подготовленной среды не назначать. На M40
для новых графиков явно проверен интерпретатор
`/media/user/Data/TimeLearnerRefactor/plot-venv-a1/bin/python` с Matplotlib
3.9.4 и Agg. Отказ первой подготовки `fr508` сохранён; исправленная
подготовка `fr517` не повторяет native-расчёты.

Новые Linux-публикации могут передавать проверенный путь явно в
`external_archive.store(..., root)` или через профиль
`NMSDK_STRUCTTRAIN_ARCHIVE_ROOT`. Путь не заменяет проверку маркера,
полного размера и SHA256 объекта. Источники продолжают версионироваться
через Git; Git bundle также является передачей точных Git objects.
Копирование результатов между несколькими локальными архивами не требуется,
когда общий каталог доступен и прошёл проверку записи.

## Исправление первичного чтения объекта через CIFS

На .4 три последовательных вызова прежнего production`store` создали
правильный объект, но завершились`EINVAL` при его контрольном открытии.
После выполнения cleanup каждый объект немедленно прочитался и совпал
по SHA256. Дополнительные три файловых пробы показали успешное чтение
при удалении собственного временного имени до открытия целевого.

Исправление`e308d7d8fc2113b5af03501e8cff500443619480` меняет этот порядок
в`Scripts/StructTrain/TimeLearner/external_archive.py`: после эксклюзивного
создания целевой ссылки освобождается собственное временное имя, затем
выполняется полная проверка размера и SHA256. Существующий объект никогда
не перезаписывается; повреждённый объект по-прежнему отвергается.

На реальном SMB-пути .4 проверен production-модуль из точного Git commit:
11 применимых Python-тестов без отказов и пропусков, три новых объекта,
три повторные записи тех же байтов и два одновременных писателя одного
содержимого. Все ссылки возвращаются и разрешаются в исходные байты;
отказ повреждённого объекта проверен в частном тестовом каталоге.
[Данные и независимая проверка](../../../Reports/StructTrain/TimeLearner/Progress-20261127/Shared-archive-CIFS-production-accepted-fr419.json).

После этих успешных проверок внешний процесс первоначально завершился
ошибкой фиксации метаданных нового каталога: CIFS обновил наблюдаемые
атрибуты во время`file_record`. Этот отказ сохранён отдельно. Контроль
стабильности исходных файлов не ослаблялся. При новой публикации собственные
метаданные записываются из одних заданных байтов, сверяются чтением и получают
ссылку по этим байтам; независимое чтение с M40 подтверждает их фактический
размер и SHA256 на авторитетной файловой системе.

Для оператора создано небольшое связанное sparse worktree
`/home/user/Nmsdk-operators/shared-archive-fr413` из существующей Git-базы .4.
Полный clone не создавался. Основной `/home/user/Nmsdk` и runtime C++-проверок
остались на прежних версиях. После исправления оба закрытых комплекта .4 —
3320 файлов исходной матрицы и1300 файлов раздельных проверок — опубликованы
прямо через общий диск. Их отдельное полное восстановление4620 файлов
завершено на .12;37 файлов доказательств читателя независимо приняты
на M40. Исходные отказы тестов сохранены, общего PASS432 нет.

Исправление относится к публикации данных. Общие fault-проверки publisher,
Git closure и остальные требования этапов2/9/10 остаются в полном плане.
