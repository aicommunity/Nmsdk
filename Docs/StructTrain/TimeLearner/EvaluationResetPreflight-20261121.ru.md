# Проверка объявленной политики сброса до Test

В production-обёртке версии1 проверен протокол со сбросом перед каждой пробой.
До исправления `validate_job` проверял `coverage_policy=per_trial_windows`,
но не проверял `reset_policy` каждой строки. В итоге задание могло пройти
preflight с непроверенным режимом сохранения динамики, хотя комментарий
и заявленная область поддержки обещали только `reset_per_trial`.

Риск воспроизведён21.11.2026 на реальном сохранённом DATA-задании M40
с исходными моделью, порогом и восемью паттернами. Изменена в памяти только
политика первой пробы; job SHA пересчитан штатным сериализатором. Старый
production preflight принял и исходный, и изменённый вариант. Console
не запускалась; исходные файлы не менялись. Это проверка допуска задания,
а не доказательство ошибочного нативного расчёта.

Исправление требует `reset_per_trial` у каждой строки для всех трёх операций
оценки через эту обёртку. Несоответствие даёт специализированную причину
`pipeline_reset_policy_not_yet_verified` до дорогого запуска модели.
Проверка наличия полей, уникальности ID и coverage сохраняется.

Выполненная серверная регрессия использует восстановленные реальные
матрицы8,56 и27 проб: штатный вариант должен приниматься, смена политики
первой или последней строки на `preserve_neuron_dynamics` либо неизвестное
значение должна отклоняться даже с корректно пересчитанным SHA. Проверка
включена в `tests/test_frozen_data_primary_restoration.py`.

Все эти случаи прошли в ограниченном задании
`s11-frozen-data-primary-restore-m40-a2`:1/1 интеграционная проверка с12
отрицательными subcases и тремя штатными матрицами, без пропусков.
Группа закрыта за67.02с. Исходные данные и результаты источников не менялись.
[Квитанция](../../../Reports/StructTrain/TimeLearner/FrozenNewFoils-20261121/m40-full-primary-restoration-a2.json).

Это ограничение области нового production-пути, а не удаление существующей
нативной возможности continuous stream или исторических результатов.
Поддержка сохранения динамики в новом runner требует отдельной проверенной
версии протокола, наблюдения межпробных участков и самостоятельной приёмки.
Текущие задания Classic new-foil и Windows Train используют прежние неизменные
runtime; их конфигурации этим исправлением не редактируются.

## Отдельное чтение прежних результатов

В прежних сохранённых опытах17.11 уже есть `preserve_neuron_dynamics` при
`per_trial_windows`. Новый допуск запуска не должен переписывать их результаты
или подменять чтение прошлого новым выполнением. Для `analyze --format pipeline-run`
подготовлен явный адаптер `--historical-analysis evaluation-v1-native-reset-policy`.
Он допускает только два известных значения reset, требует хотя бы одной
preserve-пробы и применим только к уже записанным операциям оценки.

Адаптер не меняет файлы, preflight, артефакты, метрики и проверку исходной
модели; все прежние контрольные суммы и привязки процессов остаются обязательны.
Численный результат не проецируется в другую схему. Известный переход проверки
recognition2→3 учитывается отдельно: версия3 добавила семантическую проверку
storage-образов и её диагностическое поле. Для старой записи дополнительно
требуется прежнее точное равенство определений образов, включая XML.
Только после полной текущей проверки разрешено сопоставить эти два поля
метаданных с прежней формой. Счётчики, остатки, модель, исходный аудит,
порог и доказательство его подстановки должны совпадать целиком.
Неизвестные версии и поля, изменение метрики либо подмена числа bool отвергаются.
Возвращаются явные
`new_execution_permitted=false` и `continuous_production_runner_verified=false`.
Публичные `validate_job`, `audit_execution` и `run_job` не принимают этот
адаптер в качестве разрешения нового запуска. Неизвестная политика отклоняется
и историческим читателем.

Регрессия подготовлена на полном опубликованном архиве17.11:
`tests/test_historical_evaluation_reset_analysis.py`. Она должна восстановить
все3078 файлов, прочитать обе реальные preserve-матрицы, сохранить их результаты
TP1/FP1/FN0/TN6 и подтвердить отказ нового запуска с теми же декларациями.
В первой серверной проверке нового читателя полное восстановление3078 членов
состоялось, но семантическое сопоставление закономерно остановилось на
`pipeline_run_analysis_changed`: recognition2→3 ещё не было учтено.
Исправление этой узкой совместимости подготовлено отдельно; его успешная
проверка обеих реальных матриц ещё требуется. Две другие проверки того же
задания — полные Classic и Branch архивы по199 файлов с матрицами8/56/27 —
прошли; общий cohort3/3 не принят из-за старого читателя.
[Раздельные квитанции](../../../Reports/StructTrain/TimeLearner/FrozenNewFoils-20261121/full-primary-individual-restorations.json).
