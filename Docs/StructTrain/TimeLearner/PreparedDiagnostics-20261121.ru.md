# Отдельное выполнение подготовленного диагностического Test

> Последующее состояние: [фактические ответы N4 при выбранных порогах](N4LongTrainingSameMatrix-20261121.ru.md).
> Ниже также сохранены постановка и промежуточные статусы подготовки.

## Цель и сохранённые проверки

`Scripts/StructTrain/TimeLearner/prepared_diagnostic.py` выполняет один уже
подготовленный Test на восьми паттернах. Контроллер не загружает заново
полные Python-деревья модели и истории. Все поля исходного состояния остаются
в `checked-file-source-v1`; нативный декодер заново проверяет подпись полного
задания, исходный пакет и импортируемый граф. Модель не заменяется шаблоном
или сокращённым состоянием.

Перед запуском и после закрытия процесса проверяется полный набор файлов
подготовленного input-каталога: пути, размеры и SHA256. Проверяются подпись
envelope, связность source SHA, package SHA, ранее выполненный полный аудит
источника, восемь уникальных проб с одним target и семью foil, полные окна2с
и reset-per-trial. Сохраняются исходные job, модель, первичные данные и
отрицательные исходы прежних попыток. Состав и подпись разрешённого задания
ещё раз проверяет сам Console, а не только контроллер.

Linux использует штатный cgroup backend, общий реестр ресурсов и отдельные
ограничения диска. Windows использует штатный Job backend. Для `--help`
Windows также применяет Job handles: Linux pidfd/killpg здесь неприменимы.
Проверка справки описывает интерфейс и не доказывает выполнение модели.
Пустые переменные окружения в Windows-манифесте остаются отсутствующими
в эффективном окружении. Путь Python backend и источник собранного SDK
фиксируются отдельно; одинаковые байты backend по разным путям не подменяют
его строгую runtime-привязку.

Это ещё не приёмка всего общего runner, очередей или независимого Test.
`terminal.json` этого исполнителя подтверждает закрытое нативное выполнение
и неизменность входов. Он явно оставляет `observations_independently_audited=false`
и `scientific_verdict=null`. Наблюдения, итоговые метрики, порог и рисунки
проходят отдельную проверку. Сходимость Train не выводится из успешного Test.

## Установленные исходы предыдущих попыток

| Попытка | Установленное ограничение | Последующее действие |
|---|---|---|
| M40 long-model A1 | OOM Python-контроллера до Console | Освобождение лишних parsed copies, новая A2 после закрытия |
| M40 long-model A2 | `owned_native_disk_budget`: полные копии подготовки и нативные отчётные модели превысили4ГиБ | Отдельное выполнение уже подготовленных полных входов; исходный лимит активной попытки не менялся |
| Elder long-model A1 | Неполное выполнение Console; первоначальная проверка закрытия child-group не удалась, позднее вся группа закрыта | Сохранены исходные отрицательные записи; подготовленные входы повторно используются без гигабайтного Python-контроллера |
| Windows long-model A1 | Имена внешних первичных данных не совпали с archive namespace | Штатная материализация сохранённых primary с повторной проверкой |
| Windows long-model A2 | `None` в окружении capability-процесса | Нормализация описания отсутствующих переменных; подготовленные данные не менялись |
| Windows prepared A3 | Linux pidfd/killpg в metadata help probe | Справка через штатный owned Windows Job |
| Windows prepared A4 | Python backend взят из SDK-каталога вместо пути, записанного в runtime | Используется отдельно закреплённый Python actor; SDK и модель прежние |

Изначальная причина прерывания Elder не выводится из позднего состояния
закрытия группы. Его частично записанный native model не принимается за
завершённый результат. Повторно используются только полные проверенные
input-файлы, а новый Console создаёт собственный результат.

Небольшие проверки объявлений, связности и file-source завершены31/31 на
M40 и31/31 на Elder. Эти наборы не являются проверкой всей новой оркестрации
или полной обязательной матрицы плана.

### Проверка порога на той же матрице

| Модель | Предложенный порог | Предварительный TP/FN/FP/TN по максимумам LT | Native baseline wall time |
|---|---:|---|---:|
| Elder Classic |0.025742023300155625|1/0/2/5|2027.39с|
| M40 Branch |0.0999470202411733|1/0/1/6|1796.40с|
| Windows Branch |0.09907753464712266|1/0/1/6|1851.95с|

Порог — середина между максимумом target и наибольшим строго меньшим
максимумом foil, по записанному реальному `LTZone.Potential`. Числа в третьем
столбце являются предложением по неспайковым трассам, а не результатом
проверки спайков. У всех трёх моделей максимум хотя бы одного foil выше target:
нулевые FP этим выбором не обещаются. Две Branch-модели получены разными
остановленными Train и SDK; это не независимые повторы одной конфигурации.

`prepared_threshold.py` проверяет всю byte/hash closure baseline, полный набор
исходных input и подпись исходного разрешённого задания, загружая полную
историю один раз. Он создаёт новое schema2-задание с новым run_id и единственным
научным изменением — порогом. Все первичные файлы и история остаются в полном
source namespace; одинаковые неизменяемые файлы переиспользуются hard links.
Тонкий worker снова проверяет их полный набор и передаёт задачу нативному
декодеру. Подготовка не запускает Train и не присваивает сертификат сходимости.

На Elder и M40 запущены `s11-prepared-long-model-threshold-elder-a1` и
`s11-prepared-long-model-threshold-m40-a1`:8GiB/2700с на native, по восемь проб.
Для Windows подготовка A2 завершилась за43.41с через отдельный Scheduled Task
с собственным Job-процессом16GiB/1800с и подтверждённым закрытием. Запущен
`windows-prepared-long-model-threshold-a2` с native8GiB/2700с. Controls commit
`49fa8f11593ec6bb797a9ce745f9b0cc98e18621`. Подготовка A1 перед этим была
отклонена до создания child, поскольку Python runtime не сохранил
`build_flags.windows_backend_sha256`; A2 сохраняет исходные backend flags.
Первоначальный detached SSH parent Windows не сохранился до
создания runtime/owned child; это отрицательная попытка запуска подготовки,
не результат модели. Повторная подготовка не меняет source или baseline.

Это **Historical Same-Matrix diagnostic threshold experiment**. Даже при
подтверждённых TP/TN он не станет доказательством независимой классификации
или Exact-обучения: все исходные Train остановились по бюджету/числу проходов.
Приёмочный критерий включения семейства в научное описание — реально
подтверждённые TP≥1 и TN≥2 с явной маркировкой этого протокола.

После закрытия всех восьми окон требуется независимая проверка наблюдений,
предложение порога по реальному потенциалу решающего элемента, настоящий
повторный Test выбранного порога и читаемые графики всех сом с фактическими
входными импульсами. Для последующих frozen probes можно экспортировать
компактную физическую DATA из явно преобразованного recognition-состояния,
с проверкой соответствия исходному графу и отклику; solo DATA не переименовывать.

## Экспорт physical DATA на Windows

`prepared_physical_export.py` использует тот же полный recognition-источник,
checked-file-source и нативную проверку графа для Linux и Windows. Новая
Python-копия выбирается явным `--python-source` при подготовке. Для Windows
создаётся отдельный runtime manifest с SHA фактически применяемого backend;
предыдущий manifest и native SDK не изменяются. Из JSON-источника свыше1ГиБ
удаляются только пробелы вне строк, с проверкой исходных байтов и semantic SHA.

Проверка возможностей Console находится в общем `native_cli.py`. На Windows
нужно передать `evidence_output`: bounded Job сохраняет help, точную identity,
лимиты и закрытие процесса. Запрошенная операция проверяется по её собственному
флагу; наличие только diagnostic-evaluate не подтверждает physical-model-export.

Windows backend принимает необязательный monitor. Ошибка проверки свободного
места или объёма output останавливает всю принадлежащую заданию группу через
существующий cleanup. Контроль не меняет модель и не заменяет проверку native
runtime capture. Новые реальные process-тесты проверяют вызов monitor,
закрытие main/descendant при ошибке и освобождение lock; CLI-тесты проверяют
реальный Console и отказ для другого executable. Эти тесты и actual export
выполняются на Windows-сервере, не локально.

DATA остаётся физическим описанием без сертификата обучения и без checkpoint
контроллера. Roundtrip графа и совпадение реакций — отдельные проверки; одна
успешная команда export не доказывает завершение этапа5 во всей матрице.
