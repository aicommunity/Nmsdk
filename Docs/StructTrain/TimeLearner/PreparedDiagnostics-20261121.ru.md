# Отдельное выполнение подготовленного диагностического Test

## Цель и сохранённые проверки

`Scripts/StructTrain/TimeLearner/prepared_diagnostic.py` выполняет один уже
подготовленный Test на восьми паттернах. Контроллер не загружает заново
полные Python-деревья модели и истории. Все поля исходного состояния остаются
в `checked-file-source-v1`; нативный декодер заново проверяет подпись полного
задания, исходный пакет и импортируемый граф. Модель не заменяется шаблоном
или сокращённым состоянием.

Перед запуском и после закрытия процесса проверяется полный набор файлов
подготовленного input-каталога: пути, размеры и SHA256. Проверяются подпись
envelope, связность source SHA, package SHA, ранее выполненный полный аудит
источника, восемь уникальных проб с одним target и семью foil, полные окна2с
и reset-per-trial. Сохраняются исходные job, модель, первичные данные и
отрицательные исходы прежних попыток. Состав и подпись разрешённого задания
ещё раз проверяет сам Console, а не только контроллер.

Linux использует штатный cgroup backend, общий реестр ресурсов и отдельные
ограничения диска. Windows использует штатный Job backend. Для `--help`
Windows также применяет Job handles: Linux pidfd/killpg здесь неприменимы.
Проверка справки описывает интерфейс и не доказывает выполнение модели.
Пустые переменные окружения в Windows-манифесте остаются отсутствующими
в эффективном окружении. Путь Python backend и источник собранного SDK
фиксируются отдельно; одинаковые байты backend по разным путям не подменяют
его строгую runtime-привязку.

Это ещё не приёмка всего общего runner, очередей или независимого Test.
`terminal.json` этого исполнителя подтверждает закрытое нативное выполнение
и неизменность входов. Он явно оставляет `observations_independently_audited=false`
и `scientific_verdict=null`. Наблюдения, итоговые метрики, порог и рисунки
проходят отдельную проверку. Сходимость Train не выводится из успешного Test.

## Установленные исходы предыдущих попыток

| Попытка | Установленное ограничение | Последующее действие |
|---|---|---|
| M40 long-model A1 | OOM Python-контроллера до Console | Освобождение лишних parsed copies, новая A2 после закрытия |
| M40 long-model A2 | `owned_native_disk_budget`: полные копии подготовки и нативные отчётные модели превысили4ГиБ | Отдельное выполнение уже подготовленных полных входов; исходный лимит активной попытки не менялся |
| Elder long-model A1 | Неполное выполнение Console; первоначальная проверка закрытия child-group не удалась, позднее вся группа закрыта | Сохранены исходные отрицательные записи; подготовленные входы повторно используются без гигабайтного Python-контроллера |
| Windows long-model A1 | Имена внешних первичных данных не совпали с archive namespace | Штатная материализация сохранённых primary с повторной проверкой |
| Windows long-model A2 | `None` в окружении capability-процесса | Нормализация описания отсутствующих переменных; подготовленные данные не менялись |
| Windows prepared A3 | Linux pidfd/killpg в metadata help probe | Справка через штатный owned Windows Job |
| Windows prepared A4 | Python backend взят из SDK-каталога вместо пути, записанного в runtime | Используется отдельно закреплённый Python actor; SDK и модель прежние |

Изначальная причина прерывания Elder не выводится из позднего состояния
закрытия группы. Его частично записанный native model не принимается за
завершённый результат. Повторно используются только полные проверенные
input-файлы, а новый Console создаёт собственный результат.

Небольшие проверки объявлений, связности и file-source завершены31/31 на
M40 и31/31 на Elder. Эти наборы не являются проверкой всей новой оркестрации
или полной обязательной матрицы плана.

На Elder записаны первые три пробы. Первая target-проба имеет4001 отсчёт,
полное валидное окно0–2с, неизменный model_before/model_after и ноль спайков
при исходном пороге100. Это частичное наблюдение; итог всей матрицы пока
не оценивается. Само молчание не является успешной детекцией.

После закрытия всех восьми окон требуется независимая проверка наблюдений,
предложение порога по реальному потенциалу решающего элемента, настоящий
повторный Test выбранного порога и читаемые графики всех сом с фактическими
входными импульсами. Для последующих frozen probes можно экспортировать
компактную физическую DATA из явно преобразованного recognition-состояния,
с проверкой соответствия исходному графу и отклику; solo DATA не переименовывать.

Тяжёлые данные пока сохранены на workers. Полные внешние архивы с проверенным
восстановлением ещё нужны; удалять эти исходники сейчас нельзя. В Git остаются
код, текст и компактные ссылки.
