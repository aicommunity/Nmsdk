# Fast N1: заранее объявленное сравнение полных окон и сбросов

Источник — та же сохранённая Branch N4/N1 Fast3 terminal21600 модель и
фиксированный порог 0.054353792695896797. Исходный порядок Phase A сохраняется.
Нового обучения, retarget, изменения физики, подбора порога или независимого
набора паттернов нет. Baseline уже дал TP1/FP1/FN0/TN6 при reset-per-trial;
это наблюдение, а не требование к результату новых условий.

Первый опыт содержит 32 пробы: исходные восемь паттернов в каждом из четырёх
условий — окно 2с со сбросом, 4с со сбросом, 2с с сохранением динамики нейрона,
4с с сохранением динамики. Перед каждым условием модель импортируется заново;
внутри preserve_neuron_dynamics условий физическая динамика между пробами
сохраняется штатным native методом. Сначала повторяется исходный baseline;
все его samples и классификации должны точно совпасть с сохранёнными.
Несовпадение останавливает опыт и не объявляется эффектом нового фактора.

Увеличение полного окна одновременно увеличивает наблюдаемый quiet-tail,
интервал между onset и время, в котором возможен поздний ответ. Поэтому это
не чистое вмешательство только в ITI. Фактические onset intervals и расстояния
от последнего входного импульса до следующего onset записываются из native
timestamps. Окна не сокращаются, samples не прореживаются. Сходимость Train,
полная межфакторная матрица всех положений target и независимое обобщение
этой первой серией не подтверждаются.

Исполнение: frozen_protocols.run через production diagnostic-evaluate,
managed owned native processes, native model-before/model-after и общий scorer.
Декларации, schema, effective duration/reset, число и идентичности всех проб,
закрытие окон, неизменность source/model/threshold проверяются до оценки.
Для каждого условия используется production ConditionSpec; имена attempts,
deployment paths и добавление постороннего условия в case fingerprint не входят.
Научные TP/FP/FN/TN измеряются, заранее желаемый PASS не задаётся.

До запуска проверить свободное место Elder: прежние данные сохраняются,
новый output ограничен 8ГиБ, свободный остаток должен покрывать его и 2ГиБ
пола. Parent и native имеют отдельные bounded kernel units, память резервируется
как их сумма. При недостаточном месте опыт не запускать и не удалять уникальные
данные. Все primary и temporal reports публиковать во внешнем M40 архиве;
в Git сохранять исходники, план, декларации и компактные refs.

После наблюдений построить временные Soma/LT/input графики всех 32 проб
штатным renderer с полным recovery и читаемыми увеличениями. Результат
опубликовать независимо от качества классификации. На момент этой записи
источник и код подготовлены, новый scientific run ещё не выполнен.
