# Classic: обучение с восемью кандидатами на путь

## Вопрос и условия

В свежей паре обучений с пределом24 кандидата на путь оба расчёта
остановились по ограничению времени. Последовательный порядок не исследовал
третий обучаемый путь; исправленный циклический порядок посетил все пути,
но совместное выполнение допусков не подтвердил. Новый опыт проверяет
меньший локальный предел:8 кандидатов и по3 кандидата за посещение пути.
Задача — получить измеренный охват и конечные ошибки всех путей при
прежних общих ограничениях, затем проверить фактическое распознавание.
Улучшение классификации заранее не предполагается.

Классификатор Classic получает один паттерн из M=4 импульсов с интервалами
80,160 и240 мс. Начальные длины и числа синапсов равны единице,
сопротивления —86 МОм. Применяются прежние образы компонентов и частота
2000 Гц. Настройка изменяет длины путей и числа синапсов, сопротивления
фиксированы. Предел числа синапсов128, длины256; опорный четвёртый путь
сохраняет длину1 и один синапс.

Амплитудные цели — CapturedPerInput, абсолютный допуск10⁻⁵,
относительный выключен, временной допуск0,02 с. При обучении измеряется
максимум закреплённого импульса штатной пачки. C-trim, PostTune и
автоматический выбор порога выключены; исходный порог100 сохраняется
до отдельной процедуры калибровки.

Локальный предел влияет также на некоторые сетки предложений длины
и нормализации. Восемь кандидатов нельзя интерпретировать как первые
восемь точек неизменной24-точечной последовательности или как простое
ускорение того же перебора.

## Объявленные ограничения

| Величина | Предел |
|---|---:|
| Кандидаты на обучаемый путь | 8 |
| Кандидаты за посещение при обходе по кругу | 3 |
| Поисковые пробы | 160 |
| Изменения | 1280 |
| Проходы | 1 |
| Моделируемый процесс | 10000 с |
| Управление вычислением обучения | 32400 с |
| Внешнее ограничение расчётного процесса | 39600 с |
| Полная оболочка задания | 43200 с |

Разрешены20000002 тика:20000000 соответствуют пределу модельного времени,
ещё два — выполнению уже поставленной финализации, а не продолжению поиска.
Это разные ограничения; фактическую причину остановки определяют по данным.
Расчётному процессу выделены16 ГиБ, контроллеру4 ГиБ. На Data M40
сохраняются не менее16 ГиБ свободного места и предел8 ГиБ новых выходов.
Правило32 ГиБ для .12 этим заданием не изменяется.

## Подготовка и фактический старт

Предельное число кандидатов объявлено production-функцией
`cold_budget.declare_candidate_limit`. Затем используются штатные
`matched_count_job`, политика N0 length0 и `declare_input_traversal_job`.
Начальное состояние не восстанавливается из результата прежнего Train.

Сначала отдельный реальный preflight сопротивления подтвердил исходный
граф и параметры. После него production-worker проверил начальный
Count-граф и положительный фактор Ns=2. Оба исходных графа содержат44 узла
и совпадают с прежним измеренным исходным состоянием. Увеличение числа
синапсов изменило реальный граф до45 узлов. Все три подготовительных
процесса закрыты, байты загруженных файлов сохранены.

При записи метаданных подготовитель обратился к отсутствующему полю
результата `native`. Производственный контроль уже успешно завершился.
Исправлена только ссылка на его реальный `run-manifest.json`; расчёт
не повторялся, исходный отказ сохранён. После проверки конфигурация
зафиксирована отдельным Git commit, затем запущен штатный
`linux_count_training` с резервированием ресурсов и контролем всех
дочерних процессов. Train реально работает; итог пока неизвестен.

Этот опыт использует GCC-runtime контейнерного кандидата Rdk/PulseLib,
отличающийся от runtime прежней пары обходов. Поэтому сравнение с прежними
24 кандидатами не объявляется изолированным причинным эффектом одного
числового предела. Новое исходное состояние проверено измерением;
версия программы сохраняется как отдельное условие опыта.

## Приёмка результата

После закрытия процесса требуются полный независимый аудит журнала,
проверка измерений и конечного состояния, сохранение исходного статуса
остановки и доступных ошибок каждого пути. Отсутствие свежей проверки
всех путей запрещает приписывать конечной модели выполнение допусков.

Из фактического состояния выполняется штатный перенос к распознаванию.
Предусмотрены исходная восьмёрка, один явно объявленный выбор порога
Historical Same-Matrix и отдельное реальное предъявление с выбранным
порогом. Незавершённое обучение сохраняет диагностический статус;
шаблонная модель не подставляется. Для всех паттернов нужны полные
временные графики потенциалов сомы с фактическими входными импульсами,
выходными событиями и читаемыми увеличенными фрагментами.
