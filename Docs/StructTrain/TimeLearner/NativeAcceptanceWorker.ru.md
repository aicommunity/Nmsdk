## Явная конфигурация свежего build

Обнаруженный дефект: прежний runner только проверял `required_cache_tokens` после configure. На тёплом cache A4 флаги сохранялись, но новый cache не получал объявленные ASan/LLM параметры. `configure_arguments` теперь строит фактический argv из того же job schema1, без нового API или launcher. Записываемый `configure-arguments.json` содержит именно выполненный argv.

Только известные STRING поля C/CXX flags активной конфигурации и link flags, BOOL `RDK_USE_LLM`/`RDK_LLM_BUILD_EMBEDDED` и PATH `RDK_LLM_LLAMA_CPP_DIR` преобразуются в дополнительные `-D`. Source/build, deploy/resource/framework и disconnected значения задаются каноническими job paths; противоречащий token запрещён. Незнакомые корректно типизированные entries остаются только постусловиями, их значения не применяются. Дублирующийся name даже с другим type, неполная строка, неподдерживаемый type и управляющие разделители запрещены до configure. Полная последующая проверка cache сохраняется.

При `RDK_LLM_BUILD_EMBEDDED:BOOL=ON` новый профиль обязан явно объявлять `RDK_LLM_LLAMA_CPP_DIR:PATH=...`. Эта существующая canonical директория внутри workspace должна быть отдельным точным элементом `protected_runtimes`: штатные read reservation и before/after inventory защищают её как вход. Симлинк/alias, отсутствующая директория или отсутствие protected binding отвергаются до создания worker output. Это предотвращает неявное наследование неизвестного источника из cache; LLM не выключается как способ пройти configure. Старые замороженные jobs сохраняют свои версии worker, а новые job declarations фиксируют полный прежний профиль и dependency path явно.

Сохранённый A4 воспроизводится старым worker из Root `478cc35c0f1a314c34ad93aa0095b61836c658ec`; новый контракт не делает его прежние артефакты ретроспективно невалидными. Новые профили, использующие новый worker, явно фиксируют источник embedded LLM и сохраняют прежние значения cache/flags.

Новые проверки выполняются только на серверах. Tiny CMake `project(NativeProfile NONE)` подтверждает получение параметров в настоящем свежем cache, не включает compiler language и не собирает SDK/модель. Обязательный consumed fixture `TIMELEARNER_NATIVE_PROFILE_CMAKE/cmake-dependency.json` содержит kind `timelearner_cmake_configure_dependency`, schema_version1, canonical resolved executable path и SHA256 установленного cmake; тест сверяет фактически разрешённый executable до и после configure. Binary не копируется, PATH не меняется. Это binding одного tool executable, не всей OS module closure. Отсутствие fixture не превращается в PASS; производственный набор19 не допускает skips. Остальные проверки покрывают canonical conflicts, дубли/types/bare flags, неизвестные read-only tokens и защиту llama source. Наличие source tests не объявляет их runtime PASS.

Вызов: `python3 -m Scripts.StructTrain.TimeLearner.native_acceptance_worker --job /absolute/job.json`. Job содержит schema1 с kind `timelearner_native_acceptance_job`, workspace, preparation, paths (source/build/runtime/output/resources/framework), build (type/parallel/wall_seconds/required_cache_tokens), limits (whole_wall_seconds/leaf_memory_bytes/leaf_tasks/physical_free_floor_bytes/reservation_memory_bytes/reservation_disk_bytes), asan_options, protected_runtimes, artifacts. Правило artifact содержит glob/minimum/maximum; null maximum означает отсутствие верхней границы. Пути принадлежат workspace; build/runtime/output отделены от читаемых директорий. Существующий runtime не используется как выход новой сборки.

Preparer запускается отдельным процессом из проверенного tool-root и создаёт canonical schema2 repo-module declaration. Worker получает IDs/runplan/source inventory непосредственно из неё: в теле нет копий номера Root, списка случаев или числа248. Он сверяет фактическую командную строку, физический module file с Git blob, чистую closure всех репозиториев и выбранные C++ файлы. SDK native_gate/runtime/reservations/containment импортируются только из SDK-root; подмена sys.path внутри уже загруженного Scripts namespace не применяется. Подготовка не подтверждает компиляцию, kernel closure или успешность тестов.

Независимый review первоначального1f88 выявил недостаточную проверку согласованности canonical полей и общий try, прекращавший последующие final captures. Worker теперь использует ровно production `native_preparation.serialize_preparation`, включённый merge `8bf773d4ce6f3b23d79796a8536e5c54d526341a`; helper/collector bytes сохранены. C++ файлы и gitlinks baseline17db/Pulse88/Bin918/Rdkd6 сохранены. Нельзя принимать самосогласованно перехешированные stale root/source SHA/unknown IDs либо положительные execution-флаги. Проверяются фактические пути импорта serializer/collector в том же SDK namespace. Preparer остаётся отдельным процессом.

Worker проверяет закрытие указанных прежних owned groups; резервирует директории; контролирует heartbeat, wall time и свободное место. Он сохраняет источники по Git bytes, материализованные ресурсы с проверкой Bin commit, исторические runtimes, framework и текущий runtime до/после проверок. `.git` исключается из сравнения файлов runtime/resources: изменение служебных lock/index файлов не считается изменением физики; исходники и ресурсы проверяются отдельным Git-byte путём. Сборка использует имеющийся изолированный CMake cache, disconnected framework и явно объявленный профиль. INI обязан указывать фактический ресурсный каталог.

Каждый leaf выполняется штатным native_gate schema3 с собственными ограничениями. Проверяется compiled inventory: выбранное подмножество обязано присутствовать, остальные случаи бинарника не объявляются выполненными. Фактические completed/failed/skipped ID читаются из native.xml; отсутствующие случаи не достраиваются из плана. Ошибки тестов, неполный cohort и нарушение сохранности артефактов различаются. `cohort_assertions_passed` относится только к наблюдённым assertions; `job_validation_passed` дополнительно требует первичные файлы, сохранность исходников/runtime и отсутствие ошибок heartbeat. Scientific verdict всегда null.

Внешний owned launcher остаётся обязательным: только он завершает всю физическую группу компилятора и каждую записанную detached native leaf group при остановке, затем проверяет их закрытие и освобождает lease. Worker сам не освобождает резервирование. Общий Python validation/AR adapter не заменяет этот launcher без отдельной поддержки вложенных native groups. При ошибке до создания worker output процесс может завершиться без terminal.json; это process_error внешнего launcher, не нулевой успешный запуск.

Финальные snapshots выполняются независимо для текущего runtime, каждого protected каталога, source bytes, source closure, resource HEAD и build metadata. Ошибка одного наблюдения сохраняется и не мешает остальным. Одинаковые материализованные bytes не скрывают смену HEAD/gitlink. CMake cache и generated flags/link commands сохраняются также после неуспешной сборки. Final capture errors делают job невалидным; assertions при этом остаются отдельной осью.

Двенадцать адресных metadata tests покрывают canonical selection/invocation, stale hash/PASS claim, duplicate/count/leaf corruption, bool budgets/пустой profile и escaping artifacts, actual partial/failed/skipped JUnit, дубли JUnit, повреждение JSON/alias, сохранность runtime bytes, отказ protected output до создания каталога, rehashed inconsistent canonical2 и независимые final captures при дрейфе/ошибке чтения/смене commit. Fixtures — полный формат декларативных metadata, без заявления о существовании Git checkout или модели. Эти проверки не строят C++, не выполняют модель и не заменяют полный native cohort; их запуск разрешён только на серверах. Первоначальные девять тестов не запускались и заменены текущим набором12.
