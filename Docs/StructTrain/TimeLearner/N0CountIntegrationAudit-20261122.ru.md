# N0: число синапсов и проверка численного шага

Это проверка исходного кода перед сравнительным обучением с измеренным
предложением Nₛ. Она не является новым численным экспериментом и не
подтверждает сходимость обучения. Проверенная реализация PulseLib —
`b03e13857cd7656a8ff1ff3162d28b25e90bb5a4`; C++ решающего контура совпадает
с проверенной версией `649179dd978ef2f579b0c8c020f49643b0fccd3f`.

## Фактические уравнения

В `NPulseSynapse::ACalculate2` величина `TimeStep` обозначает частоту f,
а не длительность шага. Для выделения и распада медиатора используются
коэффициенты α=1/(τₛf), β=1/(τdf). Проверка `SecretionBound` в
`Core/TimeLearner/NativeModelEditor.cpp` требует положительных конечных
параметров и 0<α<2, 0<β<2. При коэффициенте более1 учитывается возможность
перерегулирования, а не предполагается p≤1. Проверка ограничена настоящим
классом `NPulseSynapse`; неподдерживаемая формула не объявляется безопасной.

Оценка проводимости учитывает Weight, Resistance, режим входа, амплитуду,
PSI и фактические связи. Для PSI проверяется реальная кусочная формула
`PresynapticInhibitionConductance`, включая остаток только при активном
входе. Суммируются все синапсы, реально подключённые к каналу. При
`UseAverageSynapsis` применяется деление на их фактическое число.
Следовательно, Nₛ не теряется при проверке: в режиме суммирования растёт
суммарная проводимость G. Две модели с разными Nₛ могут иметь одинаковую
оценку при усреднении — это не ошибка применения фактора.

Уравнение `NPulseChannel::ACalculate2` имеет вид

```text
T = C / (G + 1/R)
u[k+1] = u[k] + (v[k] - (1 + GR) u[k]) / (Tf)
q = (1 + GR)^2 / (CRf)
```

Величина v включает фактические входы канала и обратную связь мембраны.
R выбирается из `Resistance`, `RestingResistance`, `FBResistance` по
состоянию канала и обратной связи. `AssessNativeIntegration` проверяет все
три значения и требует конечного q<2. Это проверка коэффициента именно
данной дискретной формулы, а не универсальное правило τ≥2dt. Для
фиксированных G, R и внешнего входа множитель собственного состояния
равен 1−q. Проверка этого множителя сама по себе не доказывает устойчивость
всего связанного, переключающегося дерева или сходимость структурного поиска.

## Место проверки и последствия отказа

`ApplyNativeInputParametersImpl` сначала строит отдельный штатный preview
полного графа, применяет одновременно L/Nₛ/Rs и разрешённое изменение C,
проверяет эффективные параметры и вызывает `AssessNativeIntegration`.
До этого решения рабочий граф не меняется и ни один новый физический тик
не рассчитывается. Только после принятия preview применяется изменение
живого графа и проверяется совпадение его семантической идентичности.

Проверка также выполняется при подготовке настоящей пробы и распознавания.
Число128 — предел целочисленного поиска, а не безусловное разрешение
интегрировать любой такой граф. Недопустимый кандидат отклоняется с причиной.
`BoundedTrainingSession::DeclineEdit` сохраняет причину и продолжает
ограниченный поиск только при подтверждённой неизменности текущей модели;
при несовпадении revision завершает управление как `InvalidModel`.
Отказ изменения не подтверждает `PhysicalInfeasible` или `Exact`.

Секущая N0 предлагает целое число внутри объявленных границ. Она не
обходит preview, не меняет C или частоту ради принятия предложения и не
делает проводимость линейной по Nₛ как условие сходимости. После изменения
требуются новые измерения времени, амплитуды и принадлежности вершины.

## Доказательства и оставшиеся проверки

В исходниках есть настоящий fixture `NativeIntegration` с изменением
Weight, PSI, SecretionTC и C и проверками принятия/отказа. Это наличие
проверки в коде; её результат нельзя подменить результатом146 тестов
решающего контура. Четыре новые проверки `NativeMeasuredCount` используют
реальные компоненты Classic/Branch при2000/20000Гц, но их новый запуск
после исправления ошибки компиляции ещё не завершён.

Перед интерпретацией сравнительного обучения необходимо:

1. Получить успешные результаты новых нативных проверок и проверить
   исходные трассы; сохранить отдельно отклонённую первую сборку.
2. Проверить на реальных storage-графах Nₛ=1,2,8,128, режимы суммы и
   усреднения, обе частоты и используемый PSI-профиль. Для допустимого
   графа сравнить оценку с фактическими связями и дискретным откликом;
   для недопустимого подтвердить отказ до изменения живого состояния.
3. Включить контроль уменьшения C, изменения f, неоднородных банков и
   дополнительного тормозного входа. Не менять физику контрольной
   научной постановки ради прохождения этих проверок.
4. Сравнить прежний и новый порядок предложений при одинаковых цели,
   профиле, начальном графе, допусках и бюджете. Считать отдельно отказ
   кандидата, исчерпание поиска, остатки финального измерения и TP/FP/FN/TN.

Python preflight сейчас проверяет схему, конечность и диапазоны присланных
`maximum_conductance`/`maximum_step_gain`. Этот путь сам по себе не является
независимым повторным выводом всех границ из графа. Приёмку такого
повторного расчёта следует фиксировать отдельно, не приписывая её
форматной проверке preflight. При оценке новых научных результатов
сохраняются фактические полные временные ряды и события LT.

Источник постановки и статус варианта:
[измеренное предложение Nₛ](N0MeasuredCountVariant-20261122.ru.md).
