# ModelArchive: versioned перенос native-модели

Статус: подэтап 5.2, native API для замкнутой физической модели проверен на обоих
серверах и при переносе M40 → Elder-1 через Git. Это не завершение этапа 5 и не
доступность нового контура обучения. Явные порты добавляются в подэтапе 5.3
(ModelBoundary.ru.md); реальный learner adapter ещё нужен.

`Libraries/Nmsdk-PulseLib/Core/TimeLearner/ModelArchive` сохраняет физический граф NPulseNeuron
(Classic и Branch используют этот класс), его параметры/связи и полное замыкание
storage-зависимостей. Первая версия требует единой частоты и замкнутой границы
модели. Версия 2 принимает явно объявленные matrix-double stimulus-порты;
необъявленные внешние связи отклоняются. Адаптер экспорта реального learner
остаётся отдельной работой. Legacy multirate
конфигурации продолжают загружаться прежним способом.

## Содержимое

Корневой kind — `timelearner_model_archive`, schema_version=1 для замкнутой модели,
2 для модели с объявленными портами. Payload содержит:

- `graph`: native XML, имя/класс корня, SHA256 XML и полную semantic identity;
- `class_definitions`: зависимости образов в порядке регистрации, их native
  графы и identities, включая классы, указанные в ClassName selectors для роста;
- `metadata`: implementation_id, state_kind, training, calibration, conversion;
- `dynamic_checkpoint=false`: после Load выполняется native Init/Reset;
- общий SHA256 всего payload через тот же production canonical encoder, что
  используется ModelIdentity. Hash не включает собственное поле sha256.

Native XML сохраняется штатным SaveComponent, включая доступные public/system
parameters/state. Сохранённые динамические величины не обещают продолжения пробы:
при импорте они проходят обычную инициализацию/сброс. Архив физической модели,
parameter overlay и controller checkpoint — разные сущности.

Каждый образ имеет kind `derived_image` либо `native_required`. Производный образ
можно создать из сохранённого базового класса и зарегистрировать через проверяемый
RegisterClassImage. Для native C++-фабрики XML не заменяет исполняемый код: она
должна существовать в runtime, а её эффективный образ сверяется с архивом.
Такие требования также включены в definitions, а не скрыты как неизвестные
зависимости сервера. Неиспользуемые сейчас ClassName selectors сохраняются для
воспроизводимого роста и последующего построения.

## Контракты API

ExportModelArchive требует остановить расчёт и изменения графа на завершённой
границе настройки/этапа. Он проверяет actual identity, сериализацию и native
rehearsal Load/Init до выдачи архива. Дополнительных Calculate из контроллера нет.
Ошибки передаются ModelArchiveError, без изменения bool Build/Reset/Calculate.

ImportModelArchive сначала проверяет schema, общий hash, metadata, каждый XML
и его hash, полный набор обязательных параметров, классы/число/порядок детей,
уникальность и замыкание dependencies. Только затем допускается регистрация
образов и создание модели. После native Load/Init обязательно выполняется
VerifyModelIdentity; instance возвращается вызывающему коду только при совпадении.
Существующие общие prototypes не заменяются и не переписываются.

Отсутствующий обязательный параметр отклоняется даже тогда, когда значение
шаблона случайно совпало бы с потерянным значением. Source state не обязан
отличаться от шаблона и не обязан иметь все L>1. Неизвестная схема или повреждение
не должны превращаться в пустой успешный экспорт.

implementation_id передаётся вызывающим pipeline и должен совпасть при импорте.
API не выводит его автоматически из машины и не заменяет RunManifest/runtime
provenance. В native implementation tests используется явно обозначенный
`native-archive-fixture-v1`; это не фиктивный SHA опубликованного научного прогона.

state_kind различает model_spec, learned_solo и recognition. model_spec обязан
иметь training.status=not_trained. Для learned-состояний обязательны target,
CapturedPerInput references, trainer/normalization и certificate, связанный с
identity состояния. Сохранение supplied certificate ещё не проверяет его
измерительные доказательства — это обязанность контроллера и evidence pipeline.
External stop хранится отдельным статусом, а не переименовывается в Exact.

Calibration содержит протокол, статус и путь к действительной LTZone. Declared
threshold сравнивается с её фактическим параметром; требуется finite, без
произвольного требования положительного порога. Recognition conversion хранит
происхождение solo state и факторы. Полная runtime-интеграция conversion,
calibration и certificate ещё относится к оставшимся этапам.

Регистрация нескольких образов пока не является транзакцией всего storage.
При ошибке после начала регистрации могут остаться новые неизменяемые
неиспользованные образы. Existing prototypes не меняются; полученную модель
использовать нельзя. Такой import storage нужно завершить/отбросить до повтора.
Безопасная очистка отдельных классов и общая transaction-модель ещё требуют
проверки Rdk; не следует компенсировать это заменой уже используемых образов.

## Проверки

Native fixture строит асимметричный нейрон с отдельной LT physics, неодинаковыми
индивидуальными Rs/C, тремя возбуждающими синапсами и PSI. После экспорта новый
процесс, где пользовательских образов ещё нет, импортирует dependencies и граф,
сверяет identity и рассчитывает реальную импульсную пробу. Источник и приёмник
используют штатный current model Environment, одинаковые частоту и начало времени.
Это characterization, а не замена обучения штатной пачкой.

Проверки повреждений включают schema, payload/XML hash, implementation mismatch,
потерянные dependencies, узел, класс, Rs и связь. Для последних случаев hashes
файлов пересчитаны, чтобы проверить собственно граф, а не только контроль суммы.
Несовпадение declared/actual LTZone threshold отклоняется, zero threshold штатно
переносится. Расширение матрицы физических моделей и режимов продолжается.
Качество распознавания и завершение обучения этими implementation tests не
доказываются. Точные результаты и Git artifacts перечислены в Stage05-Progress.
