# Ограниченная Rs-диагностика фактического L22

## Вопрос и статус

Проверить, как изменение сопротивления excitation bank input0 влияет на полный временной отклик сохранённой Classic N4 модели при неизменной геометрии. [Эксперимент запущен](ValidationPlans/M40L22BurstResistanceStudyA1-20261113/STATUS.ru.md), но ещё не завершён и не принят. Предварительные свежая сборка исправленного Console и шесть реальных малых контрольных probes Classic/Branch пройдены; они не подтверждают результат большой модели.

Исходная revision: `3b8a160f2fe6f5ace6aa377f5d42117bcc922bcdd746358ca8d7c34fc67a6b1c`, package7, training=budget_exhausted, certificate=null, L=[22,1,1,1], Ns=[1,1,1,1], Rs=[86,86,86,86] МОм. Сохранить исходные storage, связи, ёмкости, частоту2000 Гц, порог100 и штатную полную пачку. Начальные allocation/input values в configuration не заменяют фактически обученный граф; нужен полный native import и semantic readback.

## Конечная серия

| Проба | Rs input0, МОм | Назначение |
|---|---:|---|
| replay | 86 | Импорт и исходный полный отклик, без edit |
| matched | 86 | Явный no-op после baseline, контроль абсолютного времени |
| resistance-1 | 64.5 | Изменение только разрешённого bank |
| resistance-2 | 43 | То же |
| resistance-3 | 21.5 | То же |

Это заранее объявленные кандидаты, а не утверждение об их физической допустимости. Перед каждым edit native code обязан оценить актуальные per-input bounds для конкретной revision. Отказ bounds/интегратора, импорта или неполная проба прекращают серию с явной причиной; нельзя молча выбросить точку либо считать отказ доказательством PhysicalInfeasible. По результатам этой серии нельзя делать вывод о всех Rs или всех длинах.

Каждая Console-проба запускается production run_job под managed process policy. Сверяются фактический полный граф, применённый Rs, неизменные L/Ns и остальные параметры; полные окна наблюдений, конечность чисел, actual input events, совпадение clocks и byte-equal warm baseline. Replay должен совпасть с исходной baseline matched-пробы. Изменение потенциала, равное нулю, допустимо как отрицательный диагностический результат. Положительного обучения или классификации тестовая обёртка не утверждает.

Runner: `Scripts/StructTrain/TimeLearner/native_burst_resistance_study.py`, вход штатного owned controller — `tests/test_native_burst_resistance_study.py`. До выполнения фиксируются Git control commit, fixture fingerprints, exact source file digests и immutable runtime manifest. Файлы исходной stopped-модели проверяются до и после серии; новый Train, захват новых references и правка порога отсутствуют.

Wall budget каждой пробы и leaf_memory_bytes задаются в declaration до запуска. Допустимы1–1800 s и1–8 GiB; эти бюджеты не являются условиями сходимости. Для большого N4 package255.8MB следует использовать8 GiB native limit, как у исходного Train; память внешнего Python controller и native child резервируется раздельно. Пределы малых N2 fixtures не переносятся автоматически на большой архив.

## Графики и интерпретация

Для каждого фактического Soma channel сохраняются общий вид и увеличенные фрагменты не более901 исходного отсчёта с перекрытием. Не применять прореживание или сглаживание. Рисунки3200px по ширине показывают потенциал, наложенные реальные stimulus timestamps и отдельную дорожку фактического входа. Сравниваемые Rs имеют одну шкалу потенциала для данного Soma channel. Все gallery хранятся как воспроизводимый кэш M40; в Git — сжатые primary, условия, метрики и выбранные рисунки после визуальной проверки.

Глобальный максимум полного отклика выводится только как диагностическая характеристика. Он не является измерением закреплённого импульса, не заменяет CapturedPerInput и не создаёт сертификат синхронизации. Принадлежность слившихся вершин остаётся неоднозначной; раздельная ранняя вершина с хвостовым влиянием допустима по согласованной постановке. Для вывода о принадлежности нужен отдельный действующий measurement protocol, а не выбор самого высокого пика этой серии.

Один training pattern не является матрицей классификации. После обоснованного изменения алгоритма требуются новое холодное обучение, финальная проверка всех входов и отдельные frozen Test всех паттернов с подтверждённым реальным прогоном порогом.
