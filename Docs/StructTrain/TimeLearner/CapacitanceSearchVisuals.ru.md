# Временные отчёты измеренного C-search

Команда `report CASE_stopped_state.json --format capacitance-search --output NEW_M40_CACHE`
строит отчёт всего сохранённого поиска. Реализован также вход completed
`CASE_learned_state.json`; его отдельная render-приёмка пока не выполнена.
Это диагностические training-burst пробы, а не проверка классификации всех
паттернов. Полный многопаттерновый Test с такими же временными графиками остаётся
обязательным пунктом этапа11.

До создания отчёта production-аудитор проверяет пакет, summary, C₀/history,
сопоставление trial IDs и все исходные JSON/CSV. Необходимы завершённые валидные
наблюдения. Отсутствующий CSV или противоречащий пакет не создаёт положительный
отчёт. Затем файлы копируются в portable snapshot и проверяются повторно;
рисунки строятся из этого снимка. Hash каждого исходного файла сохраняется.

Для каждой пробы manifest содержит phase, input IDs, model revision, C witness
и полную карту множителей мембран. Это позволяет увидеть transient физику
кандидата даже после восстановления другого конечного состояния. Роли reference,
candidate, candidate anchor и final verification связаны с конкретными trial IDs,
а не с позицией строки CSV. Неиспользованная роль не обязана присутствовать.

Production probe-set renderer сохраняет исходный временной шаг, все записанные
соматические каналы и фактические входные импульсы. На каждом канале общие Y limits
охватывают весь сравниваемый набор проб; обзорные графики дополнены временными
увеличениями и явно подписанными detail views. SI-интерпретация каналов отдельно
не подтверждена. Наличие PDF/PNG и успешное построение не заменяет прямой просмотр
и не доказывает сходимость или распознавание.

Текущий контроль использует четыре реальные J2 activation histories:
Classic/Branch × N0/N1 при2000Гц. В каждой12 завершённых проб и3 физических
C witnesses, всего48 проб/72 пары trial–soma. Все случаи завершились
budget_exhausted, без Exact и certificate. Исходные данные находятся в evidence
`904a436a555c4424fdf1f99dfd7089613e648529`; они повторно не рассчитываются ради
изображений. Отдельные codec-only cases не создают вымышленных временных рядов.

Render gate объединяет11 schema4 evidence controls и3 report controls.
Отрицательные проверки удаляют первичный CSV и повреждают JSON; обе должны
отклоняться до создания каталога отчёта. Полный кэш PNG/SVG/PDF находится на M40
Data. Git хранит сжатые исходные данные, модели, manifest/метрики и выбранные PNG.
Подтверждение ручного просмотра фиксируется отдельно с точными хешами рисунков;
producer `visual_acceptance_complete=false` остаётся неизменным историческим
артефактом.

Подготовительные ошибки сохранены: visual-v1 неверно предполагал внутренний путь
архива; visual-v2 обнаружил ошибку нового test inventory normalization;
visual-v3 построил48/72, но test ошибочно требовал отсутствующую fallback роль.
Исправления не ослабляют production-аудиторы. Полные SHA и свежий результат
следует читать в текущем статусе и соответствующих Git evidence bundles.
