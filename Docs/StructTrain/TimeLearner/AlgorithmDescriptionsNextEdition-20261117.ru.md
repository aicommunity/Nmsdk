# Следующее дополнение к описаниям алгоритмов

Первая опубликованная Word-редакция16 ноября покрывает проверенное семейство
ControllerVersion2/N1 и остаётся доступной с исходными hashes. Она не является
полным каталогом всех работавших исторических вариантов.

Следующий обязательный пример Classic — N0 из
[фактического порогового опыта14 ноября](ClassicN0ThresholdScientificReport-20261114.ru.md):
TP1/FP4/FN0/TN3, target-spike0.503с после последнего входа0.490с.
Три TN относятся к трём разным foil. Это проходит критерий пользователя
TP≥1/TN≥2 даже при незавершённом Train и плохой разделимости. Не следует
исключать его только потому, что outcome Train invalid_observation/ambiguous.
Полный TrainingCertificate и научная квалификация TP/TN — разные оси.

Дополнительная сверка опубликованных отчётов и receipts записана в
[реестре источников следующей редакции](AlgorithmDescriptionEvidenceReview-20261117.json).
Это семь положительных примеров по правилу пользователя, не семь независимых
алгоритмов или обучений:

| Семейство и топология | Вариант | TP/FP/FN/TN | Существенное ограничение |
|---|---|---|---|
| V2 N1 Classic |native N2 calibration seed|2/0/0/2|один уникальный foil при двух reset policies|
| V2 N1 Branch |native N2 calibration seed|2/0/0/2|один уникальный foil при двух reset policies|
| Classic N0 |stock stopped14 ноября|1/4/0/3|прежний код до N0 geometry fix|
| Branch N1 |stock coupled stopped|1/5/0/2|target0.262с до последнего входа0.490с|
| Branch N1 |Fast terminal7200|1/3/0/4|ранний target; Same-Matrix порог|
| Branch N1 |Fast terminal21600|1/1/0/6|stopped Train; одна модель в восьми порядках|
| Classic historical PhaseA |сохранённая модель6/8|1/2/0/5|legacy family; это replay, не новый cold Train|

Stock, Fast и разные нормализаторы — варианты с общей постановкой, но не
взаимозаменяемые физические модели. Для historical PhaseA требуется отдельно
восстановить смысл legacy параметров и normalization из исходной effective
конфигурации; не назначать ей V2 или предполагаемый N0/N1 по одному имени.
Проверка её16 order/delay условий7 ноября не означает, что эти вмешательства
были проверены в августе. Первоначальные визуальные4/8–6/8 сохраняют свою
дату и область наблюдения. Reported counts и hashes источников проверены
по текущему Git; новая независимая реконструкция всего primary этим не заявлена.

Общий алгоритм следует описать одним семейством N0/N1; различие N0 —
ограниченная целочисленная нормализация Ns с измеренными кандидатами,
квантованием и повторными измерениями, N1 — положительный ограниченный Rs.
Для этого конкретного N0 пример использует прежний PulseLib
7c6c94785af0c83104d348bb3b733ed1f149c8a8 и SDK
74e5d206d4b619fcf81f77f11b54ebec7b8f0f6e, без более позднего N0 geometry fix.
Нельзя приписывать его результат этому исправлению или текущему runtime.
Модель L=[45,1,1,1], Ns1, Rs86M, stock NSPNeuronGen без LTMembrane,
2000Гц. Fixed threshold0.012765548843211696 выбран по Same-Matrix proposal
и подтверждён реальными native spikes. Model revision
35d849faa2aaea5d2620f0fd59d9934c77760b7fde0dd49d3284539f69f68263.

[Проверка64 предъявлений](ClassicN0OrderScientificReport-20261114.ru.md)
сообщает те же1/4/0/3 в каждой из восьми cyclic rotations. Это одна модель,
не восемь независимых обучений. Проверку raw provenance и доступности полного
архива включить в подготовку нового Word-выпуска, не заменять одним текстом
исторического отчёта. Текущий Root Git уже содержит внешний ref к архиву
83917844байт, SHA256
e4f4c50a328919a8f5d7c823e969b26a830ffb190454a5313aa67c130e821541,
и bundle.json612 members, expanded2219424279байт. Старое указание текста
«primary в Git» относится к прежней политике; физический архив теперь
в M40 object store, история кода и результат сохранены.

Branch N0 fixed100 — TP0/FP0/FN1/TN7 — не проходит включение. Новые короткие
N4/N1 обеих топологий TP1/FP6/FN0/TN1 тоже не проходят. Их нужно оставить
отрицательными контролями, не записывать в таблицу рабочих примеров.

Для Classic нового выпуска нужны отдельная N0 строка общей таблицы,
подробный пример с фактическими временами всех восьми паттернов и различия
версий кода/физики; для Branch сохранить общую часть N0/N1 без выдуманного
положительного Branch N0 примера. Формулы остаются редактируемыми OMML,
блок-схема и UML отражают фактически описанную версию. После изменения
источников обязательны новая неизменяемая публикация, render_docx.py и
просмотр всех страниц. Выпуск можно выполнить на границе экспериментального
этапа; научные задания не должны ждать вёрстку.
