# Ограниченный поиск соседней длины при нормализации числом синапсов

## Основание

В завершённом Classic Train на M40 при L=241 измерены отклонения амплитуды
−0,0011187873 при Ns=12 и +0,0003371598 при Ns=13. Более близкое значение
остаётся вне исходного допуска 0,00001. Между соседними целыми Ns нет
следующего целого кандидата. Это основание для исследования соседней длины,
но не доказательство физической недостижимости или сходимости.

## Явная политика

Новый необязательный параметр search `maximum_n0_length_proposals` задаёт
конечное число предложений по длине на один обучаемый вход. Значение по
умолчанию в C++ равно нулю; в JSON нулевое значение опускается. Старые
конфигурации сохраняют порядок поиска. Положительное значение допустимо
только при нормализации N0 и не превышает `maximum_candidates_per_input`.
Для первого сравнения предлагается 4, отдельным явно записанным фактором.

Лимит общий для всех контекстов ёмкости и проходов одного входа.
Улучшение, повторный визит и невалидное наблюдение лимит не возобновляют.
Общие лимиты проб, изменений и кандидатов сохраняются. Научные обозначения
Classic/Branch и M не меняются; N0 обозначает нормализацию числом синапсов.

```text
сгруппировать измерения по полной геометрии, физике и контексту ёмкости
оставить измеренные точки, удовлетворяющие временному допуску
проверить разброс имеющихся обязательных повторов
найти соседние целые Ns с разными знаками амплитудной ошибки
сравнить реально измеренные концы всех сохранённых локальных интервалов
выбрать лучший конец по существующему рангу ошибок
предложить ближайшую ещё не проверенную допустимую длину с его Ns
при равном расстоянии сначала рассмотреть меньшую длину
построить и измерить новый кандидат штатным путём
перед Exact заново проверить все входы конечной модели
```

Глобальная монотонность не предполагается. Геометрия Branch проходит
существующую проверку допустимости точек подключения и общего кабеля.
Неизмеренная оценка не подставляется вместо амплитуды или времени пика.
Параметры опорного входа, CapturedPerInput, допуски, Rdk lifecycle и
штатная пачка импульсов остаются прежними. Политика не выполняет дополнительных
вложенных Calculate и не меняет storage-образы.

## Доказательства и открытая приёмка

Добавлены проверки контроллера на две стороны по длине после целочисленного
интервала, ухудшение первого соседа, повреждение финального отклика,
немонотонные локальные интервалы и невалидные бюджеты. Добавлены проверки
JSON и Python связывания объявленной политики с наблюдаемой конфигурацией.
Это контролируемые данные для проверки решений, не результат нейронной модели.

На M40 скомпилированы полные production-реализации контроллера: корень
`49c4f08cc4cbc4675ce3e6dba160b931ab18d556`, PulseLib
`f52713ce3d807c9a0abd8655caff82daba400519`. Прошли все155 C++-случаев
и33 Python-проверки трёх модулей деклараций. Исполняемый файл и исходники
не изменялись между запуском и проверкой. Сведения о загруженных библиотеках
собраны production runner. Все37 файлов доказательств независимо восстановлены;
[компактная ссылка на внешний архив](../../../Reports/StructTrain/TimeLearner/Progress-20261124/N0-production-controls-ax15.json).

Первоначальная остановка до запуска тестов сохранена: упрощённый разбор TEST
ошибочно насчитал152 вместо155. Штатный анализатор учитывает четыре
раскрытия ATTEMPT_INVALID_BUDGET_TEST, исключая тело определения макроса;
его полный список совпал с объявленным списком executable. Исходная сборка
сохранена и не повторялась ради этой коррекции инвентаризации.

До приёмки требуются проверки общего лимита между контекстами C/проходами,
повторов и восстановления,
полный native export/replay и сравнение реальных моделей при политике 0/4.
Пока новая политика не рекомендована для основных научных серий.
Увеличение бюджета кандидатов — отдельный экспериментальный фактор.
