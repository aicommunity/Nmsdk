## Условия и шесть фаз

Очередь ждёт конкретные исходные процессы и обе задачи планировщика,
закрытие всех групп, успешный полный аудит с одной выполненной проверкой
без пропусков и правильный тип двухпроходного свидетельства. Допустим
только `budget_exhausted` без завершённой границы. При другом исходе
записывается `not_dispatched`: нужен соответствующий экспорт завершённой
либо иначе остановленной модели. Шаблонный Test не запускается.

Последовательность:

1. Подготовить полную фактическую остановленную модель и исходную восьмёрку.
2. Реально рассчитать восемь реакций при исходном пороге.
3. Проверить полные первичные наблюдения и неизменность модели.
4. Предложить порог на этой же восьмёрке по существующей процедуре.
5. Реально повторить восьмёрку с выбранным порогом.
6. Выполнить независимое чтение и полный аудит повторных наблюдений.

Результат подбора обозначается как калибровка на той же матрице,
не независимый Test. Отсутствие допустимого промежутка для целевого
порога сохраняется как `nonseparable`; реальный повтор выбранного порога
тогда не объявляется выполненным. Прежний исход обучения не превращается
в Exact из-за успешного распознавания.

Небольшой шаблон M40 с SHA256
`810cd728d2001432d1c89d6413bebd518fbeeb54812da13e8f73c075c83e00cc`
использован только как список исходных восьми паттернов и окон.
Целевые интервалы сверены с настоящим Windows-заданием. Его прежняя модель
не переносится: физика и обученные параметры берутся только из проверенного
Windows-пакета. Сам шаблон включён в Git-настройки новой очереди.

## Выполнение и пределы приёмки

Подготовка и аудит выполняются раздельными процессами с пределом16 GiB.
Native-расчёт использует прежний `prepared_diagnostic`, штатную блокировку
машины и Windows Job с16 GiB и7200 с. Очередь ожидает не более86400 с;
отдельная фаза ограничена9000 с, вся задача планировщика —36 часами.
Перед фазой требуется24 GiB свободного диска; при native-расчёте
контролируются остаток8 GiB и предел нового вывода16 GiB.

Малый диспетчер native-фазы наблюдается по PID и времени рождения и имеет
стеночный предел; отдельного жёсткого предела его памяти нет. Он не декодирует
большую историю; соответствующие операции выполняются отдельными ограниченными
процессами. Это ограничение нынешнего Windows-диспетчера, не полная приёмка
общей инфраструктуры плана. Вложенный native Job и его фактическое закрытие
проверяются перед следующей фазой.
