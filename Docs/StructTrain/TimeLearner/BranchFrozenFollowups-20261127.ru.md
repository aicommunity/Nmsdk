# Branch: объявление направленных проверок фиксированной модели

## Задача и исходное состояние

Проверить ранее полученную Branch-модель на новых отвлекающих паттернах
и при изменении момента третьего импульса. Это измерение свойств уже
обученного состояния, без нового Train и без изменения порога. Оно
дополняет проверку семи положений четвёртого импульса; сходимость
обучения по результату этих испытаний не устанавливается.

Используется исходная DATA-модель
`007f82de139e7c4e3bfdbc7a8351b306003dcd8eeb39854e66b3ec39ee8b6970`,
θ=0,0858575482028458 в собственных единицах модели. Комплект94 файлов
ранее независимо восстановлен; источник указан в
`Reports/StructTrain/TimeLearner/CountFrozenEvaluation-20261123/`
`windows-DATA-primary-external-archive.json`. Модель и её преобразование
для распознавания заново не создаются. Используется2000 Гц, M=4;
импульсы цели поступают через0,80,240 и480 мс от первого импульса.

## Последовательность

1. На .14 непосредственно загрузить исходную DATA и проверить все8
   исходных реакций. Сравнить полные записанные сигналы, времена
   входов и выходные события с первоначальными наблюдениями. При
   расхождении остановить переход к новым протоколам.
2. Выполнить27 предъявлений новой сетки: три межимпульсных интервала
   масштабируются независимо на1/2,1 и3/2. Цель повторяется как
   положительный контроль; ранее использованные отвлекающие паттерны
   исключаются штатным построителем. Метки определяются точным
   совпадением паттерна, заранее; более широкий класс целей не вводится.
3. Выполнить8 предъявлений штатного протокола сдвига третьего импульса.
   Первый, второй и четвёртый импульсы сохраняются. Проверять реальное
   время выхода относительно третьего и четвёртого входных импульсов.
4. Независимо восстановить полные данные и фактически загруженные
   байты; подготовить временные графики сомы с наложенными входными
   импульсами для всех43 наблюдений и провести визуальный просмотр.

В новых предъявлениях используется reset-per-trial. Окно не обрезается
после первого ответа; поздние выходы учитываются. Порог и model revision
сохраняются. Идентичные повторы не считаются независимыми обучениями.
Числа TP/FP/FN/TN заранее не задаются. Ранний выход до завершающего
импульса нельзя считать доказательством распознавания полной пачки.

## Исполнение и ограничения

Задание: `TimeLearner-Branch-followups-fr260` на Windows .14.
Управляющий каталог:
`C:/Projects/TimeLearnerWorker/controls/branch-frozen-followups-fr260`.
Координатор и декларация протоколов записаны в отдельный Git до запуска;
конкретные designs и fingerprints фиксируются дополнительным commit
до первой пробы. Для родительского задания предусмотрено18 ч;
для трёх native-стадий —4,6 и3 ч, по8 ГиБ памяти. Перед каждой стадией
проверяется наличие10 ГиБ свободной RAM и16 ГиБ на диске.

SDK .14: корень `cde0b851a3c156b3c31e6dbadc27b320de9a3884`,
PulseLib `5f36aebb9bfdef747c04319f3ab065be199de67c`, Rdk
`26129caa576a6b727ee2d76718e9fe9b2674e811`.
Используются штатные `prepared_physical_evaluation`,
`prepared_physical_study` и полный компаратор реакций.

Задание запущено; результаты новых предъявлений пока неизвестны.
Первоначальный координаторfr260 завершил восемь реакций с точным
сохранением исходных ответов, затем остановился на передаче типа
доказательства в preparer. Исправление
[общего пути архивного повтора](ArchivedRepeatProof-20261127.ru.md)
проверено13 тестами и реальным Windows CLI. Восемь проб не повторялись.

Направленные предъявления продолжаются в задании
`TimeLearner-Branch-followups-fr293`, управляющий каталог
`C:/Projects/TimeLearnerWorker/controls/branch-frozen-followups-fr293`.
У namespace новые идентификаторы attempts; содержательные условия,
модель, порог и оба condition fingerprint совпали с исходным объявлением.
Для координатора предусмотрено12 ч, для научных стадий —6 и3 ч.
Подтверждён старт нового native-процесса сетки27 предъявлений.
Результат всей сетки ещё не известен; восемь сдвигов третьего импульса
запланированы после неё.

Сравнение с Classic будет сравнением двух конкретных обученных моделей,
а не доказательством эффекта одной лишь топологии. Тяжёлые первичные
данные и полные графики подлежат хранению во внешнем архиве M40;
в корневом Git сохраняются документы и компактные проверенные ссылки.
