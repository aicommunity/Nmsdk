Pulse88 encoder6 использует ссылочный `QJsonValueRef` правой стороны `result["schema_version"]`, а создание отсутствующего `base_schema_version` на левой стороне меняет ТУ ЖЕ структуру до чтения ref. Это positional-index alias, не невалидный физический параметр и не необходимость bool→number conversion. [Qt primary QJsonObject implementation](https://raw.githubusercontent.com/qt/qtbase/5.15/src/corelib/serialization/qjsonobject.cpp) вставляет отсутствующий key; [Qt primary QJsonValueRef implementation](https://raw.githubusercontent.com/qt/qtbase/5.15/src/corelib/serialization/qjsonvalue.cpp) читает indexed value при assignment. Source hazard подтверждён этим порядком; точный плохой runtime value устанавливается по сохранённому raw, а не объявляется здесь угаданным bool/string.

Tiny baseline patch материализует `const QJsonValue baseSchema=result.value("schema_version")` ДО insertion и использует его в прежней range validation/assignment. Decoder/Number/Count не меняются, никакой coercion, schema weakening или expect relaxation нет. Schemas1–4 и value-safe recovery5 code paths прежние. Model/storage/Rdk lifecycle, Build/Reset/Calculate bool semantics, native clocks, targets/N−1/tolerances/алгоритмы не изменяются.

## Почему archive23 мог пройти

Baseline archive1/group replay декодирует native source/model spec/context/CSV, но не `CompositeInitialConfiguration`. `SaveCompositeBoundary` пишет initial configuration object как есть. Поэтому actual six archive bundles могут иметь корректные проверенные raw/group DATA и одновременно неверный numeric envelope в `initial-configuration.json`. Успех group assertions не разрешает strict cold6/autostart/package import. Existing raw JSON не чинится на месте; full-data/independent readers должны отразить отказ и отделить его от физической валидности waveform. Дальнейший corrected export/rerun имеет новый source pin и новую evidence identity.

На future Pulse800/b287 тот же cold6 site сохранён и cold7 повторяет его; recovery5 уже использует owning `.value`. RootE11 `App/NeuroModelerConsole/TimeLearnerCompositeArtifacts.h::WrapNativeCompositeExecution` повторяет hazard для execution3. Они исправляются следующими ОТДЕЛЬНЫМИ commits после обычного merge baseline fix, без включения новых Train5/token/package code в baselineA4. Другой найденный production counter `internal[key]=internal[key].toInt()+1` материализует scalar до assignment и не является этим proxy hazard; test hard_last_frame=hard_first_frame обновляет существующие keys и не вставляет новый key. Общая замена всех `operator[]` не предлагается.
