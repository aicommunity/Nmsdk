## Исправление смысла финальной проверки

Ранее по полю `terminal_event.fresh_all_input_verification=false` было ошибочно
написано, что финальный проход всех входов не завершён. В действительности
сохранены все4 финальные группы155–158, каждая из6 первичных проб.
Их байты сверены с execution manifest. Повторно использован полный аудит,
который ранее независимо проверил геометрию, выбор вершины, потребление
измерения и первичные трассы каждой из этих групп. Все4 группы завершены
на revision`2f47ac9e86552fa9f80f82e2a4a4d6fd554074a916a0e85529ce0d3d3ab47723`, epoch72.

|Вход|Временная ошибка, мс|Амплитудная ошибка|Временной допуск|Амплитудный допуск|
|---|---:|---:|---|---|
|0|+3,5|−0,001066649|выполнен|не выполнен|
|1|−5,5|−0,002245119|выполнен|не выполнен|
|2|−0,5|−0,002128092|выполнен|не выполнен|
|3, опорный|0|0|выполнен|выполнен|

Потенциал — в условных единицах модели. Для каждого входа сохранена
собственная исходная амплитуда; цель не заменялась общей амплитудой.
Амплитудный допуск10⁻⁵, относительный0, временной0,02с.
Следовательно, полный проход дал отрицательный результат по амплитуде.
После него запрещён следующий проход из-за `maximum_sweeps=1`:
код `BoundedTrainingSession::FinishVerification` сохраняет исход
`budget_exhausted / maximum_sweeps_exhausted`, не Exact.

Затем отдельная terminal selection восстановила выбранное измеренное состояние
одной транзакцией: epoch73 и revision
`b3286d53576e57d37b753b244b8e6261a97086f034bc6cf7efbd610410ff9b23`.
В `NativeTrainingServiceTerminal.cpp` флаг свежей проверки этой транзакции
явно задаётся false, сертификат отсутствует, перенос исторических измерений
на новую эпоху запрещён. Поэтому одновременно верны два разных утверждения:
исторический финальный проход выполнен; свежий сертификат после terminal
selection не создан. Старые данные и их hashes не переписаны.

## Измеренная область поиска

У каждого обучаемого входа24 новых кандидата и отдельное повторное предъявление
выбранного состояния. Среди кандидатов, выполнивших временной допуск,
наибольшие исследованные Nₛ равны12,10,8 для входов0,1,2 соответственно.
Все их амплитудные остатки отрицательны. Соседи13,11,9 не измерены.
Нет измеренной пары соседних целых чисел по разные стороны цели.
Поэтому ни квантизация, ни недостижимость исходного допуска не доказаны.
Достижение предела128 также не является причиной этой остановки.

В коде `PrioritizeN0Neighbors` на геометрию выделяется конечный запас
предложений, расходуемый при постановке в очередь. Улучшение ошибки его
не пополняет. Измеренный прогноз и обычные соседи используют один запас.
После его исчерпания продолжается конечный общий перебор длин и нормализаторов.
Это ограничение порядка поиска, а не установленная ошибка сходимости:
алгоритм честно вернул остановку по бюджету. Увеличивать бюджет или менять
математическую цель действующих опытов ради более удачного исхода нельзя.

Дальнейшая исследовательская проверка — ближайшие непроверенные числа и
соседние длины около уже измеренного допустимого по времени состояния,
с явно объявленным распределением прежнего общего бюджета. Любой такой
кандидат потребует новой действительной пробы; прогноз не заменит измерение.
Это гипотеза улучшения эффективности, не дополнительное требование8/8
и не основание объявить нынешний отрицательный исход ошибкой реализации.

## Отдельные командные контексты

Новый модуль `publications.plot_recorded_count_search` строит только реальные
точки из привязанной к источникам проекции поиска. Он группирует все длины,
все сопротивления и числа остальных банков, затем выбирает для каждого входа
контекст с наибольшим измеренным Nₛ. Отсутствующие точки не дорисовываются,
кривые не интерполируются, решения контроллера и сертификат не переоцениваются.

Для показанных трёх контекстов командные длины равны соответственно:
вход0 —239/201/121/1; вход1 —202/201/121/1; вход2 —122/122/121/1.
Более ранние одиночные измерения Nₛ=1 при201/201/121/1 или121/121/121/1
сохраняются отдельными группами. Изменение размера банка Branch способно
изменить соседнюю точку подключения. Нельзя смешивать такие команды и
называть полученную линию однофакторной физической зависимостью.
Равенство командных векторов само по себе также не доказывает равенства
всего физического дерева; это ограничение явно записано в projection.json.
