# Лимит реального времени нативной оценки Linux DATA

Базовая восьмёрка Classic q3 на Elder остановлена по жёсткому пределу
3600с: фактическое время3600,269с. Сохранились семь файлов проб из восьми,
но нет полного успешного исполнения и полной runtime provenance.
Это ошибка выделения времени выполнению; положительный итог восьмёрки
не допускается. Из этих данных не делается вывод о FN или разделимости.
Весь процесс и его Python-владелец закрыты; исходные файлы сохранены.
[Точная причина, ограничения и binding](Progress-20261125/Elder-q3-native-eight-wall-budget-failure-eg22.json).

Предшествовавшее холодное обучение и его исход budget_exhausted не меняются.
Сохраняется фактическая модель b1430c16b95da83567a01dcd314dbec36c92d2f6965308119ba66b0e14d0f2fc,
длины241;201;121;1, числа синапсов14;11;8;1. Порог исходной характеристики100;
частота2000Гц, сброс перед каждой пробой, окно2с. Train не повторяется.

Схема1 описания Linux DATA сохраняет прежние3600с и прежний fingerprint.
Новая схема2 требует явное native_evaluation_wall_seconds. Один общий
разбор формирует лимит Native, лимит Python-фазы и срок резервирования:
последние два больше первого на400 и600с. Это запас на аудит и закрытие,
а не изменение модельного времени. Число должно быть целым от1 до36000;
bool, дробь, нечисловое и неизвестная схема отклоняются до дорогой работы.
Для нового отдельного Test заявляются5400с Native,5800с Python и6000с lease.
Уже завершённая попытка и её лимиты не переписываются.

Общий сериализатор условий записывает фактический предел. Физический
граф, данные, критерий, порог и бюджеты самого обучения остаются прежними.
Схема2 не связана с ControllerVersion компонента. Изменение касается
оболочки исполнения исходной и подтверждающей восьмёрок.

Адресная серверная проверка использует реальную DATA2, прежнее отклонённое
задание и фактическую condition исходной попытки. Она проверяет сохранение
прежнего fingerprint, изменение только оси execution_policy и отказ
повреждённых лимитов/схем, одновременно сохраняя четыре проверки run_id.
Восемь проверок ещё требуют серверного исполнения; локально выполняется
только синтаксический разбор. Новая попытка распознавания до их приёмки
не запускается. Приёмка тестов не заменяет полного нативного Test.

Для последующих замеров скорости сохранить SIGTERM-стек: остановка попала
в ModelRevisionObserver::Read через CheckNativeRecognitionHold и ACalculate.
Это отдельная выборка стека, а не профиль затрат и не доказательство дефекта.
Проверку неизменности модели не ослаблять ради ускорения без отдельной
проверки фактических изменений параметров, связей и структуры.
