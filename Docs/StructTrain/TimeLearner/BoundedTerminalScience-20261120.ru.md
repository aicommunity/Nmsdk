# Ограниченный холодный Classic N4: следующий научный прогон

## Задача и отличие от прежней попытки

После приёмки исправления конечного экспорта получить фактически сохранённую
модель Classic N4/N1 и измерить её отклики на все восемь паттернов Phase A.
Прежняя попытка Classic остановилась по внешнему timeout до записи модели;
её результат и первичные данные сохраняются отдельно. Новый опыт не является
воспроизведением прежнего бюджета84600с и не заменяет продолжающийся Branch A2.

Сначала должны завершиться108 native-проверок Linux и16 реальных Console
вариантов на том же SDK: cold Train, конечный пакет, перенос и frozen evaluation.
Наличие записи модели само по себе не заменяет итоговый аудит исполнения.
До закрытия этих проверок новый научный Train не запускается.

## Результат и последующая проверка

1. Сохранить фактический completed или stopped package, события, измеренную
   историю, полные первичные данные и окончательный execution marker.
   Проверить закрытие всех принадлежащих заданию процессов.
2. Для completed сохранить соответствующий сертификат. При budget_exhausted
   оставить диагностический статус; отсутствие общего сертификата не скрывать.
   Ошибка исполнения или отсутствие модели запрещает Test под видом обученной.
3. Проверить перенос действительного конечного графа, профилей, индивидуальных
   параметров, связей и частоты. Историческое состояние поиска и шаблон
   не подставлять вместо фактической сохранённой модели.
4. Выполнить полные окна восьми исходных паттернов, сохраняя модель и порог.
   Для диагностического выбора порога использовать максимум всего отклика;
   выбранный кандидат обязательно проверить отдельным реальным native Test.
   Same-Matrix калибровку маркировать явно; независимый Test ею не подменять.
5. Опубликовать TP/FN/FP/TN, времена выходных событий, validity, причины
   остановки и границы вывода. Работающий пример для описания алгоритма
   требует TP≥1 и TN≥2;8/8 не является условием успешного опыта.
6. Построить читаемые временные графики сомы всех восьми паттернов с
   фактическими входными импульсами, выходными событиями и выбранным порогом.
   Сохранить обзор и необходимые увеличения. Первичные данные, модели и
   изображения — во внешнем архиве M40; в Git только компактные ссылки.

Дополнительный запас wall time не означает гарантии сохранения или сходимости.
Если возникает конкретный дефект, сохранять исход неудачной попытки и исправлять
его адресно. Новый полный отчёт оформлять по применимым ГОСТ согласно
[правилам научных отчётов](ScientificReportRules.ru.md).
