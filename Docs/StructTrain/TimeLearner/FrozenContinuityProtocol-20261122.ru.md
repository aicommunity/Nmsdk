# Проверка интервалов предъявления и сохранения динамики

Постановка подготовлена для уже полученных Classic/Branch DATA-моделей с M=4.
Новые длительные обучения не прерываются. Данный документ задаёт следующий
опыт; численного результата этого опыта пока нет. Новая ветка Python-кода
требует серверных проверок и настоящих нативных запусков перед приёмкой.

Для Windows подготовлен `prepared_physical_study`: он проверяет завершённый
восьмипаттерновый DATA-повтор, повторно проверяет первичные данные через
производственный аудит и использует общие постановки новой сетки либо
`frozen_physical_iti_study.declare_job`. Для каждой попытки сохраняет точные
условия и их fingerprint, фиксирует модель и порог, использует общую
блокировку worker и ограниченный процесс Windows. После выполнения нужны
полный аудит и контроль реакций. В сетке новых паттернов целевой контроль
сравнивается с исходным DATA-повтором целиком. При изменении интервалов
такое сравнение неприменимо даже к первой пробе: изменяются окно и правило
покрытия. Первая проба со сбросом сравнивается между парными опытами с
одинаковым интервалом и разными последующими сбросами. Изменения остальных
реакций являются предметом опыта и не запрещаются сравнением с прежними.
Новые файлы: `prepared_physical_study.py` и `tests/test_actual_physical_study.py`.
Подготовка проверена на реальном новом Windows DATA-источнике:6/6 без
ошибок и пропусков, группа закрыта за30,36с. Проверены неизменность модели
и порога, новая сетка, независимость fingerprint от ID попытки, общий
целочисленный расчёт интервалов и отказ при повреждённом либо подменённом
источнике. Проверен root30e07bb4a0e753e1b88fb72bd8009e270ffdf973;
последующая поправка сравнения разных окон не входит в эту проверку подготовки.
[Квитанция](../../../Reports/StructTrain/TimeLearner/MatchedClassicCountTraining-20261121/windows-frozen-study-preparation-validation.json).
Нативные опыты с интервалами ещё предстоят. Матрица26 новых отвлекающих
паттернов и одного прежнего target зафиксирована до исполнения и поставлена
в очередь с фиксированной моделью364de821 и порогом0,06760345444849075.
[Подготовленная постановка и живой владелец очереди](../../../Reports/StructTrain/TimeLearner/MatchedClassicCountTraining-20261121/windows-frozen-new-foil-queue.json).

## Сохраняемые условия

Используются полные модели и фиксированные пороги из проверенных исходных
восьмистрочных матриц. Исходные manifest, модель, результаты DATA roundtrip
и все файлы проверяет общий `frozen_physical_source`. Нового обучения,
изменения порога, сопротивлений, числа синапсов или физики нет. Исход обучения
прежних моделей остаётся budget_exhausted; новый опыт не создаёт Exact.

Сохраняются восемь различных исходных паттернов, их метки и правило оценки.
Метка target определяется явно, а не положением строки. Каждый из восьми
циклических порядков является отдельным нативным заданием с новой начальной
инициализацией. Целевой паттерн должен побывать на всех восьми позициях.
Между порядками динамика не переносится.

## Два независимо изменяемых фактора

| Фактор | Уровни |
|---|---|
| Длительность окна до следующей пробы | 2с; короткое окно |
| Динамика после первой пробы | сброс перед каждой пробой; сохранение |

Первая проба любого задания явно сбрасывается. В коротком варианте длительность
равна округлённой вверх до нативного такта сумме максимального времени последнего
входного импульса исходной матрицы и0,2с. Для нынешней матрицы это0,69с.
Это заранее заданное правило по входам, а не выбор по выходным откликам.
Одинаковая длительность применяется к первым семи пробам одного порядка.
Последняя проба включает не менее2с записи после последнего входного импульса;
её окно поэтому длиннее2с. На границе добавлен запас в один нативный такт,
а фактическая длина тихого хвоста проверяется по записанным timestamps.

Длительность окна не выдаётся за измеренный интервал между предъявлениями.
Фактические интервалы первых входных импульсов сохраняются отдельно. Следующее
окно должно начинаться ровно через один нативный такт после предыдущего:
ни один промежуток динамики не остаётся без наблюдения.

Сброс и полнота покрытия — разные свойства. Полностью записанный поток может
иметь сбросы на границах. Сохранение динамики само по себе не разрешает
пропустить запись межпробного промежутка.

## Выполнение и проверка

`frozen_physical_iti_study.declare_job` формирует отдельную декларацию каждой
комбинации. `condition` использует общий ConditionSpec: имя попытки и путь
неизменного executable не входят в научную identity, а порядок, длительность,
политика сброса, модель, порог и существенный код входят.
`run_case` использует существующий `native_pipeline_worker.run_job`, полный
DATA-import и общий scorer. Внешний владелец резервирует ресурсы и ограничивает
Python-контроллер; дочерний нативный процесс выполняется с явной process policy.
В работающий Train эти декларации не подставляются.

Новая проверка Python preflight записывает `evaluation_presentation` для
потока или сохранения динамики. Это декларация обязательных проверок,
а не свидетельство состоявшегося нативного расчёта. Старые preserve-manifest
сохраняют свой прежний preflight через явный исторический read-only адаптер;
они не превращаются в новые исполнения. Обычные старые reset/per-trial
задания сохраняют прежнюю форму preflight. Неизвестные политики отвергаются.

Проверки полного managed Train→calibration→Test контура остаются отдельной
задачей: его текущий `managed_declaration` ещё ограничивает coverage.
Готовность отдельного frozen DATA-пути не означает готовности всех запускателей.

Последовательность по исходникам SDKbd9ea23a/PulseLib1c8d0112: импорт,
Build/Init/Reset модели выполняются до начала последовательности. На границе
пробы AssignNativeTarget перестраивает и инициализирует только DatasetMatrix;
его генератор сбрасывается перед каждой подачей. Физический нейрон сбрасывается
в NativeRecognitionTrialExecutor только при reset_per_trial. Завершение окна
останавливает генератор, сохраняя динамику нейрона. Console вызывает один
родительский Calculate на такт, затем продвигает время. Экспорт замороженного
состояния проверяет hold и возвращает сохранённый пакет. Это проверка кода;
она не заменяет полный нативный опыт с изменяющимися паттернами.

## Измерения и пределы вывода

Для каждой пробы сохраняются полные отсчёты сомы, действительные входные
импульсы, LT potential/output и времена событий. Общий scorer проверяет
полноту, отсутствие пропусков окон, численную валидность, целостность списка
проб и неизменность модели до/после. Сохраняются TP/FP/FN/TN и события,
возникшие до первого импульса текущей пробы. Вклад прежнего паттерна в такое
событие автоматически не приписывается одному источнику: требуется просмотр
полной временной последовательности.

Для всех паттернов необходимы читаемые графики сомы с реальными входами
и выходными событиями. Отдельный общий график последовательности должен
показывать переходы между пробами; локальный вид не должен скрывать хвост
предыдущего отклика. Короткое окно и расширенный конечный хвост маркируются
явно. Полные первичные данные и рисунки сохраняются во внешнем архиве M40.

Сначала проверяются подготовка условий и полный нативный путь; затем
выполняется матрица порядков и длительностей. Изменение классификации
принимается как измеренный результат, включая отрицательный. Повтор одной
детерминированной модели не считается новым независимым обучением.
