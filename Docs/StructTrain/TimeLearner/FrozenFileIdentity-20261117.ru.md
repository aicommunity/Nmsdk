# Идентичность файла при замороженном чтении

При проверке нового cold-budget CLI на локальной Windows обнаружен общий
дефект collector_provenance: lstat(path) и CRT fstat(opened_handle) возвращали
разные представления file ID одного файла. Исходная проверка сравнивала эти
два результата напрямую и отвергала неизменённый реальный файл с причиной
collector_file_changed_during_read. Размер payload и его JSON не были причиной.

Исправление сделано в общем владельце `_frozen` / `frozen_digest`, а не обходом
в новом preparer. На POSIX сохраняется прежнее прямое сравнение. На Windows:

1. Path/lstat сравнивается с path/lstat до и после чтения.
2. Дескриптор/fstat сравнивается с тем же дескриптором до и после чтения.
3. Связь открытого дескриптора с текущим именем файла проверяется дополнительным
   native open/fstat в начале и конце. Сравниваются два fstat, не маскированные
   младшие биты inode.
4. Сохраняются canonical/no-symlink правила, regular-file и size bounds,
   точный размер прочитанных bytes и фактический SHA256. Дескрипторы закрываются.

Четыре проверки выполняют реальные операции filesystem/handles: чтение против
потокового digest, другой файл с теми же bytes, запись в источник на границе
чтения и отказ размера/неканонического пути. Для управляемой гонки меняется
реальный файл; native stat и read не подменяются. Вместе с шестью cold-budget
контрактами локальная Windows прошла10/10. Linux-регрессия и приёмка общего
проверяющего на серверных артефактах ещё не выполнены из-за отключённого VPN.
Это не численный эксперимент и не проверка физической модели.
