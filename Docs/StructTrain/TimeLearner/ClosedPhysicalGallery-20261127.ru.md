# Подготовка галерей завершённых проверок распознавания

`Scripts/StructTrain/TimeLearner/closed_physical_gallery.py` формирует входы
существующего построителя временных графиков из завершённых архивных
проверок DATA-модели. Модуль принимает отрицательные научные результаты
наравне с положительными; полнота и валидность наблюдений обязательны.
Нового расчёта модели, изменения порога или повторного обучения нет.

План версии1 содержит список `cases`. Для каждого случая явно указываются:

- уникальный `id` и `scale_group` для общего масштаба сравниваемых рисунков;
- `native_directory` с исходными job/execution/evaluation и наблюдениями;
- `bundle` как `file_record` проверенного описания первичного архива;
- внешний объект `primary`, префикс членов архива и запись `source_catalog`;
- `title_mode=pattern` либо `fourth_time`: второй вариант использует
  реальное время четвёртого импульса каждой отдельной пробы.

Команда подготовки:

```text
python -B -m Scripts.StructTrain.TimeLearner.closed_physical_gallery --plan PLAN.json --output REPORT
```

Затем `REPORT/sources.json` передаётся неизменённому модулю
`publications.plot_algorithm_trials`. Все исполняемые средства находятся
в корневом пакете; план является декларацией данных, а не историческим
скриптом в Bin/PulseLib/Docs.

Перед копированием наблюдений заново выполняется производственный
`audit_execution('physical-model-evaluate', ...)`. Метки и классификации
берутся из этого полного аудита. Job, execution, evaluation и каждое
наблюдение проверяются по конкретным членам первичного архива. Повторный
ID, пропуск наблюдения, несовпадающая контрольная сумма, неполное окно
или изменение источника прерывают подготовку. После копирования байты
проверяются снова. Число иллюстрируемых наблюдений ограничено256,
как у существующего построителя.

Выходы — точные копии наблюдений, полные аудиты, `sources.json` и
`preparation.json`. Успешная подготовка не подтверждает владение исходным
процессом, не означает готовности рисунков или их визуальной проверки.
Владение и завершение исходного запуска устанавливаются связанным
принятым каталогом; отрисовка, независимое восстановление отчёта и
просмотр PNG остаются отдельными шагами.

Для приёмки предусмотрены пять проверок на фактической архивной восьмёрке:
успешная подготовка с сохранением меток и событий, повтор ID, неизвестная
схема, подмена суммы члена и отсутствие реального наблюдения. Локальное
чтение кода не заменяет их выполнение на сервере. При создании этого
документа серверная приёмка ещё не завершена.
