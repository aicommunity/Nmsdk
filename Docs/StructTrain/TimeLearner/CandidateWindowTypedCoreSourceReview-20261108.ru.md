# Source review typed Train5 core

На08.11.2026 рассмотрены Pulse `376bee62adadb3306afec72634665aab0a612b01` и Root `6579c58386a0b77dd79926c5ff3b1bb93b84a884`, отдельные private branches `codex/timelearner-candidate-window-train`. Это проверка исходников. Компиляция,24 новых controls и совокупный408 cohort ещё не выполнены; изменения не приняты как работоспособный новый путь обучения.

Проверенная область: typed admission `BoundedTrainingSession`/`FinalVerificationSession`, opaque all-input `CandidateWindowReferenceSet`, native admission callback, certificate3 и исходные тестовые сценарии. По рассмотренной цепочке блокирующего дефекта не найдено. Математические search/rank/scalar residual helpers сохраняют прежний путь; механическое выделение validators A0 остаётся отдельной предпосылкой со своей A/B runtime-проверкой.

Schema5 Search/Final проходят отдельные Arm/ConsumeCandidateWindow. Старые scalar/composite entry points отказывают новому протоколу. Перед использованием сопоставляются исходные target values, первоначальная model revision/epoch, полный protocol, IDs и semantic proof всех references. Создание публичного JSON или арифметических seed не создаёт live admission. Native callback проверяет текущую принадлежность физической модели, полный candidate binding, исходный reference family и фактические бюджеты до/после proposal replay.

Перед all-input certificate проверяются ранее принятые Final measurements на всё ещё действующую graph/source/lease принадлежность. Их собственный измерительный deadline проверяется при consume; более поздняя проверка другого входа не переносит deadline прежней пробы. Certificate3 связывает конечную модель с protocol/attempt/final-run/recipe/measurement-instance и остатками каждого входа. Encoder проверяет protocol binding и полноту доказательств. Прежний model export/summary отказывает protocol5 вместо молчаливого сохранения неполного состояния.

Новые fixtures используют реальные native components и observations; фиксированные параметры и SyncTolerance=.2 обозначены как инженерный тест. Отдельная проверка штатного .02 должна давать OutsideTolerance. Standalone fixed N1 не объявляется проверкой native N1 domain orchestration. Записанный actor journal и certificate companion не являются package6 или завершённым Train→Test. До серверной проверки никаких фактических результатов этих fixtures нет.

Следующая отдельная работа — Service/Session composition. Здесь недостаточно заменить `==4` на `4||5`: semantic attempt задаётся до actor creation; warm continuation сохраняет оригинальные references и retained primary ledger; references становятся consumed только атомарно после all-N closure; service export не переписывает уже связанные proof2 поля policy/attempt/budget; lifecycle dispatch получает отдельную ветвь5. После этого нужны model package6, summary7 и production CLI controls с реальными архивами. Новый controller не становится рекомендуемым до выполнения зависимостей и матрицы утверждённого плана.

Контур callback/cancellation248 на baseline17db/88, mechanical A/B, функциональный candidate-window cohort, reader/roundtrip и научная матрица имеют разную область приёмки. Успех одного не заменяет остальные. CapturedPerInput, опорный N−1, амплитудные допуски и правило закреплённого импульса сохраняются.

Следующие source-only chunks рассмотрены отдельно: actor allN prepare/commit Pulse `741eeab87a6dcf16f08ba2215bc065385df7fff7` / Root `84505432b107680a970319fe108778c9ab0c46ac`; cold7 declaration после исправления Pulse `76445bd3184d4eeecae91c6a57913c425675d751` / Root `149f6e02bea3e4fcabf08ff6248313130a197116`. Private Prepare выполняет fallible allocation/read/replay/fresh checks, Commit публикует shared immutable value и selected flags без callback/allocation. Commit не является самостоятельным stale validator: будущий owning service обязан закончить свои allocating операции до final Prepare/check и выполнить непрерываемую публикацию. Cross-owner service transaction ещё не подключена.

При review cold7 найден реальный semantic gap: проверка валидности исходного protocol не запрещала последующей реконструкции молча заменить допустимые имена/перестановку входов, stimulus IDs, origin и pattern hash стандартными значениями. Исправление требует exact reconstructed protocol/input windows либо выдаёт `candidate_window_initial_protocol_not_representable`. Это ограничение данного configured codec, а не запрет named protocols низкого уровня. Шесть новых source controls включают именно валидные перестановки/имена/origin/hash и допустимый checkpoint reset. Новая schema сохраняет прежние1–6 значения, CLI/defaults/service5 не включаются. Суммарный planned inventory442 и все новые controls остаются без runtime-приёмки.

Следующий source chunk Service5 рассмотрен на Pulse `800f92ae1f9e0133cefc0ccfe36abc3d8c99727f` / Root `311a714d38da1e37a457c8a88cd709ee01885a73`. Он добавляет explicit dispatch5 и lifecycle/Build ветви с сохранением прежнего4, semantic attempt до создания actor, cold7, shared atomic allN, typed core и warm adoption полной retained history. Service archive2 сохраняет фактически связанные record2 caps/attempts, исходные references/P0/C0 и реальные primary; прежний schema1 exporter не переименовывается в новый. После fallible allN Prepare дополнительно проверяется deadline именно последней closing group; старые references проверяются на fresh identity без продления их собственных измерительных deadline через последующие пробы. Search/ranking/residual math не меняется.26 новых native controls и planned470 inventory пока не запускались. Package6/runtime2/summary7/Console dispatch остаются отдельными необходимыми шагами.

До приёмки Service5 открыт отдельный source audit live authority: manual actor с закрытой ещё не consumed пробой может пережить чужой Begin→Finished в CalculateMode1 при той же модели и Need=true. Текущий owner guard сравнивает service actor только в Capturing/Searching. Root `f74b9fbf9ece38668396c21fa569d688f595bb05` содержит два ожидаемых negative и два positive own-next-group controls, без production fix. Проверки отделяют историческую DATA пригодность от права старого live Consume и явно исключают истечение group/attempt budgets, смену graph/source/lifecycle/Need как альтернативные причины. Это подтверждённая source-цепочка и подготовленный reproducer, а не runtime-результат; до запуска и исправления нельзя объявлять полный ownership-контракт Service5 принятым. Работающий M40 baseline b6d0/88 этими private changes не обновляется.

Отдельное исправление подготовлено в Pulse `353f17baf505edf92ff39fe40422b9dcea023045` / Root `85ca858ae3c8ec39aaa527211868facb17208ad9`, ветка `codex/timelearner-manual-control-lifetime`. При последующем просмотре полного caller path найден оставшийся source gap в353: публичный `NativeTrainingService::InterruptComposite` возвращается при `!composite` до вызова `CaptureCompositeInterrupt`, где расположена новая invalidation. Поэтому обещание design «interrupt инвалидирует manual authority даже без stored service actor» ещё не выполнено этим commit. Требуются отдельная invalidation перед ранним return и реальные Classic/Branch controls без смены Need/model/UM lifetime/deadline. Это ограничение публичного service API; его нельзя выдавать за доказанную ошибку всех learner Reset/Default hooks: они имеют собственные guards/reset, а lifecycle dispatcher вызывает InterruptComposite только для plan4/5. Исправление и runtime этой границы пока не приняты;353/85ca сохраняются как исходная точка с известным ограничением.

Точечная source-правка Pulse `b2878e565febe20a4ba7c9c64536d6e66f672626` рассмотрена отдельно: добавлен только `InvalidateOwnerControlLifetime()` при входе публичного InterruptComposite, до раннего return; callback/generation/delivery ветви не менялись. Граница runtime остаётся непроверенной. Для адресной проверки исследуется существующий штатный путь stopped package5 import: plan4 и portable proof восстанавливаются без live composite, затем создаётся новый manual actor. Проверка должна использовать реальные публичные lifecycle/bind/import пути, без const_cast, test hooks и изменения диспетчеризации ради теста.

На Root `4c06292e1e764d754b7c88823f616f43d82058d9` рассмотрены два подготовленных Classic/Branch controls именно этого публичного пути. Исторический DATA archive отдельно остаётся декодируемым. Source inventory теперь20 адресных controls, TU335 literal tests; никаких фактических PASS или приёмки общей матрицы этим не добавлено. Рабочий baseline M40 b6d0/88 остаётся прежним.

Перед будущим запуском найдено ещё два инфраструктурных расхождения веток. На f74/4c отсутствуют maintained `native_acceptance_worker.py` и `native_preparation.py`; worker нельзя запускать из чужого Tool tree против SDK, поскольку он проверяет собственное расположение и source closure. Кроме того, в actual4c сохранены старые15s двух service deadline helpers; проверенный fixture17db не является его ancestor. Полный regression с ними повторил бы уже установленную ошибку постановки. Нужны отдельные `--no-ff` объединения: сначала17db с шестью test-only изменениями60s/реальный sleep61s, затем db2 metadata worker. Production Pulse800/b287 при этом сохраняется; фактические C++ test diffs нужно явно записать, а не объявлять такое объединение чисто metadata-only. Исходные f74/4c остаются неизменными для истории. После объединений требуются новые реальные inventories/canonical specs и frozen source preflight; принятие исходного248 не является приёмкой новых descendants.
