# Измеримый контроль сохранения динамики между пробами

Это проверка нативного механизма предъявления, не новое обучение и не
оценка точности классификации. Она нужна перед расширением production-runner
на continuous stream и перед интерпретацией опытов с изменённым ITI.

Реальные компоненты обеих топологий создаются через штатный storage и
Environment. Используется существующий fixture полного DATA-переноса:
явно остановленная до первой обучающей пробы граница, стандартный профиль,
два асимметричных входа, нормализация числом синапсов. Не создаются фиктивные
references, сертификаты и обученные веса. Из этой границы штатно получены
модель распознавания и её полный DATA-образ.

Две одинаковые копии DATA-модели рассчитываются общим scheduler один раз
за такт при2000 либо20000Гц. Для каждой копии выполняются две полные пачки
M=2 с ISI0.01/0.08с. Первая проба обеих копий сбрасывает физическую динамику.
Окно заканчивается через четыре нативных шага после конца последнего импульса;
остаточный отклик должен быть измеримо отличен от исходного состояния.
Длинный тихий хвост здесь специально не используется: он устранил бы
различие и сделал контроль нечувствительным к ошибочному сбросу.

Во второй пробе первая копия опять использует `reset_per_trial`, вторая —
`preserve_neuron_dynamics`. Ожидаемые проверки:

1. Первые волны обеих копий совпадают при одинаковом физическом состоянии.
2. В конце первой пробы остаётся отклик больше1e−6 относительно фактически
   измеренного исходного состояния. Нулевой rest-state не предполагается.
3. Первый отсчёт второй reset-пробы возвращается к тому же исходному состоянию.
4. Первый отсчёт preserve-пробы сохраняет измеримый остаточный отклик; в этот
   момент новый вход ещё не поступил. Разность с reset-контролем больше1e−6.
5. Окна следуют по единой нативной сетке без пропущенного шага.
6. Все отсчёты сомы совпадают с независимым чтением реальных компонентов после
   единственного родительского Calculate; фактические стимулы и события
   проверяет штатный `ValidateNativeRecognitionObservation`.
7. Полный DATA-образ остаётся неизменным; контроллер обучения idle,
   `IsNeedToTrain=false`, сертификат по этим наблюдениям не создаётся.

Четыре случая размещены в
`Tests/Integration/Libraries/Test_PulseLib_PhysicalModelData.cpp`, suite
`NativePhysicalDynamicsContinuity`. Вместе с ними повторно проверяется
существующий suite `NativePhysicalModelData`, поскольку fixture теперь
принимает частоту с сохранением прежних defaults2000Гц.

Успешная проверка этого уровня ещё не подтверждает полный continuous runner,
учёт событий между окнами при произвольном ITI или научное распознавание.
Для этих требований остаются отдельные production-протокол и реальные
проверки моделей. Ниже зафиксирован фактический серверный результат этого
ограниченного контроля.
