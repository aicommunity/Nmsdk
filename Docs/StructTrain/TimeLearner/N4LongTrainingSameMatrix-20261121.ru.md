# M=4: реакции сохранённых моделей после длительного обучения

M — число импульсов целевого паттерна; в этой постановке ему равно число
обучаемых входов. Исторические N4 в именах файлов/job ID означают здесь M=4.
Топология указывается отдельно: Classic или Branch; N0/N1 в коде — режимы
нормализации числом синапсов/сопротивлением соответственно.

Статус: промежуточная запись рабочего журнала21.11.2026; исходный материал
для следующего издания двух научных отчётов. Полные штатные аудиты обеих
Branch-моделей завершены; внешние архивы с проверкой восстановления и
визуальная приёмка продолжаются.
Этапы1–12 плана этим результатом не закрываются.

## 1 Постановка

Исследованы три фактически экспортированные модели после остановленного
обучения с нормализацией сопротивлением (N1) и разрешённой поправкой ёмкости
(C-trim). На каждую модель поданы все восемь паттернов PhaseA: один целевой
(`target`) и семь отвлекающих (`foil`). Использованы2000Гц, сброс динамики
перед каждой пробой (`reset_per_trial`) и полное
окно2с с4001 отсчётом. История обучения сохранена целиком. Test импортирует
фактический конечный граф; шаблонный граф вместо него не применяется.

Train завершился по времени либо по числу проходов с `budget_exhausted`.
Сертификата Exact нет. Проверяемый вопрос — присутствуют ли полезные
детектирующие свойства у получившейся модели. Критерий включения семейства
в описание работающих алгоритмов: фактические TP≥1 и TN≥2, с указанием
протокола и всех ложных ответов.

## 2 Выбор и проверка порога

Сначала записаны полные реакции при унаследованном пороге100: все три модели
молчат, TP0/FN1/FP0/TN7. Из этих неспайковых трасс получены максимумы реального
`LTZone.Potential` за всё окно. Для предложения порога использовано правило

\[
M_T=\max_t U_{LT,T}(t),\qquad
M_- = \max\{M_F:M_F<M_T\},\qquad
\theta=(M_T+M_-)/2. \tag{1}
\]

После выбора порога выполнены новые настоящие нативные прогоны всех восьми
паттернов. Ответы ниже подсчитаны по записанным временам LT-событий. Потенциалы
после появления спайка могут измениться из-за обратной связи: например,
Windows target-максимум изменился с0.10112859892319448 до0.10074983443469898.
Поэтому предлагаемый порог подтверждается реальным повторным Test.

TP означает правильное обнаружение целевого паттерна, FN — его пропуск,
FP — ложное срабатывание на отвлекающий паттерн, TN — правильное отклонение
отвлекающего паттерна.

Обе Branch-модели дали ложный ответ только на `phasea-row-4`. У Classic ложные

на Elder, через0.483с на M40 и через0.4825с на Windows.

Это диагностический подбор и проверка порога **на той же матрице**
(`Historical Same-Matrix`). Матрица
использована и при выборе порога, и при его проверке. Независимый Test,
устойчивость к перестановкам/ITI и сходимость обучения этой таблицей не
подтверждаются. Размерности потенциала сохраняются как единицы модели:
обозначение мВ без отдельной проверки не применяется.

## 3 Достоверность и ограничения

Первичные наблюдения сопоставлены с artifact SHA256 в native execution.
Проверены восемь уникальных ID, метки, полнота, числовая конечность каналов,
равенство model_before/model_after и согласованность count/timestamps.
Полный независимый штатный аудит эффективного графа, исходной истории,
временной сетки, измерений и метрик выполняется отдельно.

В Classic расчёт всех проб закончился, но `AwaitNativeRuntimeCapture` не получил
ack. Native ready-файл существует и совпадает с PID/start_ticks зарегистрированной
группы. Записи мониторинга показывают разрыв44.80796с, перекрывающий10-секундное
окно подтверждения; первый последующий monitor наступил через33.02103с после
ready. Точная причина задержки самого monitor ещё не установлена. Исходная
ошибка процесса и `incomplete_loaded_files` сохранены; данные Classic пока
имеют это ограничение подтверждения происхождения. Автоматического повышения результата до
валидного исполнения не делается.

На M40 полный штатный аудит завершён отдельным16ГиБ процессом за1913.30с.
На Windows
первая попытка аудита остановилась до child по нехватке свободной физической
памяти для заявленного16ГиБ лимита. Новая отдельная попытка имеет12ГиБ и
2ГиБ запаса; используются те же полные исходники и те же проверки. Она
завершилась за1639.53с. Оба аудита подтвердили TP1/FN0/FP1/TN6, полную
объявленную матрицу, сохранённую историю исходного обучения и неизменность
входных файлов и модели. Нового обучения или повторного подбора порога
для этих аудитов не проводилось. Полная независимая проверка происхождения
каждого решения прежнего поиска этим переносимым аудитом не заявляется.

Экспорт полной физической модели Classic (physical DATA) из существующей

## 4 Следующие научные проверки

1. Завершить штатные аудиты и построить временные графики всех сом для
   всех восьми паттернов с реальным входом и LT-событиями; сохранить полные
   окна и увеличения без прореживания.
2. Экспортировать и проверить physical DATA конечных recognition-моделей;
   подтвердить совпадение графа, параметров и полного отклика при новом импорте.
3. Зафиксировать модель и порог, проверить порядок с target в каждой позиции
   и изменение ITI. Reset-per-trial и непрерывный поток исследовать отдельно.
4. По свежим одиночным обучающим пробам разобрать остатки N1 на допустимых Rs.
   Отдельно учитывать ограничение `native_no_crossing_domain_v1`: оно не
   является доказательством физической недостижимости амплитудной цели.
   Влияние нормализации на оставшийся ложный ответ требует реального вмешательства.
5. После проверенных артефактов обновить соответствующие семейства в документах
   Classic/Branch. Новый содержательный выпуск оформить по действующим правилам
   ГОСТ; опубликованную четвёртую редакцию только ради оформления не переделывать.

Тяжёлые модели и трассы пока находятся на workers; внешние архивы этой серии
ещё готовятся. Их удаление не разрешается до проверенного восстановления.
В корневом Git сохранены только компактные
[первичные readback](../../../Reports/StructTrain/TimeLearner/PreparedDiagnostics-20261121/actual-threshold-primary-readbacks.json),
[квитанции исполнения](../../../Reports/StructTrain/TimeLearner/PreparedDiagnostics-20261121/actual-threshold-execution-closures.json)
и [диагностика capture](../../../Reports/StructTrain/TimeLearner/PreparedDiagnostics-20261121/elder-runtime-capture-failure.json).
