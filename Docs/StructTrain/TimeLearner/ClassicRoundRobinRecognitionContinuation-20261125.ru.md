# Проверка распознавания после циклического Classic-обучения

Постановка25.11.2026, до получения исхода нового обучения
`classic-candidate-round-robin-q3-cold-elder-dv31`. Продолжение
[циклического поиска](ClassicCandidateRoundRobin-20261125.ru.md),
не новое обучение и не изменение работающего runtime.

## Источник модели и порядок действий

Использовать только фактическое состояние этого Train после завершения
его управляющего процесса, всех дочерних групп и отдельного полного аудита
`classic-q3-full-primary-audit-and-DATA-elder-dy4`. Проверить исходный job
`c990d360d49d8d73fc5fb2f620f750d671d3c305796bc94e4921aae238a56b5c`,
revision модели, исход обучения, completed_boundary, исходный пакет и
контрольную сумму DATA-проекции. Эти значения разрешается получить только
из завершённых первичных данных; заранее их не задавать. Связь записать
до первой новой нативной операции. Ошибка полного аудита останавливает
продолжение; повторного Train нет.

1. Штатно импортировать DATA1 и выполнить явное тождественное преобразование
   solo → recognition DATA2: mode=identity, resistance_bounds=[],
   reference_amplitudes=[]. Проверить полный физический roundtrip штатным
   production `prepared_physical_export`, не ручным XML overlay.
2. Выполнить восемь полных frozen-реакций при исходном пороге100.
3. По реально записанному потенциалу пороговой зоны предложить один порог:
   середину между максимумом цели и наибольшим строго меньшим максимумом
   отвлекающего паттерна. Использовать production
   `physical_threshold_proposal`. Отвлекающий максимум выше цели остаётся
   ошибкой разделимости. Отсутствие представимой середины — явный
   отрицательный результат, без альтернативной подгонки.
4. Штатно создать DATA3 с этим единственным порогом и заново предъявить
   все восемь паттернов. TP/FP/FN/TN получить из действительных выходных
   событий, не из сравнения старых максимумов с новым числом.

Оба предъявления выполняет общий `native_pipeline_worker.run_job` с
file-source transport, проверкой полных первичных наблюдений и frozen-графа.
Модель из прежнего успешного опыта вместо результата этого Train запрещена.

M=4; начальная задержка10мс, частота2000Гц, длительность каждой пробы2с,

правило порога и пределы исполнения включены в условия.

## Исполнение и ограничения

Новый контроллер — корневой модуль
`Scripts/StructTrain/TimeLearner/linux_physical_recognition_sequence.py`.
Его immutable source размещается отдельно от actor и SDK работающего Train.
Супервизор ожидает точный PID/start_ticks/boot_id/uid полного аудита.
Вычислительный слот до завершения предшественников не резервируется.

Для каждой фазы — отдельная ограниченная группа Python-владельца и заранее
известная группа нативного потомка. Импорт/смена порога:1ГиБ контроллер,
8ГиБ native, общая штатная резервация9ГиБ. Предъявление/анализ:4ГиБ
контроллер,8ГиБ native, общая резервация12ГиБ. Предел native3600с,
всей фазы4000с; диск контролируется супервизором. Слот освобождается
только после подтверждённого закрытия всей группы владельца и потомка.
Нет автоматического повтора неуспешной нативной операции.

Это Historical Same-Matrix calibration, не независимый Test. Никакие
сертификаты Train или калибровки DATA-файлу не приписываются. Остановка
обучения по бюджету, если она произойдёт, сохраняется как исход Train
независимо от будущих счётчиков распознавания. Получение1TP и хотя бы2TN
позволит включить пример в научное описание, но не докажет Exact.

Приёмка новой последовательности требует действительного исполнения
всех необходимых фаз на Elder, закрытых групп, полных наблюдений,
независимого восстановления первичных данных и временных рисунков
для всех паттернов. На момент постановки она ещё не выполнена.
Полная архивация Train, проверочных фаз и иллюстраций остаётся отдельным
обязательным действием; тяжёлые данные в корневой Git не добавлять.
