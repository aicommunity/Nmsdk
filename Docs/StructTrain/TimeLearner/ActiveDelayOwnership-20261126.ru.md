# Delay во время нативной пробы: проверка владельца и реального отклика

Подготовлены восемь дополнительных случаев в штатном
`Test_PulseLib_DelayOwnership.cpp`, вместе с прежними восемнадцатью.
Серверная компиляция и результаты ещё не получены. Нового дефекта
производственного кода или исправления алгоритма этот документ пока
не утверждает.

## Контракт Rdk

В `UVProperty::SetData` обычная связь `SetPointer` делает присваивание
приёмнику пустой операцией: значение по-прежнему берётся из источника.
Это отличается от делегирования через `ExternalDataSource`; наличие
последнего нельзя вывести из одного `IsConnected`. Связанное свойство
не нужно отсоединять ради применения желаемого значения. В тестах
используется настоящий механизм `SetPointer`, как в компонентах Rdk.

Возврат `Build/Reset/Calculate` не используется как критерий качества;
расчёт выполняет только штатный scheduler корневого UNet. Изменение
Delay через обычное свойство при владении нативной пробой должно быть
отклонено; присваивание прежнего значения допустимо. Проверяется реальный
отклик после такого вызова, а не только факт исключения setter.

## Новые реальные случаи

| Топологии | Частота и размерность | Проверка |
|---|---|---|
|Classic / Branch|2000 Гц, M=2|Две полные пробы; во второй после начала выборки отклоняется изменение Delay. Сравниваются все сомные отсчёты, времена и реальные входы|
|Classic / Branch|20000 Гц, M=4|Та же проверка с другой частотой и размерностью; модель строится сразу на нужной частоте|
|Classic / Branch|2000 Гц, M=2|Связанный дочерний Delay=5 с достаточен для окна 0,2 с. Проба должна завершиться, источник и сама связь сохраняются|
|Classic / Branch|2000 Гц, M=2|Связанный дочерний Delay=0,05 с недостаточен для окна. Завершённое наблюдение недопустимо; источник не переписывается, связь сохраняется|

Для сравниваемых проб используются неизменные полные storage-профили,
эффективная модель, физические связи и исходный паттерн. Каждая проба
подготавливается через штатный NativeProbeExecutor с нативным сбросом
физического поддерева. Разрешённый допуск сравнения сигналов и относительных
времён — 10⁻¹²; он не является изменением допусков обучения.

Проверка не требует успешного выделения закреплённой вершины в короткой
контрольной модели: полнота записи физического отклика, локальная
валидность пика и сертификат обучения имеют разные значения. Для
неподдерживаемого связанного окна требуется отрицательный исход.
Ни распознавание, ни обучение эти случаи не сертифицируют.

Сохраняются полные production-пакеты наблюдений и первичные временные
кривые, точный состав 26 GTest ID, JUnit, команды компиляции/линковки,
реальные библиотеки, runtime и доказательство закрытия принадлежащих
проверке процессов. Новый executable использует отдельный каталог;
исходники, библиотеки и runtime текущих научных опытов не меняются.
