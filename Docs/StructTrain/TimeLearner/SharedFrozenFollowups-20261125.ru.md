# Общий протокол продолжений фиксированных физических моделей

Рабочая запись реализации от 25 ноября 2026 года. Общая математическая
постановка Linux и Windows теперь формируется одним сериализатором;
существующие численные задания и runtime не изменялись.

## 1 Назначение и общая часть

После фактической подтверждающей оценки модель и порог фиксируются.
Выполняются полный повтор исходных восьми реакций, направленный сдвиг
третьего импульса и новые отвлекающие паттерны. Для допуска к последним
двум стадиям нужны закрытый полный повтор и сравнение всех восьми
записанных реакций с источником. Это не новое обучение и не новая
калибровка. Исход остановленного по бюджету Train сохраняется.

Функция condition в frozen_physical_condition.py вынесена из прежнего
Linux-контроллера отдельно от изменения протокола. Порядок сериализации
и математические условия существующих Linux-случаев сохранены.
prepared_physical_study.py использует тот же frozen_third_pulse_study,
а затем штатные подготовку, запуск и аудит реального физического задания.
При анализе времени передаётся настоящий evaluation.json; подписанное
задание запуска не подменяется декларацией наблюдений.

## 2 Явные ограничения запуска

Версия 1 декларации сохраняет прежние 4 ГиБ и 7200 с. Версия 2 требует
execution_limits с целочисленными memory_bytes и maximum_wall_seconds.
Новые Windows-продолжения объявляют 8 ГиБ, 5400 с для восьми сдвигов и
18000 с для сетки отвлекающих паттернов. Память и время входят в условие
как для матрицы, так и для каждого её случая; значения не скрываются
в отдельном worker. Лимиты старых работающих заданий не обновляются.

windows_frozen_physical_followups.py — поддерживаемый контроллер
корневого пакета. Он связывает запрос с полным Git SHA, точным запросом
предшественника, PID, временем создания процесса и путём Python.
Исполняемый worker не генерируется. Контроллер ждёт конкретный полный
повтор; ошибка предшественника завершает цепочку без автоматического
повтора Native или Train. Нужны неизменные проверенные файлы протокола,
ресурсы и общий lock штатного Windows backend. Между фазами проверяются
отмена и общий бюджет.

## 3 Выполненные проверки

На M40, на восстановленном настоящем физическом состоянии, пройдены
24 адресных проверки без пропусков. Проверены общая постановка третьего
импульса, фактические времена, ограничения, источники, представление
порогового параметра и использование настоящего evaluation.json.
С прежней реализацией совпали три fingerprints матриц и все 43 case
fingerprints при прежних значениях лимитов. Отдельный положительный
контроль изменения памяти меняет fingerprints всех затронутых случаев.
Это проверка генерации и анализа условий, а не новые реакции нейрона.

На Windows отдельно пройдены четыре проверки схемы запроса. Для cap8
зарегистрирован контроллер из корня 0a1586ca467e72ddc54eaec311bc5dd81d1bceb5;
он ожидает текущий фактический повтор и не использует прежние завершённые
с ошибкой ea19/ec3/ec5/ec11. Продолжение cap24 требует отдельной новой
регистрации; его автоматический запуск здесь не объявляется.

## 4 Отчётность без изменения наблюдений

render_physical_data_evaluation теперь допускает явный параметр
include_native_tiles=False. Полное окно и детали измеренных максимумов
сохраняются, а многочисленные дополнительные временные плитки можно
не строить. Выход этой настройки имеет версию схемы 2; метаданные
прежнего вызова по умолчанию остаются прежними. Производный набор
для отображения не меняет исходные наблюдения, их validity или метрики.

Путь реально выполнен на полном cap8: все 32 пары «паттерн–сома» и
восемь пороговых сигналов, 622 индексированных файла; исходные hashes,
производственные метрики и времена до/после совпали. Внешний комплект
из 666 файлов независимо восстановлен; все hashes пересчитаны.
Просмотрены 16 русских сомных PNG и восемь пороговых обзоров. Приёмка
всех остальных технических увеличений этим не заявляется.

Для будущей русской галереи plot_algorithm_trials.py поясняет в основном
тексте реальные сигналы, количество сом, моменты входов и наличие выходов;
под рисунком оставляет короткое индивидуальное название. Проверены
восемь содержательных пояснений и восемь различных кратких подписей
на фактических данных. Прежние опубликованные рисунки и DOCX не изменены.

Эта работа закрывает конкретные подзадачи этапов 2, 3, 9–12, но не
является общей приёмкой этих этапов и не подтверждает научный результат
ещё выполняющихся продолжений.
