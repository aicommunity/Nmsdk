# Ограниченный контроль предшествующего паттерна

Цель — проверить зависимость распознавания от предыдущего паттерна,
которую не разделяют циклические повороты исходной матрицы. Это часть
контролей порядка и непрерывного потока этапа11; успешные8/8 не требуются.

Первый источник — уже экспортированная и проверенная Branch-модель
`007f82de139e7c4e3bfdbc7a8351b306003dcd8eeb39854e66b3ec39ee8b6970`,
порог0,0858575482028458. Исходные8 DATA-реакций воспроизвелись точно.
Текущая новая сетка27 паттернов должна сначала завершиться и закрыть процессы.
Её runtime не изменяется. Для нового Python-кода используется отдельное
Git-дерево; новый C++ SDK для этого протокола не требуется.

## Условия и объём

На каждый из7 исходных отвлекающих паттернов объявляются две политики.
Каждый case — новый нативный процесс и2 последовательные пробы:

1. Полный сброс, один исходный отвлекающий паттерн, длительность0,69с.
2. Исходная цель с полным сбросом либо сохранённой динамикой.

Всего14 условий и28 наблюдений. M остаётся числом импульсов одного
паттерна, здесь4; два паттерна в последовательности не переименовывают его
в M=2 или M=8. Модель, частота, порог, сами паттерны и длительности
одинаковы между парными условиями. Контроллер обучения не включается.
Первые входы соседних проб, вероятно, разделяет0,6905с; это ожидаемая
проверяемая величина существующего нативного генератора, не подставленный факт.
Фактические входы и выходы сохраняются.

Заключительное наблюдение включает не менее2с после последнего входа цели.
Все границы рассчитываются в целых отсчётах частоты исходной модели.
Непрерывное наблюдение охватывает весь поток и хвост. Основные прогоны
используют короткий такт; длинный такт поддерживается декларацией, но
автоматическое расширение матрицы не предусмотрено.

Исходные паттерны уже участвовали в калибровке: это новая проверка протокола,
а не независимые новые отвлекающие паттерны. Повторы цели не являются
независимыми обучениями. Порог не подбирается по этим наблюдениям.

## Приёмка матрицы

Проверить закрытие каждого процесса, полный набор28 наблюдений,
неизменность модели/порога и фактическое применение reset policy.
Первый отвлекающий отклик должен совпасть между двумя политиками одного
предшественника: в обоих случаях проба начинается со сброса. Целевые отклики
в reset-условиях должны совпасть между всеми предшественниками после
совмещения по фактическому входу. Несовпадение — диагностический отказ
протокола сброса, не научный PASS; исходные данные сохраняются.

Для этих сравнений используются одинаковые новые окна. Старую исходную
двухсекундную запись нельзя считать равной новому более длинному окну
по одному общему фрагменту. Целевые preserve-отклики могут различаться —
это проверяемый результат, а не причина отвергать наблюдение.

Показывать TP/FP/FN/TN по каждому условию, все реальные выходные события,
в том числе до последнего входа текущего паттерна, и полные временные
графики всех28 реакций. Отрицательные и silent-результаты сохраняются.
Тяжёлые первичные данные и рисунки идут во внешний архив M40; в Git —
спецификация, код, компактные метрики и ссылки. Не вводить распространение
ошибок через bool Build/Reset/Calculate и не менять общие storage-прототипы.
