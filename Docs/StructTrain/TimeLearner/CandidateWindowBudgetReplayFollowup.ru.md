# STEP2 archive2: исторический primary-byte budget

Статус: исправление исходников после root source review, без compile/numeric/runtime acceptance. Исторические pins Root `80b2571ec396577bfda9efc3c2a836ab89cda050` / Pulse `feb5fa5d4d6ee3c649905e638fc4914d63a5e260` сохраняются неизменными. Исправление не меняет criterion, windows, targets, tolerances, физику или lifecycle; не включает Train5/service/CLI/defaults.

Обнаруженный дефект: record2 проверял individual bytes ≤ record cap и стабильность caps внутри semantic attempt, но накопленные bytes проверялись только против CURRENT archive cap. После warm с более высоким лимитом можно было согласованно занизить старые caps ниже суммы прежних records, сохранив каждый individual record допустимым, пересчитать proof2/document IDs и пройти replay. Наличие cap в content hash само по себе не проверяет accounting.

Shared production `CheckCandidateWindowPrimaryHistory` вызывается явным archive2 encoder и decoder. На каждой retained record boundary он проверяет отдельно сумму bytes данного semantic attempt и cumulative prefix ВСЕЙ сохранённой истории против cap этого record. Финальная история также обязана помещаться в current cap. Поэтому later higher cap не легализует прежний перерасход, и later attempt обязан оплатить retained original refs. Old archive1/codec1 paths не вызывают новую проверку.

Порядок имеет явный ограниченный смысл: `records` — producer append/retained-ledger order. Attempt blocks не переоткрываются, actual issued group ordinal внутри блока возрастает (gaps допустимы при retained subset), current observed block последний; unobserved empty warm current attempt допустим с нулевыми counters. Candidate появляется только после всех selected original reference groups. Не вводится сравнение global model/wall clocks across imported warm attempts: clocks могут начинаться заново. Replay проверяет объявленную retained историю, а не доказывает реальный cross-process execution order; фактический порядок входит в provenance/receipt. При pruning prefix — нижняя граница исторического расхода, не полный execution-history attestation.

Шесть новых `NativeCandidateWindowBudgetReplay.*` cases используют настоящие allN N+2 refs attempt A и actual warm constructor. Основной отрицательный fixture — refs-only A → empty warm B с большим current cap; все A caps и semantic proofs/document hash согласованно переписаны так, что `max(recordBytes) < capA < sum(ABytes)`. Candidate proposals отсутствуют и не могут скрыть нужную проверку. Другой real fixture A refs → B candidate → empty C проверяет B cap ниже retained A history при допустимой собственной сумме B. Дополнительные controls: positive empty-warm replay, current cap ниже retained bytes, reverse issued order и candidate-before-reference order. Counterexample не подменяет native traces/physics.

Actual bundles: `classic-window-budget-refs-A-empty-B` и `classic-window-budget-A-B-empty-C`, production archive2 index/records/все CSV, current actual after-model/source boundary. Численно локально tests не выполняются. Будущий gate обязан сохранить отрицательные данные/receipt, если проверки или физические preconditions не пройдут.
