# Проверка composite206: состояние 08.11.2026

Это техническая приёмка service/archive, а не научная классификация и не
завершение этапов 5–8. Принятый M40 core143 остаётся отдельным результатом.

Следующая cancellation248 на Rootcc23/Pulse88 собрана на M40/ASan, но
остановилась после13 случаев:12 passed,1 failed,235 не запускались.
Обе первоначальные PreparedStop проверки прошли. Ошибка
`BranchLastCompositeSinkCannotCrossRealGroupDeadline`: last-final callback
не был достигнут (`slept=false`,elapsed0), хотя итоговый outcome BudgetExhausted.
Это не PASS post-callback deadline: нужна диагностика фазы более раннего
исчерпания бюджета. Все14 групп закрыты; отрицательный primary
`eaa4350defa80c932ececaafa58b5373112fc75d` опубликован и
[независимо проверен](CompositeCancellationM40A1IndependentVerification.json):
502 members,3687 Git source files,13 фактических JUnit cases, ASan-loaded files,
неизменность трёх старых runtime и327 ресурсов. Скопированный inventory.root540 отдельно отмечен как
metadata errata, actual source closure — cc23/88; raw bytes не переписываются.

Последняя Elder A3 завершилась после 12 passed / одной failed проверки;
193 случая не запускались. Обнаружена потеря уведомления об отменённой пробе
при остановке из onPrepared. Исправление доставки результатов подготовлено
в Root `cc23d9fff8baba3c5dca89f5e2a0131d7ad1c237` / Pulse
`88ea9c7ab3583da601b1f01ec84bf6f122875a34`; полная проверка248 ещё не выполнена.
Шесть новых архивных экспортов ещё не получены. M40 ASan на предыдущем pin
тоже завершился с ошибкой:143 passed,1 failed,62 не запускались. Полный
отрицательный результат независимо проверен до изменения кэша. Это уточняет
исторические попытки ниже.

## Elder A1: сохранённый отрицательный результат

Исходники Root `d433acf6ed250e7ed5da781970b3963a51c56a26`, Pulse
`f925e37247bb987980fce80da47831a1c31d04c9`. Сборка и линковка завершены;
из 206 объявленных случаев выполнены 112: 111 успешных, один неуспешный,
94 не запускались. Архивные 23 проверки ещё не выполнялись; шесть новых
native-архивов не получены.

`NativeCompositeTraining/ClassicRawProbeCannotEnterCompositeProtocol`
ожидал исключение от `EncodeVerificationProtocol` на строке 238.
Однако protocol4 уже имеет явный portable codec. Сериализация декларации
сама по себе не предоставляет право принимать raw observations.
Соседние запреты Arm/Consume/Capture не дали ошибок.

Отрицательная попытка не переоценивается как успешная. Evidence commit:
`9b9a38f1a5d8842ada5e167d9bdbf33bd24b6381`.
[Независимая проверка](ElderCompositeArchiveA1NegativeVerification.json)
сверила 810 членов архива, 3687 файлов исходников с Git, JUnit и закрытие
всех 25 групп процессов. Резервирование освобождено; исходная диагностика
failed-unit сохранена. Ранее принятые runtime и 327 ресурсов не изменились.

## Исправленная постановка A2

Root-only commit `22af717465cbfe110a923f927d31406337a2c3a8` от точного
родителя d433; Pulse f925 не меняется. Вместо устаревшего ожидания исключения
проверяются roundtrip protocol4 и отказ при удалённом composite contract
или неверной маркировке schema3. Запреты raw admission и отсутствие
выданных проб/сертификата сохранены. Требуется новая полная проверка 206
случаев с отдельными request, runtime и журналами. A2 запущена отдельно:
сборка завершена, выполнены 144/206 проверок: 143 passed, одна failed,
62 не запускались. Итог — отрицательная попытка, а не принятый206 gate.
Metadata-only продолжение `540179d70ddf3764334eb6bb59b7fef691054eee`
исправляет hash исходника в трёх inventory: используется точный Git blob,
а не локальная CRLF-копия. Код и набор из 206 случаев не меняются.

Elder A2 остановилась на `NativeCompositeService/ClassicCalculateMode0Exact`:
`ServicePlan` в fixture не объявил обязательный `probe.protocolRevision`;
для Branch также требовался явный routing. Рабочий configured-путь уже
задаёт оба поля, а service validator правильно отверг неполную декларацию
до начала измерений. Root-only исправление
`6dacdb3d4fb3245649aba3a5d69ba8f83f611c8e` добавляет эти два присваивания
в fixture; Pulse, численные критерии и 206 ID не меняются.
Отрицательный evidence `153751c4b3a3b2c0a25f10540265b41233197f7c` и
[независимая проверка](ElderCompositeArchiveA2NegativeVerification.json)
сверяют 1801 член архива, 3687 source files и закрытие 57 групп.
В следующей попытке A3 service/archive случаи поставлены в начало;
старые проверки из полного набора не исключались.

**A3 запущена отдельно на Root6dac/Pulsef925.** Новый подписанный бюджет
учитывает горячую сборку и фактический peak A2 210 640 896 байт: cap прироста
768 MiB, неизменный physical floor 512 MiB, preflight 1280 MiB. Это явно новая
постановка, а не изменение ограничений завершённой A2.
[Обоснование и границы оценок](ElderCompositeArchiveA3WarmDiskBudgetReview.json)
отделяют source-derived CSV/base64 расчёт от оценочного запаса на JSON и сборку.
Watchdog останавливает только собственное задание при превышении cap/floor;
полный набор 206/96 leaves сохранён. A3 собрана, но остановилась на
`NativeCompositeService/ClassicPreparedStopHasSingleRawResult`: при
prepared=1, rawSamples=0 и одной сохранённой raw trial обработчик observationSink
не получил ожидаемое единственное уведомление. Это отдельный дефект доставки
отменённого результата; критерии пика и численные допуски не менялись.

Корректный evidence `ec2935e8511f89da6457e896dba21099037b796c` и
[независимая проверка](ElderCompositeArchiveA3NegativeVerification.json)
сверяют 531 член архива, 3687 source files, 13 JUnit и закрытие 14 групп.
Первоначальный collector ошибочно включил supervisor log от A2;
`90af73022c3c0955eaafa368ef5a7e00702147b1` сохранён отдельной веткой origin как
collector-mapping-negative. Исправленный сбор использует подлинный A3 log;
все исходные worker/controller файлы не менялись, численный запуск не повторялся.

Перед A2 выполнено отдельное обслуживание закрытого A1 runtime: удалены
только семь производных статических библиотек `Lib.CMake/*.a`, 87 737 788 байт.
Исходный runtime manifest остаётся историческим снимком до удаления;
новый manifest явно фиксирует эти семь отсутствующих файлов.
ELF, INI, результаты, исходники, общий build cache и три других runtime
сохранены. Свободное место после обслуживания — 1 680 998 400 байт.
Evidence `e86b5081515efa75a4195c264866be23e8a79f56` и
[независимая проверка](ElderCompositeArchiveA1StaticRetirementVerification.json)
содержат точные пути, хеши и журнал удаления. Порог допуска A2 по месту
остаётся 1,5 GiB и проверяется заново непосредственно перед запуском.

На M40 ASan206 A1 остановлена до сборки и обновления source/cache: строгая
проверка процессов не учла два давно работающих служебных контекста сеанса,
`(sd-pam)` и `ssh-agent`, с ограниченной доступностью maps/exe/fd. Это ошибка
подготовки задания; выполнено ноль C++ проверок. Отрицательная попытка
сохраняется отдельно. Следующая A2 использует точную идентичность этих двух
контекстов — boot ID, PID, start ticks, UID, comm, command и cgroup; остальные
неизвестные контексты по-прежнему запрещают запуск. Полная видимость памяти
этих системных процессов не заявляется.
[Идентификаторы попыток](TypedCompositeTrainingJobs.json).

M40 A1 опубликована как `c19d2eb325541667ef770eacee8e8f132ad99ba3`;

## Windows: сборка не принята из-за завершения процессов

A2 на .14 собрал Console и StorageComponents: основной процесс вернул 0.
Но production guard обнаружил остававшийся дочерний процесс PID 15228
и закрыл собственную группу. Его назначение не установлено; предположение
о вспомогательном процессе компилятора не считается фактом.
Новые native-тесты на Windows не запускались, runtime не принят.
Ранее принятые три runtime сохранены.

Evidence `2483362581205cffacd487888d6466730110f051` опубликован отдельно.
[Независимая проверка метаданных](WindowsCompositeA2IndependentVerification.json)
сверила все 58 членов архива, восемь репозиториев source closure,
неизменность трёх защищённых runtime и сохранённый снимок закрытой группы.
89 строк реальной компиляции и две линковки подтверждают выполненную сборку;
они не отменяют отказ production guard.

Следующая отдельная диагностика должна записать идентичность процессов
своей группы, пока они живы: PID, время создания, путь и hash executable.
Проверка закрытия группы сохраняется. Успешная диагностика одного
перекомпилированного объекта не заменит приёмку полной сборки.

Последующие отдельные проверки: production backend прошёл 26/26 Win32 API
случаев и закрыл 23 Job. Однако две настоящие компиляции завершились main exit0
при остающемся `vctip.exe`; подписанное ожидание 30 секунд также не дождалось
естественного закрытия. Windows SDK/build admission не получен; дальнейшие
попытки компиляции отложены без изменения системных настроек.
[Независимая проверка API26 и отрицательного compile A/B](Wire67Windows26CompileABIndependentVerification.json)
разделяет эти результаты. Тот же receipt подтверждает Python wire67/67 и
430 Git blobs на M40; это проверка схем и start-failure/run-ID contracts,
а не чтение будущих actual6/package5 данных.
