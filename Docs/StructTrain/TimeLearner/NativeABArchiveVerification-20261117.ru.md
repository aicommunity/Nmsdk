# Проверка архива A/B и граница совместимости glog

Actual native A/B содержит32 наблюдения и четыре полных pipeline-снимка.
Classic/Branch inline/file дают одинаковые4001 отсчёт на каждую из8 проб,
совпадающие stimulus/spike ticks и нулевую численную разность Soma/LT.
Оба контрольных состояния имеют TP1/FP6/FN0/TN1. Это проверка передачи,
а не новый успешный алгоритм по критерию TP≥1/TN≥2.

Первый Linux gate16 выполнил15 проверок успешно, одна завершилась ошибкой
`packaged_run_has_unrecorded_artifacts`. В каждом настоящем снимке оказался
один glog `NeuroModeler.INFO`: producer сохраняет его байты как дубликат
именованного лога, а production manifest намеренно не включает severity alias.
Все обязательные artifacts присутствовали; неизвестных потерь не обнаружено.

Проверка по умолчанию остаётся строгой. Для этого исторического формата явно
применяется существующий `dereferenced-glog-aliases-v1`: проверяются подписанный
manifest, фактические owner bytes/PID, запись именованного лога в его inventory,
единственный подходящий target и совпадение размера/SHA. Только такой alias
исключается из сравнения множества run artifacts; исходные архивные байты
остаются сохранены и проверены. Общий алгоритм adapter теперь доступен как
inventory-функция и используется и штатным restore, и streaming verifier.
Ни PID, ни чтение архива сами по себе не доказывают выполнение процесса:
actual run audit и закрытие kernel groups проверены отдельно.

Добавлена DATA-регрессия: строгий default, явный adapter, неправильный PID,
неодинаковые bytes и посторонний artifact. Повтор настоящего Linux archive
gate необходим до публикации окончательной квитанции; прежняя неуспешная
попытка сохраняется. Это не основание повторять32 native наблюдения.
