# Проверки native runtime с закреплёнными DATA inputs

`Scripts.StructTrain.TimeLearner.native_data_checks` запускает конечный список GTest cases на уже собранном неизменяемом runtime. Пересборка, изменение модели до импорта, калибровка и научный verdict не входят в эту операцию. Контроллер предназначен в том числе для проверки больших сохранённых Classic/Branch пакетов через production import/export; допустим отрицательный исход обучения сохранённой модели.

Запуск: `python3 -B -m Scripts.StructTrain.TimeLearner.native_data_checks run request.json`. Команда является долговечным supervisor и запускается в отдельной серверной сессии с сохранением stdout/stderr. `status <controller-directory>` читает фактическую группу процессов; `recover <controller-directory>` разрешён только после подтверждённого завершения исходного supervisor. Он закрывает исходные группы и восстанавливает ресурсный учёт, не перезапускает вычисления и не создаёт PASS.

Закрытая декларация версии1 содержит worker/execution root/job ID, Tool commit, SDK path/commit, runtime manifest path/SHA256, DATA inputs в штатной schema5 форме, уникальные `{name,test_id}`, outer/leaf limits, aggregate memory reservation и disk budgets. Arbitrary command/module/environment/build поля запрещены. Имена cases регистронезависимо уникальны; GTest IDs уникальны. Whole budget покрывает последовательные leaf budgets и минимум60s управления; reservation memory покрывает одновременно Python owner и один native leaf.

Перед запуском проверяются Git bytes всего materialized Tool Scripts, соответствие runtime его SDK closure, реальные runtime files, входные файлы по ограничению размера и SHA, canonical paths, независимость output, отсутствие конфликтующих leases, memory/disk capacity. Runtime directory, SDK, Tool, manifest, control и каждый DATA source резервируются на чтение; отдельный output — на запись. Копия request и исходный control защищены по identity и bytes; их изменение останавливает работу.

Используется существующий `owned_native_job._run_owned`, а не новая реализация управления процессами. Полный ожидаемый граф дочерних групп задан списком cases до запуска. Внутренний worker является bound main PID и владельцем единственного lease; heartbeat проверяет исходные пути. Каждый case проходит production `native_gate` schema5: cooperative runtime capture, отдельная bounded cgroup, точный JUnit inventory, source/runtime validation и проверка исходных/staged DATA bytes после процесса. Источники read-only; staging расположен только в output. Результаты и terminal сохраняются отдельно от supervisor cleanup. Lease освобождает только внешний контроллер после закрытия всей исходной группы и всех конечных child intents. Восстановление использует тот же `_finish` и не считает cleanup доказательством успеха.

Для recorded N4 cases требуются два qCompress-compatible `.qz`: Classic/Branch. Их уникальные исходные JSON уже находятся в compact primary root Git; `.qz` — производный серверный Git cache, а не второй набор обязательных primary. Имена staged файлов: `classic-recorded-model.qz` и `branch-recorded-model.qz`. Native case дополнительно проверяет исходные raw size/SHA, импортирует весь model package, выполняет штатные Build/Init, экспортирует его и повторяет импорт в новом fixture. Сравниваются effective model revision, non-image learned state, retained recovery ledger и все кадры реальной пробы; обязательны4 stimulus edges и ненулевой Soma excursion. История поиска не объявляется checkpoint, а остановленный Train не превращается в сходимость.

После выполнения сохраняются спецификации, runtime/source/Tool snapshots, inputs descriptors, hashes, оба JUnit, полный model export `.qz`, summary8, до/после waveform JSON и phase timings. Для публикации обязательны финальная whole-group closure, released lease и compact primary archive с independent readback. До выполнения metadata tests и actual native cases сам факт наличия этого кода не является приёмкой. Полный code-before/code-after performance эксперимент и научная матрица остаются отдельными проверками.
