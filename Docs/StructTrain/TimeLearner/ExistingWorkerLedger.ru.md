# Повторное открытие реестра worker

В s04-rdk-description-elder-a1 численные задания завершились, но supervisor
не смог освободить резерв: `Reservations(database)` выбирает schema1, тогда
как реестр Elder создан с capacity и schema2. Ошибка и последующее штатное
восстановление сохранены в commit 6117aad55a6d105ad046c1867abc6f4a5a3cb050.

Для уже созданного реестра добавлен `Reservations.open_existing(database)`.
Метод читает сохранённые ограничения, проверяет schema, worker, устройство
файловой системы, набор metadata и определения обязательных таблиц. Затем
открывает существующую базу без вызова создающего конструктора и без DDL.
Он не создаёт отсутствующую базу и не мигрирует старую схему. Для schema3
обязательно явное `managed_units=True`; автоматического включения managed
ownership по содержимому файла нет. Конструктор с явной capacity остаётся
путём создания нового реестра. Несовпадения явной политики по-прежнему запрещены.

Последующие worker/supervisor должны использовать этот метод при повторном
открытии, а не предполагать schema1 или копировать capacity другого сервера.
Он не освобождает lease автоматически, не отменяет проверку закрытия процессов
и не удостоверяет успешное выполнение научного задания.

Проверки используют реальные Linux /proc и SQLite: все три схемы, сохранение
существующего ownership в schema1/2, отсутствующий файл, symlink, неизвестные
schema/worker, лишние metadata, повреждённая capacity, смена устройства,
чужая SQLite-база, потеря leases/managed_unit_intents и ослабление их структуры.
Schema3 здесь проверена на пустом реестре: сохранение живого managed graph
этот адресный набор не удостоверяет.

Код ab4f1460f228e60cd0e0704ab35afbe2d0e1d415 проверен на M40 и Elder:
по44 теста, без failures/errors/skipped. Восемь новых проверок дополнены
существующими проверками reservations, budgets и closed-worker recovery.
Worker и supervisor открыли реальные разные реестры серверов через новый API:
schema1 M40 и schema2 Elder. После выполнения все группы закрыты и leases
освобождены. Численные нейронные эксперименты в этом наборе не выполнялись.

Git-primary: M40 `8bc1e5a5622d727761544b81807858fef7c2449d`, Elder
`d4fa89fd753925c15202abdaa343c1935a5505bd`. В M40-пакете сохранены предыдущие
неуспешные попытки настройки test worker: отсутствие spawn guard, ошибка
сериализации unittest result и неправильная среда дочерних Python-процессов.
В Elder-пакете сохранена ошибка раннего supervisor с неверным путём source.
Они не выдаются за дефекты модели или успешные проверки.

Это исправление конкретного открытия реестра, не завершение этапа10. Все
новые supervisor должны использовать API; ранее запущенные исторические
скрипты и их provenance остаются неизменными. Полный перенос запускателей
в единый production CLI остаётся отдельным незавершённым требованием.
