# Дополнительный общий диск disk2tb

Пользователь28.11.2026 разрешил использовать общий диск примерно2ТБ
для данных расчётов, если места на4ТБ M40 недостаточно. Проверка
фактических mounts установила общий ресурс `//10.245.1.15/E`;
это хранилище, нового вычислительного worker на .15 не назначали.

Создан отдельный проектный раздел `Nmsdk-StructTrainExpData`.
Идентичность записана в `data.root.json`: kind
`nmsdk_structtrain_shared_working_data`, schema1, storage_id
`53aa6baa-14da-4688-b16c-7bbd52b8dae3`.

| Среда | Путь | Фактическая проверка |
|---|---|---|
|Elder .11, M40 .17, .12, .4|`/mnt/disk2tb/Nmsdk-StructTrainExpData`|одинаковая идентичность, запись и обратное чтение отдельных проб подтверждены|
|Windows .14/.8|`//10.245.1.15/E/Nmsdk-StructTrainExpData`|запись и обратное чтение из фактического TaskUser подтверждены fr1126/fr1127; Y также видна этому пользователю|
|Пользовательский Windows-сеанс|`Y:/Nmsdk-StructTrainExpData`|буква указана пользователем; из SSH .14/.8 и текущего локального процесса Y не видна|

После проб Linux свободно около1996303970304 байт. Пробы находятся
в `probes`, производные рабочие данные предусмотрены в `cache`.
Не путать раздел с `/media/user/Data/Nmsdk-StructTrainExpArchive`:
он сохраняет идентичность основного архива и существующих ссылок.

Новые объёмные временные восстановления и производные кэши можно
помещать сюда с явным пределом объёма, запасом места и владельцем.
Для новых уникальных первичных данных, переносимых с4ТБ при его
заполнении, сначала потребуется отдельный проверяемый каталог размещения
и поддержка его ссылок: существующий `external_archive` связывает
объекты с прежним авторитетным корнем. Копирование marker основного
архива или подмена ссылок без проверки нового места неприемлемы.

Квота локального диска не покрывает SMB. Общую поддержку нескольких
файловых систем в scheduler ещё требуется завершить в этапе10;
этот профиль её не объявляет реализованной. Действующие задания
fr948, fr1097 и производные кэши прежних попыток не переносились.
