# Classic: завершённая пара обходов на одном runtime

Оба Train завершены по бюджету и прошли полный исходный аудит.
Циклический вариант посетил все три обучаемых входа; последовательный
не дошёл до третьего. Однако циклический поиск сохранил короткие пути,
потеряв найденные ранее удачные предложения. Дефект выбора состояния
[воспроизведён отдельно](CyclicIncumbentSelectionDefect-20261126.ru.md).
Исправление прошло отдельные24 контролируемые проверки, полная SDK-приёмка
ещё впереди. Распознавание обеих моделей завершилось; независимое
восстановление его полных первичных данных ещё не принято.

## Предварительное дополнение: фактическое распознавание

Оба продолжения завершены штатно, все14 групп процессов закрыты.
Использован Historical Same-Matrix: кандидат порога предложен по
подпороговым реакциям и затем проверен отдельным реальным прогоном
восьми паттернов. Повторного Train не было.

| Величина | Последовательный | Циклический, quantum3 |
|---|---|---|
| Проверенный кандидат порога | 0,02342413248481376 | 0,006695608954337337 |
| TP / FP / FN / TN | 1 / 2 / 0 / 5 | 1 / 6 / 0 / 1 |
| Прежний полный подпороговый margin | −0,006083772219529882 | −0,004503725380705870 |

Кандидат расположен между максимумом цели и ближайшим меньшим максимумом
отвлекающего паттерна. Отрицательный margin по всей матрице сохраняется;
эта процедура не объявляет набор полностью разделимым. Высокий исходный
порог100 дал TP0/FN1/TN7 в обоих случаях: это молчание цели, а не успешная
классификация. Сертификат Exact не переносился.

Сам по себе охват третьего входа в старом циклическом алгоритме
не улучшил распознавание в этой паре. Результат относится к прежнему
SDK d2c7487a88a5c1c372f825dc708a543c03234fcb, а не к новому исправлению
свежего выбора координат. Оба Train остановлены по бюджету; нельзя
объявлять общую непригодность циклического обучения по одному примеру.

Terminal-квитанции, controls, фактические bindings и предложения порогов
сохранены во внешнем архиве с hashes. [Компактная запись](../../../Reports/StructTrain/TimeLearner/Progress-20261126/M40-paired-recognition-terminal-ex24.json).
Это пока результат штатного завершающего аудита. Полная внешняя
архивация, независимый повтор анализа и графики всех откликов ещё нужны;
настоящий срез не заменяет их приёмку.

## 1 Сопоставимость условий

Оба реальных задания выполнены на M40 с тем же executable, SDK,
исходной физической моделью
5c97864335ce7cc91a3bcd071514e2bceb8b88e38aa122e055d8306881450964
и исходным набором 31 образа хранилища. После исключения только run_id,
подписи задания и объявленного input_traversal документы Train полностью
совпадают. Скопированные runtime manifests совпали по размеру и SHA-256;
их deployment-пути различаются и не являются научным фактором.

M=4, частота 2000 Гц, нормализация числом синапсов, CapturedPerInput,
амплитудный допуск 10⁻⁵, временной 0,02 с. Общие ограничения: 24 новых
кандидата на вход, 160 поисковых проб, 1280 изменений, один проход, 10000 с
модельного времени и 32400 с стенового времени управления обучением.
Лимит расчётного процесса 39600 с — отдельное внешнее ограничение.
Нормализация сопротивлением в этой физической паре не проверяется.

Их исходные пакеты имеют 1185881421 и 1265970945 байт и сохраняются
как состояния после остановки, не как доказанное завершённое обучение.

Последовательный участник начал штатный перенос и проверку DATA-модели.
Циклический допущен 6/6 адресными проверками без пропусков и поставлен
после точного владельца последовательной проверки. Используется прежний
протокол: реальный импорт, исходное предъявление восьми паттернов,
один объявленный
порог на той же матрице и новое реальное предъявление восьми паттернов.
Нового Train, шаблонного Test или сертификата от проекции DATA нет.
TP/FP/FN/TN этих новых моделей пока не опубликованы.

Не смешивать эту M40-пару с прежней работающей моделью Elder q3,
давшей TP1/FP2/TN5: это разные обученные состояния. Нынешнее наблюдение
не отменяет её результат и не доказывает общую бесполезность обхода
по кругу. Оно показывает охват входов и конкретный дефект финализации.
