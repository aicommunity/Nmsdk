# Проверка поиска и управления TimeLearner на .4

## 1 Цель и границы

Для текущего кандидата выполнена расширенная проверка алгоритмов выбора
длины, числа синапсов и сопротивления, управления измерениями и подготовки
распознавания. Она относится к этапам4,6–8 утверждённого плана. Результат
исполнения432 случаев содержит24 отказа и не принят как общий PASS. Прохождение C++-проверок само по себе
не устанавливает качество классификации или выполнение всех допусков
обучения на паттерне из четырёх импульсов.

Обновление после закрытия первого раздела: штатный gate подтвердил169/169
случаев поиска, без отказов и пропусков, с точным JUnit и закрытой группой
процессов. Раздел lifecycle завершил все191 случай:177 прошли,14 получили
`window5_output_new_only` при записи артефактов. Подготовка распознавания
завершила72 случая:62 прошли,10 остановились на отсутствии требуемого
сертификата после`maximum_sweeps_exhausted` подготовительного Train.
Всего в исходном совместном исполнении408 успешных случаев и24 отказа,
пропусков нет. Оба закрытых архива опубликованы через общий диск;
полное независимое восстановление4620 файлов завершено на .12.
На M40 дополнительно проверены все37 файлов комплекта читателя,
16 реально загруженных файлов до и после чтения и управляющий Git.
Это две моментальные карты загрузки, не утверждение о полном времени
жизни загрузчика. Снимок исходников до работы этого читателя не получен;
его управляющий код объявлен в отдельном Git, версия корня проверена после.

Все14 отказов относятся к`NativeManualControlLifetime`. Общий helper
`SaveCandidateWindowGroup` создаёт пути из топологии и имени этапа;
несколько тестов используют одинаковые`reference-0/1`. Защита NewOnly
останавливает повторную запись. Исходный JUnit SHA256
`229bc9e2b721d7513e696811acb65a655aa0b38452097c0498f8fec730ea0b8c`
сохраняется с14 отказами. Это не основание объявить assertions пройденными.
Объявлена отдельная проверка тех же14 случаев на неизменном бинарнике,
каждый в новом каталоге. Управляющий commit
`8d8f63762818596d812c3a6de8893396bf8519f0`, каталог
`/home/user/Nmsdk-experiments/Matrix-manual-isolated-controls-fr385`.
Все14 отдельные проверки завершились успешно на том же бинарнике, без
изменения исходников и допусков; сохранены1300 первичных файлов. Будущие
общие наборы этих fixtures также должны разделять выходы случаев.

## 1.1 Предпосылки калибровки и PostTune

Оставшиеся10 отказов имеют другую причину. Все останавливаются в
`LearnedBoundary` на требовании`service.Certificate()` до исполнения
самой калибровки или PostTune. Отдельный запуск с неизменными параметрами
объявлен в commit`2f6d56ddc54398b80c1a645b8292f1a29cfea0d4` и каталоге
`/home/user/Nmsdk-experiments/Matrix-recognition-isolated-fr417`.
Все10 случаев повторяют отрицательный исход и в отдельных процессах.
Исходные допуски, параметры и executable в этом повторе не менялись.

В этих первых случаях для изменяемого пути разрешены длины2…3 и
сопротивления86…172 МОм, число синапсов закреплено равным1. При одном
проходе проверены четыре сочетания. Наблюдаемая временная невязка Classic
составляет−68 мс для L=2 и−58,5 мс для L=3; Branch —−70 и−60,5 мс.
Все значения превышают по модулю заданные20 мс. При L=2 и86 МОм
амплитудная невязка равна0; переход к L=3 даёт−0,0004389148544778898
в единицах модели при допуске0,00001. Создание положительного сертификата
по этим измерениям было бы ошибкой.

Это устанавливает неуспех текущей предпосылки транспортного теста, а не
отказ ещё не исполненного PostTune. Необходимо сохранить отрицательный
контроль ограниченного обучения и отдельно получить измеренно валидный
завершённый источник для проверок транзакций. Его частоту, профиль,
привязку вершин и реальные остатки проверять штатным runner. Допуски
20 мс/10⁻⁵ не заменять более широкими ради успешного теста. Глобальная
физическая недостижимость по четырём измеренным сочетаниям не установлена.

Проверялся существующий SDK без изменения работающих опытов Classic на
M40 и .14. В обозначениях исходного программного интерфейса
`N0` означает настройку числа синапсов, `N1` — сопротивления. Эти поля
не являются названиями топологий Classic и Branch. Число импульсов в
паттерне в описании метода обозначается M.

Точный список432 идентификаторов сохранён до исполнения в отдельном
Git-репозитории управляющих файлов, commit
`fdae476dfefc9078ec11a57e42cd54ed064952ee`. Контрольный список прочитан
из настоящего executable: в нём2356 случаев, все432 объявленных имени

Три раздела последовательно запускаются штатным `native_gate` схемы6.
Для каждого необходимы полный JUnit с точным множеством идентификаторов,
отсутствие пропусков, захват реально загруженных файлов и закрытие всей
принадлежащей заданию группы процессов. Assertions с отрицательным
результатом сохраняются; завершение процесса не превращает их в успех.
Проверки на управляемых наблюдениях и проверки реальных компонентов
остаются разными видами доказательства.

Один раздел ограничен5400с вычисления,8ГиБ памяти и128 задачами.
Для управляющей группы выделены12ГиБ и21600с. До начала зарезервированы
16ГиБ под выходы сверх24ГиБ остатка. Объём и остаток проверяются между
разделами; эта проверка не является непрерывным ограничителем записи
данных внутри C++-процесса.

## 4 Что остаётся за пределами проверки

Отдельные тесты PostTune и финализации требуют архивных входов, явно
подключаемых через переменные окружения. Они не включены в эту432;
их нельзя считать пройденными или заменить пропусками. Открыты полная
матрица режимов и профилей, независимая проверка отрицательных10,
сопоставление с приёмками исходного плана и интеграция в develop.
Проверки `NativeImageRestSnapshot` в эту выборку также не входят:
[три прежних отказа сравнения архивов](NativeImageRestDiagnostic-20261127.ru.md)
сохранены отдельно. Совпадение18 пар временных откликов не устранило
различие формы одного поля состояния и не отменило этих отказов.

Общий диск M40 теперь доступен на .4 по
`/mnt/disk4tb/Nmsdk-StructTrainExpArchive`. Первоначальный publisher искал
другой, отсутствующий путь; его отказ сохранён. Оба уже рассчитанных
комплекта опубликованы через новый путь после исправления проверенного
дефекта CIFS-публикации. C++-расчёт ради публикации не повторялся.
Тяжёлые3320+1300 файлов и37 файлов читателя находятся во внешнем архиве;
в корне Git сохранена только компактная проверенная ссылка.
