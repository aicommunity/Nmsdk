# Одна проверка модели на пакет наблюдений

Прежний scorer вызывал полную проверку threshold candidate и хеширование вложенных model/source envelopes для каждой пробы. В больших пакетах они содержат всю историю обучения; стоимость повторялась с числом наблюдений. Это подтверждено графом вызовов `recognition_metrics → recognition_trial_evidence → threshold_candidate_evidence`. Само по себе это наблюдение не измеряет ускорение и не объясняет OOM native-экспорта.

Новая граница — один синхронный вызов scorer или `audit_recognition_trial_set`. Модель, derivation и граф проверяются до обхода наблюдений. Для проверки откликов создаётся малая неизменяемая проекция: revision, число входов, частота, топология и описание LT-канала. Проекция не содержит ссылок на изменяемые физические поля исходного пакета. Перед выходом проверяется неизменность полного digest исходной модели. Глобального кэша, межзапускового proof token или параметра `already_validated` нет.

Каждое наблюдение по-прежнему проходит проверки полной схемы, native временной сетки, отсчётов и NaN/Inf, размерности сомы, фактических stimulus/spike histories, count/timestamps, закрытия окна, model-before/model-after и метаданных ожидаемой пробы. Standalone auditor самостоятельно проверяет переданную модель. Метрики, критерии, порог и разделение завершённого обучения/остановленного diagnostic не меняются.

Для приёмки предусмотрены реальные native модели четырёх видов: обычная, threshold candidate, diagnostic threshold candidate и calibrated. Узкие C++ контролы восстанавливаются через существующий immutable SDK executable, с отдельным owned process, памятью/временем и проверкой GTest XML. Это генерация контрольных данных; она не является новым научным обучением классификатора. Python-проверки сравнивают batch/standalone ответы, контролируют число derivation audits, повреждённую позднюю пробу, мутацию/переподпись модели внутри вызова и запрет переноса доверия между вызовами. Отдельно результат полного scorer сравнивается с сохранёнными метриками реального большого eight-pattern Test до изменения кода.

На момент создания этой ветки серверная приёмка ещё ожидается. Ускорение и runtime-проверенное исправление не заявляются. Вложенная история остаётся в формате модели; это изменение не завершает предусмотренное исходным планом разделение физической модели, controller checkpoint и архива измерений. Математика обучения и C++ lifecycle не изменяются.
