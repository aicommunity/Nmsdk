# Компактная передача физической модели без истории обучения

## Наблюдаемая проблема

Завершённый Windows Train с двумя проходами имеет полный аудит4791 файла.
Оценка сохранённого состояния at29 остановилась до первой пробы через1215с
с `bad allocation` при лимите16ГиБ. Исходное состояние занимает671057982
байта; отдельный индекс первичных измерений —1755582762 байта. Это разные
файлы. Прежнее общее указание «пакет2ГБ» недостаточно точно описывает
источник загрузки и не доказывает место выделения памяти.

По исходникам преобразование модели для распознавания и экспорт физического
состояния используют полный импорт обученного пакета. Затем эта история
остаётся вложенной в сохранённые состояния распознавания и кандидаты порога.
В `limits-after.json` сохранён пик8050470912 байт, около7,50ГиБ,
при лимите16ГиБ. По одному этому числу причина отказа не устанавливается:
оно не описывает размер следующего неудачного выделения памяти.
Отказ не является результатом классификации или обучения.

Попытка az4 с лимитом20ГиБ отклонена по доступной физической памяти
до CreateProcess; native-процесс не запускался. Внешний контроллер
затем ошибочно обратился к отсутствующему полю all_processes_closed;
этот отказ сохраняется отдельно. Новая az13 использует18ГиБ и предварительно
проверяет также физическую память. Её native-процесс10368 и именованная
группа были подтверждены через API ядра Windows. Обработка предварительного отказа в новом контроллере
исправлена; общий runner этой правкой не менялся.
Исполняемый файл, исходная модель, восемь паттернов, порог и режим сброса
не меняются. Исходный Train не повторяется. Это адресная диагностика,
которая сама по себе не закрывает проблему масштабирования.

При проверке24 ноября попытка az13 уже закрыта: native вернул2 через1231,49с,
в stderr записано `bad allocation`, первая реакция не получена. Пик учтённой
памяти8074915840 байт; все процессы закрыты. Предыдущее указание о живом
процессе описывает более раннее наблюдение. Увеличение лимита16→18ГиБ
не решило проблему; следующая правка должна отделить импорт физической
модели от загрузки полной истории. Повтор Train для этого не требуется.
[Окончание попытки и наблюдения ядра](../../../Reports/StructTrain/TimeLearner/Progress-20261124/native-progress-observations-ba6.json).

## Подготовка физического пакета

Модуль `physical_data_projection` создаёт отдельный документ уже существующей
схемы `timelearner_physical_model_data`, версия1. Он сохраняет:

- реальный граф нейрона, связи и определения storage-образов;
- dataset, генератор и исходный целевой паттерн;
- индивидуальные параметры входов и все физические параметры дочерних узлов;
- конфигурацию, протокол, режимы управления и происхождение преобразований;
- ссылку на неизменённый исходный документ: вид, версию, SHA и revision модели.

История измерений и поиска остаётся в исходном пакете. Проекция не меняет
его вид, не подписывает сокращённое состояние как обученное и не переносит
сертификат либо подтверждение калибровки. `certificate=null`,
`data_only=true`, `dynamic_checkpoint=false`; признаки проверки первичных
доказательств и native-импорта остаются ложными.

Проверяются контрольные суммы исходного и вложенных документов, роли
границ и согласованность физики production-анализатором. Для распознавания
используется реально сохранённый граф конечного состояния, а не исходный
solo-граф. Самостоятельное solo-состояние остаётся solo и не допускается
в frozen evaluation без явного преобразования.

Текст конфигурации сериализуется семантически эквивалентно. Совпадение
байтов этого текста с экспортом Qt не обещается; проверяются разобранная
конфигурация, все физические поля и semantic model fingerprint. Полученный
SHA физического документа относится к новому документу.

CLI принимает ожидаемые размер/SHA исходного файла, ограничивает вход
по умолчанию1ГиБ и выход32МиБ, сохраняет исходник и публикует только новый
файл. Подготовку следует выполнять отдельным ограниченным процессом:
первый выпуск ещё разбирает исходный JSON целиком. Постоянный объём памяти
для подготовки не заявляется; последующий Test получает компактную модель.

## Проверки и открытая приёмка

Добавлены проверки по реально экспортированным Classic/Branch-моделям:
сохранность графа, образов, входов и конфигурации; отсутствие переноса
полномочий; неизменность исходного объекта/файла; повреждение вложенной
подписи; границы размера и запрет перезаписи существующего результата.
На снимке корня0338c3f28 прошли все5 Python-случаев без пропусков.
Затем production Console выполнила4 реальные пробы: цель и отвлекающий
паттерн для каждой топологии. Во всех случаях совпали801 отсчёт,
входные события и выходные спайки; максимальная разность сигналов0.
Хеши моделей до и после каждой пробы сохранились. Все106 файлов
доказательств независимо восстановлены из внешнего архива.
[Проверки и первичные данные](../../../Reports/StructTrain/TimeLearner/Progress-20261124/physical-data-projection-proof-az17.json).

Для всех четырёх проб подготовлены полный диапазон потенциалов и отдельный
масштаб положительного отклика: восемь PNG индивидуально просмотрены.
На графиках наложены фактические входы и выходные события; все801 отсчёт
сохранены. Все21 член галереи, включая журнал визуальной проверки,
независимо восстановлены во внешнем архиве.
[Проверенная галерея](../../../Reports/StructTrain/TimeLearner/Progress-20261124/physical-data-projection-reviewed-gallery-az29.json).

До научного использования обязательны штатный импорт полученного DATA,
проверка эффективного графа и frozen model hash, а затем реальные временные
реакции. Проекция не выполняет преобразование solo→recognition, повторный
подбор порога, обучение либо восстановление контроллера. Для существующей
Windows-модели сначала требуется получить её явную границу распознавания;
после отказа попытки18ГиБ нужен отдельный путь преобразования
физических данных без импорта полной истории. Такой путь здесь не заявлен.


## Кандидат явного физического преобразования, схема2

После повторного отказа Windows подготовлен отдельный путь без загрузки
истории. Он ещё не прошёл серверную приёмку и не применялся к большой
научной модели. Его наличие в коде не означает, что проблема уже решена.

Механическое выделение общего преобразования и добавление нового формата
выполнены отдельными commits PulseLib. Полный импорт и новый физический
путь вызывают один участок кода: включение всех входов, историческое
масштабирование Branch/N1, границы сопротивлений, все пять режимов PostTune,
проверку интегрирования и чтение фактических индивидуальных параметров.
Изменений математической цели обучения, допусков и scheduler нет.

Алгоритм нового пути:

```text
validate and import immutable solo DATA1 through native storage mechanisms
apply the shared physical recognition conversion on private children
verify actual graph, input parameters, frequency and integration
export DATA2 with unchanged original source_boundary
retain complete compact source_model_data and explicit conversion_spec
on import: repeat this transition and compare the entire resulting document
allow frozen probes only after the native comparison and all-input check
```

Схема2 сохраняет физический исходник схемы1, а не исходную историю обучения.
Вложенность ограничена одним переходом: повторно преобразованное состояние
не принимается как solo-источник. Повтор с тем же неизменным исходником
должен давать те же параметры и хеш. Изменение типа источника, сертификата,
графа, результата преобразования или условий требует отказа, даже после
пересчёта подписи JSON. Исходные объект и рабочий нейрон не меняются.

Для исторического масштабирования Branch/N1 передаются индивидуальные
исходные амплитуды. Это явно сохранённые данные, которые воспроизводят
физическое изменение; их измерительное происхождение проверяется отдельно
по исходным доказательствам. Новый формат не создаёт такое доказательство.
Для преобразования без масштабирования массив амплитуд обязан быть пуст.

Существующая команда `--timelearner-physical-model-export` дополнена видом
задания `timelearner_native_physical_model_conversion_job`, версия1:
`source_model_data`, `conversion_spec`, `reference_amplitudes`,
`implementation_id`, `sha256`. Она сохраняет отдельный результат и
проверяет его повторным штатным импортом. Старый вид задания экспорта
не меняется. Положительный итог классификации, обучения или калибровки
не выдаётся; число расчётных тиков при преобразовании равно нулю.

Подготовлены шесть C++-проверок на реальных storage/Environment-компонентах:
обе топологии и все PostTune, четыре временные реакции с сопоставлением
полного и физического путей, нарушения контракта, Branch/N1 и его границы.
Пять Python-проверок должны читать именно созданные native-артефакты,
включая13 вариантов физического состояния. Серверные результаты,
проверка большой модели, её распознавание и реальный пороговый повтор
остаются открытыми. Рабочие научные runtime этим кандидатом не обновляются.
