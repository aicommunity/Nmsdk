# Августовская модель: проверка порядка и интервала, пилот 2×2

Сохранённая Classic-модель Phase A сохраняет **6/8** в четырёх проверенных
условиях: исходный порядок и один циклический сдвиг, каждый при Dataset Delay
1.5 и3.0s. Target распознан; ложные ответы дают одни и те же два паттерна,
`phasea-4` и `phasea-6`. Поздних либо предшествующих первому стимулу спайков
в полных записях не обнаружено. Это ограниченное подтверждение устойчивости
исторического результата, без улучшения разделимости.

Проверка относится к одной сохранённой модели49/41/25/1 и порогу0.0135.
Обучение, выбор порога и изменение физики в этой серии отсутствуют. Восемь
паттернов — историческая матрица, а не новая независимая выборка. Исходные
визуально подтверждённые4/8–6/8 не отменяются и не переименовываются.

## Как читать графики

На каждом рисунке четыре потенциала сом, полученные как записанные
ExcChannel.Output + InhChannel.Output, и отдельно native Neuron.SomaSumPotential.
Каждый sample четырёх производных каналов совпал с соответствующими native
learner readout channels. Пятая панель не выдаётся за автоматически равный
им decision potential произвольной LT-модели. Единицы оставлены native:
перевод в SI здесь не подтверждался.

Оранжевым наложен фактически записанный вход, красным — реальный LT output
spike. Чёрная точка обозначает **глобальный максимум данного канала в полном
интервале Test**, с выбором первого sample при равенстве. Она не обозначает
закреплённый импульс Train и не доказывает его однозначную принадлежность.
Выходное решение проверяется по LT events, а не по одному максимуму сомы.

Для каждой пробы построены full и response views, а также их positive-scale
companions. Full сохраняет весь отрицательный feedback после спайка. На
positive views отсечение явно указано над панелью и отмечено треугольниками;
оно не меняет метрики. Response zoom охватывает все импульсы и ещё0.6s,
full — весь интервал до следующего стимула либо конца записи. Следующая
пачка не попадает в предыдущую пробу. Все native samples сохранены без
прореживания. Размер1920×1680, шрифт не меньше12; картинки следует открывать
в полном размере, если просмотрщик уменьшает их до ширины страницы.

## Проверки, доступность и воспроизведение

Первичные сжатые данные: commits
`18ac0e263b9878b5c59cbaf652fcaec9d29322a5` (baseline A3) и
`72af32bdd057952d94ffe0241a3d6597f6a193f0` (принятый пилот A4).
Второй архив содержит остальные три case и ссылку на переиспользованный
baseline. Исходный failed terminal A3 оставлен failed: после выполненного
Test тогда отказал reader; последующее read-only исправление не скрыто.
Подробности: [primary verification](HistoricalProtocolPilotVerification.json).

Три новые проверки на настоящих native записях подтверждают исключение
следующего входа из интервала, максимум по всем samples полного интервала
и сохранность прежней observation schema при подключении сигналов для
рисования. Проверки выполняются на M40, а не локально. Дополнительно
генератор проверяет размеры, hashes, полный набор8×4 views, границы текста
и отсутствие отсечения full views. Первые ошибки подготовки окружения и
ошибка размещения подписи сохранены, научными результатами они не считаются.

Полный кэш всех128 рисунков расположен на M40:
`/media/user/Data/TimeLearnerRefactor/ReportsCache/historical-protocol-pilot-temporal-a5/figures`.
По каждому из четырёх case находятся32 PNG и `report.json` с hashes/границами/
максимумами и полным наблюдением. Для просмотра всех паттернов создано HTML-оглавление `figures/index.html`:32 раскрываемые пробы и ссылки на128 полноразмерных видов. Оно проверяет hashes каждого рисунка перед созданием. Git содержит исходные сжатые записи, модели,
метрики, код, manifest и шесть выбранных изображений. Кэш не является
единственным источником: его можно заново построить из Git архивов.

На analysis worker восстановить оба опубликованных bundle штатной командой
`python -m Scripts.StructTrain.TimeLearner.portable_primary BUNDLE OUTPUT`.
Затем для каждого case выполнить:

```text
python -m Scripts.StructTrain.TimeLearner.historical_protocol_temporal \
  --input RESTORED_CASE --output NEW_REPORT_DIRECTORY --case CASE_ID
```

Запускать из checkout с новым renderer и установленными matplotlib/Pillow.
Входные файлы не изменяются; существующий output не перезаписывается.
Метаданные проверки и отдельная визуальная приёмка:
[HistoricalProtocolTemporalVerification.json](HistoricalProtocolTemporalVerification.json).

## Границы вывода

Пока проверены только две позиции target из восьми и два Delay одной модели.
Оставшиеся12 условий матрицы8×2, другие исторические пороги/модели, reset-per-trial,
сравнение cold retrain и новый контроллер этой серией не подтверждены.
Здесь нет независимых обучений или доказательства общего отсутствия
зависимости от порядка. Ложные ответы сохранены и не скрываются точностью6/8.
Полный план рефакторинга и его этап11 остаются незавершёнными.


Оглавление проверено на M40:3 tests,132 hashes прежних PNG/JSON не изменены,
CLI output совпал с library output. Evidence
`9ac555a816695e38d604d82bd0ff6b0f6f409d7f`; сжатый комплект25 файлов33668B,
391 source hashes. [Независимая проверка индекса](HistoricalReportIndexVerification.json)
не выдаётся за browser QA; шесть выбранных рисунков проверены отдельно.
После восстановления и построения четырёх папок графиков оглавление можно
воспроизвести командой:

```text
python -m Scripts.StructTrain.TimeLearner.historical_report_index \
  --cache-root REPORTS_DIRECTORY \
  --case original-order-gap1.5 --case original-order-gap3 \
  --case rotated-order-gap1.5 --case rotated-order-gap3
```

Расширение до16 условий зарегистрировано в
[HistoricalProtocolCompletionJobs.json](HistoricalProtocolCompletionJobs.json).
На старте проверены завершение пилота и архивные hashes четырёх используемых
case; новых процессов для них нет. Остальные12 условий выполняются последовательно,
с резервом системы1.5GiB и проверкой свободного места до каждой матрицы.
Это регистрация выполнения, не объявление заранее полученных результатов.
