# Закреплённый пик: отдельная вершина и остаточный хвост

Пользователь уточнил постановку 8 ноября: отдельная ранняя вершина допустима
как отклик закреплённого раннего импульса, даже если её остаточный хвост немного
усиливает более позднюю вершину. Настоящее слияние в одну неразличимую вершину
остаётся неоднозначным. Train по-прежнему измеряет максимум закреплённого
импульса; Test оценивает полную реакцию и реальные spikes.

## Следствие для текущего v1

`matched-omission-assigned-maximum-v1` измеряет влияние исключения каждого
импульса возле full maxima. Любое превышающее объявленный influence threshold
отклонение может сделать поздний максимум Shared. Поэтому критерий
influence-exclusive для всей трассы сильнее уточнённой математической цели.
Нельзя отказывать отдельной ранней вершине только из-за такого Shared у
более высокой поздней вершины.

В actual N2 controls Classic/Branch при 2000/20000 Гц это уже наблюдается:
ранний максимум exclusive, поздний выше и Shared по v1. Первичные данные и
их independent replay сохранены в evidence
`9400c0da0a4d2333efea36076c0e235855ca50f2`. Это корректный результат метода
влияния v1, но не основание для отказа в обучении по уточнённому правилу.
Исторические v1 outcomes не переименовываются.

Действующий portable codec сохраняет именно v1. Он остаётся диагностическим:
успешные codec/native/reader tests не разрешают превращать его результат в
CapturedReferences или TrainingCertificate. Общий максимум пачки, разность
двух трасс и single-pulse waveform не подставляются вместо actual full peak.

## Следующая проверяемая гипотеза, без изменения действующего кода

Для сопоставления можно исследовать необходимость источника для локальной
вершины в фиксированном бассейне полной записи:

1. Выделить реальные plateau-aware максимумы и впадины fullBefore. Границы
   записи явно отличать от измеренной впадины.
2. В omit-control выделить экстремумы на полной записи, затем сопоставить с
   фиксированными бассейнами. Предварительное обрезание окна не должно создавать
   новую граничную вершину.
3. Различать сохранённую единственную полную вершину, отсутствие вершины внутри
   бассейна и Unknown при split/merge, нескольких кандидатах, clipping либо
   пересечении границы плато.
4. Единственный необходимый источник — вершина отсутствует при omit-i и
   сохраняется при всех остальных omissions. Несколько разрушающих controls
   или отсутствие уникального необходимого источника не дают назначения.
5. Рассматривать кандидаты внутри явно объявленного input-specific окна.
   Выбирать высший actual full maximum среди локально однозначных кандидатов;
   не скрывать более высокий ambiguous кандидат внутри того же окна выбором
   меньшего. Отдельная поздняя shared вершина вне окна не создаёт global veto.
   Full repeat должен воспроизводить выбранную вершину и топологию её бассейна.

Это пока diagnostic-only гипотеза, а не реализованный или принятый Train
method. Исчезновение вершины внутри фиксированного бассейна не доказывает
исчезновение физического отклика: control peak может нелинейно мигрировать в
соседний бассейн. Падение ниже measurable floor не следует автоматически
выдавать за отсутствие геометрического экстремума. Нужны отдельные Unknown и
adversarial controls; dominance амплитудного вклада и линейная декомпозиция
не утверждаются.

При реализации требуются новый method/schema, прежние exact event/frame и
model/reset/source проверки, полное N+2 evidence и отдельные pure/native gates.
Не вводить процентные допуски или автоматически разрешённый one-tick сдвиг.
Текущие train tolerances, CapturedPerInput и опорный вход N−1 сохраняются.
Только после проверки применимости метода допустима
[типизированная Train-интеграция](MatchedOmissionTrainTypedPath-2c3eb8d.ru.md).

## Ограниченная реализация следующего измерителя

В существующей native-конфигурации окна уже задаются явно:
`ConfiguredNativeTraining::windows → NativeTrainingPlan::inputWindows`.
Следующий opt-in diagnostic использует эту декларацию и сам не вычисляет окно
из `EstDelayPerSeg` и не передвигает его вслед за удобной вершиной кандидата.
Окно фиксировано до первой пробы конкретной N+2 группы и её repeat. Это не
вечный запрет на proposal другого окна контроллером для следующего кандидата:
исходный план допускает такую гипотезу модели задержки. Изменённое окно требует
новой specification/proof и полностью свежих наблюдений. Сам прогноз не
подтверждает наличие пика, а post hoc выбор удобного окна не допускается.

Его проверяемый смысл: высшая внутренняя вершина полной записи в объявленном
окне, для которой в фиксированном бассейне вершина исчезает только при
исключении закреплённого импульса. Все extrema сначала извлекаются на полной
записи. Отдельный поздний shared максимум вне окна не запрещает принятие
отдельного раннего кандидата. Clipped/merged/несколько неоднозначных кандидатов
внутри окна не превращаются в успех.

Это операционное правило измерений, а не доказательство физического
происхождения или преобладающего вклада. Нелинейная миграция control vertex
может изменить причинную интерпретацию без наблюдаемого split/merge; этот
предел явно сохраняется. N+2 endpoints не доказывают непрерывную lineage.
Существующий `CapturedInputReference` сохраняет rawPotential и provenance,
но не sample range/время/топологию выбранной вершины. Старое ordinal labeling
schema3 и предсказанные legacy windows не считаются доказанной lineage.

Первый новый модуль ограничивается чистой геометрией трасс и diagnostic-only
результатом. Контекст native N+2, source/readback/model/reset и portable proof
должен проверять отдельный типизированный слой до Train integration; успех
геометрии не создаёт TrainingCertificate и не ослабляет прежнюю схему.
Подготовка кода и адресных controls выполняется в отдельной ветке, без
изменения источников уже работающего ASan gate.
