# Новые отвлекающие паттерны при фиксированных модели и пороге

Протокол фиксируется до нового измерения. Он дополняет исходную матрицу и
проверку перестановок, сохраняя математическую цель обучения и конечную модель.
Это проверка чувствительности к новым отрицательным примерам, а не новое
обучение, подбор порога или доказательство сходимости.

## 1 Исходное состояние

Используется сохранённая Branch-модель M40 с M=4, прошедшая полный DATA replay.
Её revision —`0fe43bddd70414e903ec41e68eb3433d9b85feaa5799448e2af7793ed8c5ff9f`,
порог0.0999470202411733 ранее выбран и реально проверен на исходных восьми
паттернах. В новой серии модель и порог не меняются. Порог не подбирается по
новой матрице. Исходный Train остановлен по бюджету, сертификата Exact нет.

## 2 Определение новой матрицы

Целевая последовательность ISI: (0.01;0.08;0.16;0.24)с. Первый интервал задаёт
начало предъявления и сохраняется. Для остальных трёх интервалов заранее
задаётся декартово произведение множителей (1/2;1;3/2). Получаются27
сочетаний, включая исходный target. Никакие ответы модели при генерации не
используются. Половинные интервалы должны точно укладываться на нативную сетку;
скрытого округления или изменения частоты не допускается.

Метка target назначается только исходному точному паттерну; остальные новые
сочетания имеют метку foil. Совпадающие с любой ранее использованной
калибровочной строкой варианты исключаются по hash до запуска. Для текущей
исходной матрицы остаются26 новых foil и один повтор target. Это явно
заданное правило меток, а не установленная область допустимого временного
искажения положительного класса.

Сочетания предъявляются в лексикографическом порядке множителей. Target
оказывается на позиции13 при нумерации с0; scorer должен искать его по метке,
а не по первой строке. Сохранены2000Гц, `reset_per_trial`, полное окно2с,
все4001 нативный отсчёт, действительная последовательность входных событий,
LT potential/output, потенциал сомы и времена спайков. Предел записи4005
отсчётов наследуется из исходного проверенного протокола.

## 3 Проверки и измерения

Перед дорогим запуском выполняются проверки production-конфигурации и
идентичности условий. Используется общий `ConditionSpec`: перенос executable
и изменение run/trial ID не меняют scientific fingerprint, изменение порога
должно его менять. Descriptor hash сам по себе не доказывает выполнение.
Исходный manifest и DATA roundtrip повторно проверяются штатными аудиторами.

Native `physical-model-evaluate` формирует полные первичные наблюдения. Общий
production-аудитор проверяет их полноту, численную валидность, соответствие
фактических входов плану и неизменность frozen model. Для каждой строки
сохраняются TP/FP/FN/TN, спайки и измеренные сигналы. Классификация учитывает
реальные спайки во всём объявленном окне; максимум временного ряда не заменяет
проверку реального порога.

Повтор target сравнивается с исходной пробой относительно фактического onset
общим `trial_response_comparison`. Сигналы не нормируются и вершины не
совмещаются; допуск сравнения1e−12. Если контроль изменился, это явно
записывается отдельным статусом, а не скрывается итоговой точностью.

Нативная группа ограничена2ГиБ и7200с, внешний контроллер —отдельной группой
и10800с; резервируется память обоих. Лимит новых данных512МиБ, минимальный
остаток диска2ГиБ. Работающие runtime и источники не обновляются. Для новых
строк должны быть подготовлены читаемые временные графики сомы с наложением
фактических входных импульсов, как и для исходной матрицы.

## 4 Границы выводов

Новые foil не участвовали в прежней калибровочной матрице. Target остаётся
повторным контролем того же точного паттерна: новый положительный класс и
общая область инвариантности этим опытом не проверяются. Результат зависит
от явно объявленного правила меток. Непрерывный поток, другой ITI, независимые
случайные обучения и другие физические профили остаются отдельными проверками.
Повторы одной детерминированной модели не считаются независимыми обучениями.

Исполнители находятся в корневом пакете:
`frozen_physical_source.py`, `frozen_physical_foil_study.py`.
Тяжёлые данные и рисунки сохраняются во внешнем архиве M40, в Git —код,
протокол, компактные квитанции и проверенные ссылки.
