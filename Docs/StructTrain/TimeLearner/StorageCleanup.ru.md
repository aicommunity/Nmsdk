# Удаление storage-образов: TL-014

Дефект относится к Rdk, а не к алгоритму learner. При подготовке безопасного
импорта ModelArchive найдены и воспроизведены два обращения к освобождённой памяти
в UStorage::DelClass. Они мешали использовать штатное удаление новых образов
после неудачной подготовки. Сам многошаговый rollback импорта ещё не реализован.

## Воспроизведение

Исходный root 65f623cc67f706ee1651ec4c79115af94621e475,
Rdk b15f4384c4516c865afc59a83b487acd477744d0. Новые проверки находятся в
Tests/Integration/Libraries/Test_PulseLib_ClassImages.cpp и используют настоящий
Console-like Environment/storage, NPulseChannel и RegisterClassImage.

1. Зарегистрировать отдельный образ без выдачи экземпляров, вызвать DelClass.
   ClassesStorage.erase уничтожает запись map, затем I->second читает её.
   M40 ASan завершает процесс с heap-use-after-free.
2. Выдать экземпляр образа. DelClass обязан отказать с EObjectStorageNotEmpty,
   сохранив фабрику и выданный экземпляр. Вернуть экземпляр, повторить DelClass.
   После освобождения последнего экземпляра ObjectsStorage.erase(temp)
   предшествует повторному чтению temp->second.size(). Второй ASan процесс
   завершается с heap-use-after-free уже на этом участке.

Это два отдельных падения старой реализации, а не один failing assertion
нового теста. Полные стеки, сборки и runtime manifests сохранены в s05-cleanup-m40.

## Исправление и ограничения

Rdk 2317f3147c1193dbe2097ea2a242c8d0ab7b049b проверяет наличие фабрики до
изменения пула и сохраняет её указатель до erase. После native освобождения
экземпляров запись ObjectsStorage ищется заново; непустой список вызывает отказ,
пустой удаляется без последующего чтения. Удаляется также cache имени библиотеки.
Неизвестный id не меняет пул. Имя удалённого образа допускает новую регистрацию
с другой физикой; старый prototype не заменяется.

Lifecycle Build/Calculate/Reset не изменён. Не вводятся проверки их bool.
Выданные экземпляры возвращаются штатно; UEPtr после ReturnObject нельзя
использовать как владеющий указатель. Наличие имени зависимого класса не является
reference count. Порядок удаления зависимостей, force-пути, общая транзакция
импорта и поведение всех классов дерева этой проверкой не сертифицированы.

## Проверки

Проверен root 7e11054ddce74fefea430786293c3b9755c4dc16 с исправленным Rdk.
Последующий Rdk commit 13859899be75fb69a8170ec8131603f9b4fd763b добавляет только
документацию контракта, без изменения проверенного кода.

- Elder-1/.11: 7/7 class-image controls, 4/4 maintained CTest suites.
- M40/.17: те же 7/7 и 4/4 под ASAN_OPTIONS=detect_leaks=0, включая штатное
  завершение процесса. Полный PulseLib набор: 137 cases, 136 passed, один helper
  skipped; два свежих child imports исполняются внутри parent controls.
- Leak detection выключен; отсутствие утечек не заявляется.

Все сборки/проверки выполнены на серверах через jump host. Результаты перенесены
через Git: s05-cleanup-elder1 и s05-cleanup-m40 содержат raw logs, provenance и
SHA256SUMS.json. Это проверка реализации; обучения и научного PASS в ней нет.
