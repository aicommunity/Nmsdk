## Обнаруженная ошибка постановки Python-тестов

Первая попытка анализа текущими полными Python-модулями дала 20 проверок:
13 успешных, один отказ и шесть ошибок. Семь проверок наблюдений прошли;
неуспех проверки метрик связан с `evaluation_trial_duration_mismatch`.
Тест ошибочно объявлял постоянное окно 0,12 с. Штатный C++-fixture
`FrozenTrialChecks` запрашивает иной протокол:

```text
span = 0
для каждого интервала исходного либо развёрнутого паттерна:
    span += interval
duration = ceil((span + 0.03) * frequency) / frequency
```

Для этих четырёх моделей окно равно 0,07 с и содержит 141 отсчёт при 2000 Гц.
Следовательно, строгий scorer правильно отказал противоречивой постановке.
Ожидаемая длительность теперь вычисляется из объявленного исходного паттерна,
частоты и заданного хвоста 30 мс. Она не выводится из конца наблюдения.
Порядок сложения binary64 сохранён как в C++, чтобы не изменить границу `ceil`.

Исправлен только
`Scripts/StructTrain/TimeLearner/tests/test_recognition_metrics.py`,
коммит `b41e9f9f1cd0222ebeb3b5a77041868afbc4f940`.
Production-scorer, численные допуски, физика и первичные наблюдения не менялись.
Новый отрицательный контроль увеличивает объявленное окно на один такт,
сохраняя все отсчёты и флаги `complete/valid`; несоответствие отклоняется
для каждой из 16 проб четырёх профилей.

## Границы приёмки

Закрыта адресная регрессия связности объявленного окна и фактических данных
на четырёх штатных профилях. Это не приёмка всех исторических адаптеров,
размерностей, физических моделей или всего этапа 3. В частности, эти fixtures
не заменяют требуемую общую матрицу для M>4 и исторических схем. Успешный
анализ не повышает `budget_exhausted` научной модели до `Exact`.
