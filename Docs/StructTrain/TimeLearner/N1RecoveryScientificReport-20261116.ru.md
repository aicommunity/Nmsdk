## Следующий алгоритмический вопрос

Максимальный пробел по всему integer domain предложил верхнюю границу255 слишком рано для доступного wall budget. Следующий ограниченный вариант должен сначала исследовать более умеренные новые длины, сохраняя возможность выхода за ближайшую сетку и исходные глобальные bounds. Это порядок предложений, а не сужение математической области, не оценка отсутствующего пика и не изменение допуска. Для такого изменения нужны отдельные unit/native проверки, затем same-condition cold comparison. Изменение Rs при прежней геометрии уже проверено и само по себе слияние не сняло.

Классификация terminal state по8 паттернам здесь не выполнялась. Нет оснований считать его лучше прежнего stopped-state, присваивать Exact или PhysicalInfeasible. Августовские4/8–6/8 сохраняются как рабочие результаты своего исходного протокола. Полный план остаётся активным: этапы1–12 частичны.
