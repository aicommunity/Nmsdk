## Найденная ошибка постановки первой быстрой пробы

s11-uniform-profile3-N1-train-m40-a1 сохранил валидные четыре эталонных измерения, затем остановился с invalid_model / candidate_window_proposal_arithmetic_rejected до первого search candidate. Это не отрицательный научный результат обучения и не ограничение физики: в декларацию были перенесены численные guard-координаты исходной stock-физики. Первый stock-пик имел frame49; реально измеренный быстрый — frame27. Вычитание прежнего left_guard49 давало отрицательную границу. Защитная проверка сработала правильно, менять её или молча обрезать окно не требуется.

Исправление только постановки: reference_window_frames заново проверяет пакет и первичные CSV завершённой пробы, восстанавливает seed штатным reference_seed; по каждому входу формируются left=measured_first, right=3600−measured_last. Эффективный домен остаётся тем же [0,3600], все коэффициенты прогноза/расширения нулевые, длительность 1.8 с. Новый холодный Train заново захватывает эталоны: старые амплитуды, controller state и сертификаты не импортируются. Для быстрого профиля меняются два guard-значения каждого входа и run_id; исходная запись A1 сохраняется. До повторения проверить отказ старой арифметики и полное окно новой на реальных измеренных координатах. Stock-задание A1 продолжается без изменений.

Уточнение выбора иллюстраций до закрытия обоих Train: сначала булев признак выхода за timing tolerance, затем за amplitude tolerance, затем сумма нормированных остатков; при полном равенстве первая записанная точка. Это диагностический выбор для отчёта, не перепроигрывание controller parameterChangeCost. В метаданных он обозначен selected_measured_by_input, отдельно от accepted_parameters и фактической terminal morphology. Нельзя приписывать остаток выбранного измерения другой конечной модели.


Усиление контроля фиксированного ModelSpec: после роста разрешены только три структурных root-поля NumDendriteMembranePartsVec/TrainingDendIndexes/TrainingSynapsisNum. Остальные root-parameters, включая TimeStep и имена образов для будущего роста, должны совпасть с исходными. Это закрывает возможность незаметно изменить профиль следующего Build при пока ещё одинаковых текущих дочерних C/TC. Проверка проводится на реальных cold/grown readback; дополнительный hash-consistent control меняет только root TimeStep при прежней частоте дерева. Для уже работающих Train код не обновляется; их пакеты при чтении дополнительно проверяются новым data-only auditor.


В Rdk свойство TimeStep хранит частоту, а не dt: реальный root readback имеет unsigned_integer="2000". Контроль изменяет его на "1000" при сохранённых frequency_hz="2000" у узлов и пересчитанном hash; никакое floating-point значение dt в это свойство не записывается. В native модели частота задаётся штатным SetGlobalTimeStep до инициализации.


Подготовка дополнительного root-spec gate A2 остановилась до запуска worker: при редактировании Python ошибочно сработали специальные подстановки String.replace в строке с корневым путём '$'. Native Train не использовали эти файлы. Аудитор и контроль восстановлены из ранее принятой версии с адресной правкой без текстовых подстановок; синтаксис всех восьми изменённых Python-модулей разобран отдельно. A2 не записывается как выполненный/прошедший тест; новая адресная проверка получает новый ID A3.


В read-only отчёте A1 найдена конкретная ошибка renderer: он предполагал candidate_frame у каждой группы, тогда как корректный anchor reference имеет coordinate_mode=reference_time и candidate_frame=null. Отчёт остановился до построения графиков. Исправление обрабатывает оба штатных вида координат, проверяет область окна и не меняет измерения или выбор пиков. В повторном отчёте остаются anchor reference и полная/частичная search-группы; выбор групп не сокращается, чтобы обойти ошибку. Принятые producer Train и их primary остаются исходными.
