## Ошибка идеального носителя

Для DelayTime=1 мс фактическая задержка на всех пяти событиях составила два такта при каждой частоте. При 2000 Гц это правильно: 1 мс. При 20000 Гц получены 0,1 мс вместо 1 мс, при 40000 Гц — 0,05 мс. Для остальных четырёх значений задержки на всех частотах измеренное число тактов совпало с floor(DelayTime*frequency). Равные counts сами по себе эту ошибку не выявляют.

В исходнике найден механизм: private длина FIFO сохраняется от заводских 2000 Гц. Установка той же DelayTime=0,001 может не вызвать setter из-за проверки равенства, а UContainer::SetGlobalTimeStep не снимает Ready. Обычный Build тогда не пересчитывает private кэш. Подготовлена коррекция в PulseLib 161e590: Reset и Calculate сверяют фактические DelayTime/частоту, а смена сетки очищает старую очередь. Подготовлена отдельная регрессия с обычным PulseGenerator и повтор 15 идеальных условий. Серверная проверка этой новой версии ещё не выполнена.

## Сегментные варианты

На 20000 Гц один узел сохраняет пять событий, более длинные варианты не проводят сигнал. На 40000 Гц один узел удваивает число событий, более длинные варианты не проводят сигнал. Это воспроизведено без влияния разборки дерева и согласуется с [диагностикой формы спайка](FactoryDiagnosticResult-20261128.ru.md). Причины изучаются отдельной фиксированной 54-условной сеткой моделей LT-зоны и порогов.

Это один повтор разреженной серии. Он не закрывает трёхкратную повторяемость, пачки M=2/4/8/16, рефрактерность, рабочий диапазон задержек, сохранение/загрузку, дерево или обучение. Основной носитель ещё не выбран.
