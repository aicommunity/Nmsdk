# Правила аксонного исследования

Для этого направления действуют согласованные документы данного каталога и общие [правила научных отчётов](../../ScientificReportRules.ru.md). Применять также предметные требования [TimeLearner](../TimeLearner/ScientificReportRules.ru.md): M означает число импульсов одного потока, режим нормализации отделяется от топологии, фактические входные события и потенциал входа LT-зоны сохраняются раздельно.

Локальный clone `E:\Science-Repo\nmsdk-axone-timelearner` предназначен для документации, исходников, конфигов, коммитов и синхронизации. Не выполнять здесь сборки и экспериментальные расчёты. Сервер разработки runtime и приёмки — `user@10.245.1.15`, clone в `C:\Projects\nmsdk-axone-timelearner`. Требования исходного дендритного исследования о загрузке остальных серверов не распространяются на аксонное направление.

В корне, Bin, Nmsdk-PulseLib и Rdk рабочие ветки создавать от `axone_timelearner`. Использовать отдельные дочерние ветки этапов и `merge --no-ff`. Не изменять `develop` и `dendr_timelearner` этой задачей. Не применять rebase, squash, cherry-pick или force push.

Источник — стандартный генератор импульсов; для исторической нерегулярной пачки используется NDatasetMatrix и NPulseGeneratorTransit. Один генератор питает всё дерево. Каждая ветвь проводит весь поток. Нейрон-источник и скрытое распределение импульсов по номерам в основной постановке отсутствуют.

NAxoneChain — предпочтительный кандидат линейного участка, окончательный выбор требует измерений P1. NAxoneTreeChain — составной компонент дерева, а не вторая независимая модель регенерации. Предварительное название NAxoneArbor больше не использовать.

До научного запуска публиковать через Git код, точный протокол и воспроизводимый конфиг. Конфиги каждого объявленного условия сохранять в Bin/Configs. Тяжёлые результаты, бинарники, сборки, журналы и галереи не добавлять в Git, включая сжатые копии. Предел отдельного публикуемого файла — 1 MiB; последовательности маленьких файлов с сырыми данными также запрещены.

Разделять исходник, проверку реализации, реальное исполнение модели, полноту данных, обучение, калибровку и классификацию. Нельзя объявить этап принятым по одной компиляции или числу коммитов. Непроверенный код остаётся в дочерней ветке. Отрицательные научные результаты сохраняются, 8/8 не является обязательным условием завершения программы.
