# Сетка источника перед P2

P2-source-clock-v1 — подготовленный инженерный протокол, ещё не исполненный на сервере. Он не закрывает P2.

NDatasetMatrix с одним обычным NPulseGeneratorTransit воспроизводит только историческую цель M=4 для длительностей 25/50/100/200/480 мс при 2000/20000/40000 Гц. В source header включены точные десятичные ISI из закреплённых P2 JSON, включая первый ненулевой ISI. Эти первые интервалы нельзя заменять нулём по нормированной иллюстрации паттерна.

Один sample, одна feature, MaxSpikesPerFeature=4; режим timed=1, TimeGeneration=1 с, Delay=2 с, без loop и advance. Генератор имеет амплитуду 1, ширину 1 мс, нулевое случайное отклонение. Полное окно 0–1,1 с сохраняется. Проверяются реальные четыре фронта источника, конечность, сетка времени и before-children playback. Принимающий нейрон отсутствует.

По наблюдённым tick_i формируется только ручное предложение идеальных задержек: T=last_tick+frequency/1000 и d_i=T-tick_i. Число тактов первично; положительный double-параметр получается через nextafter(d_i/frequency,+infinity) с обязательной проверкой floor(parameter*frequency)=d_i. Это исключает потерю такта из-за округления дроби в двоичном представлении.

План не утверждает, что предложенные задержки уже проведены моделью. Их последующее физическое исполнение и сохранение/загрузка проверяются отдельно. Эти значения допускаются для P2 ручной настройки и управляемого эталона. Локальное правило P5 не получает этот вектор или номера входных импульсов.
