# Подготовка отчётов проекта

При написании новых отчётов соблюдать [общие правила научного изложения](Docs/ScientificReportRules.ru.md).
Они обобщают все33 комментария пользователя к пятой редакции Classic,
прочитанные26.11.2026 вместе с их контекстом. Требования относятся ко всему
тексту Classic, Branch и других будущих отчётов, а не только к отмеченным
фрагментам. Замечания должны менять способ объяснения; ответы рецензенту
не вставлять в научный текст. Уже выпущенные отчёты ради этих требований
не переделывать. Для TimeLearner дополнительно действуют профильные
[правила](Docs/StructTrain/TimeLearner/ScientificReportRules.ru.md).

# Размещение расчётов

Загружать полезной работой все доступные вычислительные машины. Если
независимых расчётов меньше, чем исполнителей, порядок назначения:
Elder (.11), M40 (.17), Windows .14, Windows .8, .12, .4. Подготовка,
сборка и проверка среды не считаются уже выполняющимся научным опытом.
Не запускать бессодержательные детерминированные копии ради загрузки;
продолжать очередь реальных проверок плана. Действующий опыт не переносить
и не перезапускать ради изменения этого порядка.

На `user@10.245.1.4` также использовать существующий `/home/user/Nmsdk`,
его исходники, конфиги и данные; пользователь явно предоставил эту копию.
Не создавать новый полный clone. Выходы сборки и заданий изолировать;
до смены версии проверить отсутствие действующих процессов. Пользователь
отдельно разрешил переключать ветку этой копии без сохранения её прежнего
содержимого; архив старого дерева .4 не требуется.

# Вычисления на .12

На `user@10.245.1.12` использовать существующий `/home/user/Nmsdk`, его
исходники, конфиги и данные: пользователь предоставил их для расчётов.
Не заменять это дерево повторным клонированием. Сборочные и временные
выходы изолировать от исходников; не менять дерево, пока его использует
действующее задание. На файловой системе исполнителя сохранять не менее
32 ГиБ свободного места. До запуска резервировать также предельный объём
новых выходов, логов и временных файлов; во время работы контролировать
остаток и останавливать только собственное задание с запасом перед этим
пределом. Машина одновременно служит jump host: оставлять ресурсы SSH
и передачи архивов. См. [профиль .12](Docs/StructTrain/TimeLearner/Jump12Deployment-20261126.ru.md).

# Замороженные SDK и runtime

Любые Python-опросы и проверки, импортирующие модули замороженного SDK,
выполнять с `python -B` и запрещать запись байткода до первого такого
импорта. Это относится и к чтению состояния процессов. Не исключать
`__pycache__` из строгой проверки файлового состава. Подтверждённый
служебный кэш удалять только после проверки закрытия задач и сохранности
всех объявленных исходных файлов; исходную неудачную проверку сохранять.

# Объявления запусков в Git

Новые отдельные Git-репозитории управляющих файлов запусков создавать
с `.gitattributes`, содержащим `* -text`, до первого `git add`. Это сохраняет
точные байты JSON, командных файлов и контрольных сумм независимо от
системного `core.autocrlf`. Не менять управляющие файлы действующего опыта.
Если у исторического запуска обнаружена нормализация LF/CRLF, сохранить
обе формы и явно перечислить различия; побайтовое совпадение не объявлять.
