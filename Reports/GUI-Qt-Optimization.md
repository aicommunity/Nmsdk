# Оптимизация Qt-GUI NeuroModeler

Документ описывает комплекс мер, которые следует реализовать поэтапно. Все пункты учитывают динамическую природу дерева компонентов и возможность изменения свойств “на лету”.

## 1. Метрики и требования

| Направление | Цель | Пояснение |
|-------------|------|-----------|
| FPS графов / отклик `UGraphWidget` | ≥ 30 FPS при 10 графиках и обновлении раз в 10 мс | Тестировать на профиле с ≥ 200 компонентами и 5 каналами |
| Перестроение дерева компонентов | ≤ 50 мс на частичное обновление, ≤ 200 мс на прогрузку 10 000 узлов | Включает lazy-loading и diff-обновления |
| Блокировка UI при обращении к ядру | ≤ 5 мс на вызов / ≤ 100 мс на пакетную операцию | Обеспечить асинхронные обращения или снапшоты |
| Латентность синхронизации | ≤ 300 мс между событием ядра и отображением в UI | Для графов, дерева, свойств |
| Потребление памяти UI | ≤ 500 МБ при 10k компонент и 1k графов | Завести мониторинг и watchdog |

Дополнительно:

- Зафиксировать параметры тестовых проектов (число компонент, частота изменений, типы графов).
- Включить в CI/regression набор сценариев с прогрессивной загрузкой дерева и переключением свойств.

## 2. GuiModelSnapshot и событийная шина

### Архитектура

1. **SnapshotDaemon** – фоновый поток (Qt `QThread`), который подписывается на события ядра (через RPC, shared memory или расширение `RDK::UIVisualControllerStorage`).
2. **SnapshotStore** – thread-safe структура, хранящая последнюю версию модели:
   - `ComponentSummary` (Id, класс, родитель, версия).
   - `PropertySummary` (имя, тип, класс публикации, версия).
3. **EventBus** – очередь событий для UI (Qt сигнал/слот или `std::shared_ptr<QMetaObject::Connection>`).

### Поток данных

```
Ядро -> (event stream) -> SnapshotDaemon -> SnapshotStore/Version -> UI Widgets
```

- Каждому компоненту присваивается версия; любое изменение структуры/класса/статуса свойств увеличивает её.
- События: `ComponentAdded`, `ComponentRemoved`, `ComponentUpdated`, `PropertyChanged`, `PropertyStatusChanged`.
- UI-виджеты подписываются и получают `ComponentDiff`, что позволяет обновлять только затронутые узлы.
- Для устойчивости к потерям событий – периодический heartbeat (например, раз в 1 с), когда снапшот сравнивается с ядром и устраняются расхождения.

### Потокобезопасность

- SnapshotStore предоставляет `std::shared_ptr<const Snapshot>`; UI читает immutable данные без блокировок.
- При обновлении `SnapshotDaemon` создаёт новый объект снапшота и публикует его через `std::atomic<std::shared_ptr<>>`.
- Для крупных изменений (массовое добавление) события группируются, чтобы UI не получал всплеск сообщений.

## 3. Оптимизация графов и Live мониторинга

### Буферы и перерисовка

- Для каждого графа (`UGraphPaintWidget`) реализовать кольцевой буфер (`QVector<double>` с head/tail) фиксированной длительности (например, 5 000 точек или 10 с истории).
- Использовать `QCPGraph::data()->add(data)` без полного копирования; `setData` хранить только для загрузки пресетов.
- `QTimer` (30–60 Гц) вызывает `replot(QCustomPlot::rpQueuedReplot)`; если данных не было, перерисовку пропустить.
- Это уменьшит блокировки и сохранит стабильный FPS даже при большом числе графов.

### Управление источниками

- Структура `GraphSource` содержит `ComponentId`, `PropertyId`, `PropertyVersion`.
- Снапшот уведомляет граф о событиях:
  - `SourceRemoved` – граф помечается “offline”, UI отображает уведомление и предлагает выбрать новый источник.
  - `SourceUpdated` – граф проверяет очередность и подгружает данные из нового свойства.
- Presets графов хранят метаданные (версия компонента). При загрузке пресета выполняется проверка: если компонент изменился, граф переводится в pending и показывает подсказку.

### UX аспекты

- Панель статуса графа: онлайн/офлайн, задержка данных, частота обновлений.
- Возможность “свернуть” графы для снижения нагрузки, но удерживать данные в буфере.

## 4. Дерево компонентов и свойства

### QAbstractItemModel

- `ComponentTreeModel : QAbstractItemModel` работает поверх SnapshotStore:
  - Lazy loading: при `canFetchMore` модель запрашивает детей узла через снапшот.
  - `data` читает immutable информацию (название, иконка, состояние).
- События:
  - `ComponentAdded` → `beginInsertRows`/`endInsertRows`.
  - `ComponentRemoved` → `beginRemoveRows`.
  - `ComponentUpdated` (смена класса, имени) → `dataChanged`.
- Вкладывает поддерживать фильтрацию через `QSortFilterProxyModel`.

### Свойства и кеш

- `PropertyModel` (например, на вкладки параметров/состояний) основана на `QAbstractTableModel`.
- Кеш `PropertyCache` хранит:
  - Значение свойства, тип, статус (param/state/input/output).
  - Версию; при `PropertyChanged` обновляет только соответствующие записи.
  - TTL/очистку для тяжёлых значений.
- Смена статуса (param↔state) приводит к перемещению записи между вкладками и отображению уведомления («Свойство X стало состоянием»).

## 5. UX и конфигурация

- **Фильтры и поиск**: глобальный фильтр по имени/классу, быстрый переход, сохранённые запросы.
- **Синхронизация выбора**: выделение графа подсвечивает компонент в дереве, и наоборот; при удалении компонента граф подсвечивается красным.
- **Панель событий**: список последних изменений (добавлен/удалён компонент, смена статуса свойств), чтобы пользователь понимал динамику.
- **Массовые действия**: multi-select в дереве, изменение параметров сразу для нескольких компонент.
- **Drag&drop линков**: `UComponentLinksWidget` получает улучшенный UI для создания связей.
- **Presets конфигурации**: наборы открытых окон, фильтров, графов, которые можно быстро применять.

### 5.1 Адаптация к новым темам Qt (визуальное выравнивание)

- **Иконка закрытия вкладок графиков**  
  - В светлой и тёмной темах (`Rdk/GUI/Qt/Styles/default.qss`, `Rdk/GUI/Qt/Styles/dark.qss`) добавлен блок `QTabBar::close-button` с горизонтальными отступами (`margin-left`/`margin-right`) и фиксированным положением `subcontrol-position: right;`.  
  - Это устраняет прилипание иконки закрытия к тексту заголовка вкладки в `UGraphWidget` и соседних виджетах на новых стилях, одновременно сохраняя корректный вид в старых темах.

- **Вертикальные отступы в мастере конфигурации (`UCreateConfigurationWizardWidget`)**  
  - На второй странице мастера (`Model`) увеличены `spacing` и `margins` у корневого `QVBoxLayout` (`verticalLayout_4`) и вложенных лейаутов (`verticalLayout_2`, `horizontalLayout_8`, `horizontalLayout_9`, `verticalLayout_5`, `horizontalLayout_10`).  
  - Благодаря этому заголовок «Channels configuration», разделительная линия, флаг `Apply settings to all channels` и группа `Channel Properties` визуально разделены, элементы больше не “слипаются” по вертикали в новых темах и остаются аккуратными в классическом стиле.

## 6. Дорожная карта

1. **Сбор метрик**  
   - Добавить профилирование (Qt `QElapsedTimer`, custom лог).  
   - Результат: отчёт с базовыми показателями.
2. **GuiModelSnapshot + EventBus**  
   - Реализовать demons, API, интегрировать с базовыми виджетами.  
   - Результат: UI читает снапшоты, события приходят за ≤ 300 мс.
3. **Графы**  
   - Буферы, batched replot, статус источников, presets.  
   - Результат: стабильный FPS, корректная обработка исчезающих компонент.
4. **Дерево и свойства**  
   - Н новый `QAbstractItemModel`, PropertyCache, фильтры.  
   - Результат: обновления без полной перестройки, время отклика ≤ 50 мс.
5. **UX-расширения**  
   - Панель событий, drag&drop линков, массовые действия.  
   - Результат: лучшая навигация и конфигурация.
6. **Миграция настроек**  
   - Обновить сохранение пресетов/графов/окон, обеспечить обратную совместимость.  
   - Результат: пользователи не теряют свои конфигурации после обновления.

Каждый этап завершается тестами, профилированием и фиксацией влияния на метрики. В случае динамичных деревьев особое внимание уделяется корректной инвалидации кешей и отображению изменений пользователю.
