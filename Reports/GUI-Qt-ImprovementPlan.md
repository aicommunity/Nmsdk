# План улучшений Qt-GUI NeuroModeler

## 1. Требования и динамика

- Дерево компонентов в Qt-интерфейсе формируется на лету (`UComponentsListWidget::AUpdateInterface` полностью пересобирает `QTreeWidget` на каждом тике), что подтверждает возможность добавления/удаления узлов во время расчёта.
```142:170:Rdk/GUI/Qt/UComponentsListWidget.cpp
componentsTree->clear();
QTreeWidgetItem *rootItem = new QTreeWidgetItem(componentsTree);
rootItem->setText(0, "Model");
addComponentSons("", rootItem, oldRootItem, oldSelectedItem);
```
- Свойства выбранного компонента перечитываются каждый раз (`reloadPropertys`), но пользователь отметил, что статусы могут редкими случаями меняться (параметр ↔ состояние). Любой кеш обязан учитывать эти сценарии.
- Следовательно, любые оптимизации (кэш расположения узлов, описаний свойств, источников графов) должны:
  - Быть безопасными при асинхронном добавлении/удалении компонентов и изменении их структуры.
  - Иметь стратегию инвалидации при смене класса или статуса свойств.
  - Сообщать UI о том, что ранее выбранный объект исчез или трансформировался.

## 2. Снимок данных и события ядра

### 2.1 GuiModelSnapshot

- Отдельный сервис в GUI-процессе, который поддерживает *immutable* снапшоты модели для чтения UI.
- Источники данных:
  - `RDK::UIVisualControllerStorage`/`UApplication` – уведомления о расчётных шагах.
  - Новые события ядра: `ComponentAdded`, `ComponentRemoved`, `PropertyChanged`, `PropertyClassChanged`.
- Механизм:
  1. В фоне (Qt `QThread` или `std::jthread`) подписываемся на события от ядра (через существующие RPC/IPC или расширение `GetModelLock` с “версией”).
  2. При событии собираем минимально необходимую информацию (идентификаторы, метаданные, ссылки на свойства) в `SnapshotChunk`.
  3. Версионируем снапшот (monotonic `uint64_t`). UI запрашивает последнюю версию и может быстро проверить, изменился ли конкретный компонент (по `ComponentVersion`).

### 2.2 Подписки и версии

- Каждый компонент хранит `ComponentVersion` (инкремент при структ. изменениях, смене статуса свойств или замене класса).
- Списки компонентов/свойств в снапшоте – это карты `UId -> ComponentSummary`.
- UI-виджеты подписываются на `SnapshotBus`:
  - `onComponentListChanged(ComponentDiff diff)`
  - `onComponentPropertiesChanged(ComponentId id, PropertyDiff diff)`
- Кеш графов/дерева получает событие и точечно обновляет соответствующий узел, не перебирая всю модель.
- При отсутствии новых событий за N мс допускается фоновый “heartbeat” (на случай потери синхронизации).

## 3. Оптимизация графов

### 3.1 Буферизация и батчинг

- Для каждого графика хранить кольцевой буфер фиксированной длины (по времени или числу точек). Для длинной истории – отдельный архив в диске/памяти, подгружаемый по запросу.
- Вместо `std::vector` и полной перезаписи:
  - Использовать `QCPGraph::addData(const QVector<double>& x, const QVector<double>& y)` или `QCPGraph::data()->add(QCPGraphData(x,y))`.
  - Включить `QCustomPlot::setNoAntialiasingOnDrag(true)` + queued replot (`QCustomPlot::replot(QCustomPlot::rpQueuedReplot)`).
- Периодическая перерисовка через `QTimer` (например, 30-60 Гц), чтобы batch из нескольких семплов приходил одновременно.

### 3.2 Управление источниками

- `GuiModelSnapshot` помечает граф как “невалидный”, если компонент или свойство исчезли или сменили тип.
- UI показывает уведомление пользователю и предлагает выбрать новый источник либо удаляет граф.
- Для добавленных компонентов – быстрый мастер, который может автоматически подключить новый сигнал к существующему графу (например, по маске имени).

## 4. Новая модель дерева компонентов

- Перейти с `QTreeWidget` на `QTreeView + QAbstractItemModel`:
  - Lazy loading: дети узла загружаются при раскрытии, что уменьшает блокировку при больших сетях.
  - `ComponentTreeModel` хранит указатели на `SnapshotNode` и версии, полученные из `GuiModelSnapshot`.
  - При событии `ComponentAdded/Removed` модель обновляет только затронутую ветку через `beginInsertRows`/`beginRemoveRows`.
- Вкладки свойств (`parameters/state/inputs/outputs`) используют отдельную `QAbstractItemModel`, подписанную на `PropertyDiff`.
- Status change (param→state): модель удаляет запись из одной вкладки и добавляет в другую, сохраняя выделение. UI показывает badge «статус изменён».

## 5. Безопасный кеш свойств

- Кеш хранит:
  - `PropertyKey = (ComponentId, PropertyName)`
  - Значение + метаданные (тип, класс, публикация).
  - `PropertyVersion`, синхронизированный с событиями ядра.
- Стратегии инвалидации:
  - По версии: событие `PropertyChanged` с новым `PropertyVersion` автоматически помечает запись dirty.
  - По таймауту: если свойство не обновлялось долго, фон очищает запись (полезно для редких, но тяжёлых свойств).
  - По статусу: событие `PropertyClassChanged` переносит запись в другую категорию и обновляет UI.
- API кеша:
  - `GetPropertySnapshot(PropertyKey)` – возвращает `std::optional<PropertyData>` и версию.
  - `SubscribeProperty(PropertyKey, callback)` – уведомления об изменениях/удалении.
  - При удалении компонента все связанные ключи инвалидаются каскадно.

## 6. План UX-расширений

- **Фильтры и поиск:** глобальный фильтр по имени/классу/типу, быстрый переход к компоненту; работает поверх `ComponentTreeModel`.
- **Пресеты графов:** сохранение/загрузка наборов графов с источниками. Для динамических изменений – отображать состояние «источник недоступен», предложить «исправить».
- **Режимы визуализации:** графы → линейные, логарифмические, heatmap для матриц, стек областей. Режимы выбираются пер-граф/пер-панель.
- **Навигация:** синхронизация выбора – клик по графу подсвечивает компонент в дереве. При удалении компонента граф показывает нотификацию.
- **Панель событий:** feed изменений (добавлен/удалён компонент, изменился статус свойства), чтобы пользователь понимал динамику модели.
- **Диалог конфигурации каналов:** быстрый выбор канала исполнения напрямую из дерева, отображение статуса расчёта.

## 7. Дорожная карта реализации

1. **Телеметрия и наблюдаемость**
   - Добавить замеры времени `AUpdateInterface`, логирование изменений дерева/свойств.
   - Цель: количественно подтвердить выигрыш после оптимизаций.
2. **GuiModelSnapshot + события ядра**
   - Реализовать версионированные снапшоты, канал событий, минимальный API для подписчиков.
   - Мигрировать `UVisualControllerWidget` на чтение из снапшота.
3. **Оптимизация графов**
   - Внедрить кольцевые буферы, batch replot, обработку исчезающих источников.
   - Добавить пресеты и уведомления UX.
4. **Компонентное дерево и свойства**
   - Переписать на `QAbstractItemModel`, подключить к событиям снапшота.
   - Реализовать кеш свойств с версионированием и реакцией на статус.
5. **UX-улучшения**
   - Фильтры, синхронизация выбора, панель событий, новые режимы графов.
6. **Интеграция с настройками/INI**
   - Обновить сериализацию (QSettings/XML) под новые структуры, добавить миграцию старых пресетов/графов.

Каждый этап завершается контрольным срезом производительности и UX-оценкой (сравнение с базовой версией).
