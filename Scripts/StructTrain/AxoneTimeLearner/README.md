# Инструменты аксонного исследования

Генераторы формируют только исходные конфиги, без исполнения модели:

```powershell
python -I -S -B -X utf8 Scripts/StructTrain/AxoneTimeLearner/generate_component_configs.py
```

Программа не запускает модель или сборку. Она читает шаблоны из точного Git commit Bin, формирует 45 условий в Bin/Configs и сохраняет hashes файлов. Получение научных результатов требует отдельной серверной приёмки.

Общие механизмы исполнения, измерений, ConditionSpec, архивирования и отчётности должны использоваться через проверенные адаптеры существующего TimeLearner. Отсутствующая команда не заменяется успешным stub.

Следующий пакет формирует generate_stage_configs.py. Он сохраняет 51 native-условие P1 и исторические входы P2 для пяти длительностей, читает Model_00.xml и Parameters_00.xml из закреплённого Git commit Bin и явно сохраняет их различия. P2 пока не является готовым Console-проектом.

```powershell
python -I -S -B -X utf8 Scripts/StructTrain/AxoneTimeLearner/generate_stage_configs.py
```

Непроверенные исходники компонентов и GTest не запускаются генераторами. Протокол native-проверок включает hashes исходного файла тестов; его окончания строк закреплены в .gitattributes.

`generate_observation_contract.py` сохраняет исходный контракт десяти регрессионных сценариев анализа событий, включая hashes C++ исходников. Он не исполняет эти сценарии и не рассчитывает модель.

`Run-Server15NativeGate.py` исполняется только на .15 после успешной сборки. Он проверяет том E: и marker, точный чистый SDK и объявленные C++ исходники, сохраняет manifest runtime и запускает штатный Windows Job/native_gate schema 7. Собственные процессы ограничены по памяти и времени; состав DLL фиксируется при кооперативной остановке процесса. Это проверка реализации, её научный вердикт всегда null. `--protocol` принимает отдельные контракты native P1 и анализа событий.

Текущая версия generate_stage_configs.py создаёт P1-native-contracts-v2.json и stage-source-manifest-v2.json. Объявления v1 сохраняются для неудачной первой сборки.

Seal-Server15Attempt.py архивирует завершённую попытку на E: без переноса первичных файлов: две полные инвентаризации должны совпасть, manifest и компактный *.archive.json находятся в Seals/<id>. Поддержан отдельный --verify-pointer для полного readback. Native-попытка с созданным process-каталогом требует подтверждения закрытия всего Windows Job. Для setup/build отдельно сохранено отсутствие нативной карты процессов; целостность файлов не означает успешного теста или научного результата. Режимы seal и verify исполняются только на .15.

`generate_segment_diagnostic_contract.py` формирует девять исходных диагностических условий P1-factory-diagnostic-v1.json. Новый GTest записывает внутренние сигналы неизменённого NAxoneSegment, трёхсегментной Chain и ChainAndDelay при 2000/20000/40000 Гц. Цель — объяснить расхождения первой серверной серии; конечный полный capture не требует ненулевого аксонного выхода. Порог и параметры не подстраиваются. Окно 80 мс является диагностическим и не заменяет приёмку хвоста P1.

Analyze-Server15P1.py читает только закрытую валидную native-попытку P1. На .15 он сверяет полный CSV с сеткой и JSON событий, сохраняет ширину по порогу, максимумы, все допустимые временные пары в окне 0–50 мс и равенство всех портов дерева. Это анализ разреженной последовательности, не обучение и не приёмка полного P1; отсутствие проведения сохраняется. Совпадение двух молчащих графов отделено от нетривиального проведения.

Для изоляции native-сценариев Run-Server15NativeGate.py принимает --case-id с точным именем из исходного протокола и выбранной partition. Каждая такая проверка получает свежий процесс и выходной каталог; произвольный фильтр вне опубликованного объявления запрещён. Это позволяет исследовать ошибки разборки графа, не перенося состояние неудачной фикстуры в следующий тест.

Версия v3 исходного P1-контракта сохраняет диагностические поля исключения Rdk и фазу cleanup. После ошибки BreakLinks фикстура отдельно пытается DestroyModel и RestoreClock; каждое исключение остаётся GTest failure. Это уточнение наблюдаемости и освобождения ресурсов, не исправление физической модели и не обход ошибки дерева. Предыдущие v1/v2 остаются для своих source snapshots. Текущий generate_stage_configs.py формирует v3.

generate_local_rule_contract.py публикует P5-local-rule-unit-v1.json для 11 инженерных сценариев AxoneLocalTimingRule. Исходники реализуют локальные следы и непрерывное предложение задержки; физическое редактирование аксонов и завершённый тренер этим контрактом не подменяются. Генератор исполняет только создание исходных входов.
